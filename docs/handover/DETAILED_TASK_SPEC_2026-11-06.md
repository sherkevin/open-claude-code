   - 只处理管理员预先限定的工具、数据、金额和操作范围；
   - 记录模型、策略、理由和结果；
   - 拒绝优先，不能越过高风险人工审批；
   - 默认关闭高风险能力。
4. **APR-003：用户明确批准**
   - 显示不可变参数、影响范围和风险；
   - 允许、拒绝、取消和超时都可追溯；
   - 重启后不自动重放。
5. **APR-004：管理员或双人批准**
   - 生产、删除、凭据、批量变更、外部发布等高风险动作；
   - Sub-agent 审批必须级联；
   - 父子审批失效和重启失效要有测试。

**验收：**

- 路由决策可重放，候选白名单有效，预算有效，切换不会污染既有运行；
- 四种审批策略分别有自动化测试；
- 高风险动作无法由模型单独放行；
- 活动会话不会被自动切换模型。

**证据路径：** `docs/evidence/ROUTING_APPROVAL_<日期>.md`

- 一个子任务失败不误取消兄弟任务；

## 9. 常见坑

1. **不要把 0.4.2 发布树和当前开发树的测试数字混在一起。** 0.4.2 是 316 通过、3 失败；当前开发树是 322 通过。两套证据不能互相替代。
2. **不要直接跑 `npm run build`。** 生产 Nginx 正在服务 `client/dist`，会覆盖线上前端。必须用 `--outDir` 输出到独立目录。
3. **不要为了测试通过改掉 409 行为。** `409 MODEL_SELECTION_REQUIRED` 是产品要求的防漂移保护，只能改测试 fixture。
4. **不要把“设计文档存在”写成“功能已实现”。** 多模态图谱、Sub-agent、RAG 可视化目前都只有设计。
5. **不要相信没有原始证据的对标数字。** 没有实测的指标必须显示“待测”。
6. **不要把合成数据当客户真实数据。** 所有合成结果必须标记 `synthetic`。
7. **不要在 `client/dist`、`.runtime`、`.venv` 里做实验。** 用独立目录和临时目录。
8. **不要忽略文件所有者问题。** `docs/PRODUCT_EVOLUTION_PLAN_2026-11-06.md` 当前是 `root:root`，如果你以 `ubuntu` 身份运行，先确认能否编辑。
9. **不要在项目根目录执行 `rm -rf`。** 改文件前先做时间戳备份。
10. **不要在没有用户授权的情况下推送 GitHub 或操作远程仓库。**

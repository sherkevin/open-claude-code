## 1. 背景

「知行工作台」是给 Better AI 工业 Agent 场景（当前按华微世纪场景开发）的一套可独立交付的企业智能助手系统：客户端（React）+ 执行服务（FastAPI）+ 知识库/RAG + MCP 工具接入 + 会话与记忆 + 管理后台。客户已有自己的工业助手，但只支持简单知识问答和表格可视化；我们的目标是**覆盖它现有全部能力，并在 Token 节省、响应速度、上下文管理、记忆管理、多模态数据处理和可视化上全面超过它**，把它作为主产品交付。

本轮会话的起点是「接手 L2 项目负责人，完成需求审计与回归」；中途需求升级为「把平台打磨成可对标并超越客户现有助手的完整产品」，于是产生了大量新需求、产品升级计划和持续目标（goal）。会话在 15:45 被用户中断，goal 置为 paused，留下了未完成的需求冻结与阶段实施工作。

### 2.4 用户在会话中确认的产品边界（已冻结）

1. **协议**：模型侧兼容 OpenAI-compatible Responses API 与 Chat Completions API；工具侧支持标准 Streamable HTTP MCP，并兼容 OpenAI Responses MCP 配置导入。业务方现有 MCP 都是 OpenAI 协议，因此我们也可以自建合成 MCP + 文档作为开发/演示基准。
2. **文档上传**：PDF、DOCX、XLSX、CSV、Markdown、TXT、JSON 和常见图片；首期本地解析/OCR，外部视觉模型逐次审批。
3. **审批策略（四种）**：安全只读自动批准、**模型代用户批准**、用户明确批准、管理员或双人批准。模型代审不得处理高风险操作，所有策略服务端复核并留审计。
4. **执行展示**：展示计划、阶段、工具、审批、上下文压缩、子任务等安全进度，不展示模型私有思维链——即 Codex CLI / DeepSeek Harness 那种滚动小字，而不是现在的空转。
5. **对标方式**：先合成基准（合成助手 + 合成 MCP + 文档/表格/图片 + 标准答案），再接真实样例；指标含正确性、来源覆盖、首字节、完成时间、Token、费用、上下文、记忆、多模态；客户端出柱状图/折线图/雷达图，缺失指标显示「待测」。

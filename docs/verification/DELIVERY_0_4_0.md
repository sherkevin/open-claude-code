## 修复记录与证据

- 首次数据库回答没有脚注：SDK 实际返回扁平 JSON 字符串包装。已补充有界规范化、错误结果拒绝及去重，重新运行通过。保留原失败报告。
- 首次网页访问失败：服务器代理 DNS 为公网域名返回198.18/15虚拟地址，触发私网保护。现在仅此类全虚拟地址结果触发受限 HTTPS 公共 DNS 回退，再验证并固定真实公网 IP；不改变系统 DNS/代理，不允许私网、混合地址或关闭 TLS 校验。31项运输层回归及真实页面读取通过。
- 公司回答把“齐套装配”改成“整机装配”：强化专用术语保留，针对性复验关闭。
- DeepSeek 回答附加“整体稳定”：缺判定标准，强化客观统计边界，复验数值和口径准确且不再出现该判断。
- 普通介绍简洁使用 Dano-v2.1 / Better AI，不主动列出执行框架、内部路径或数据用途警告。资料用途仍保留在可核验来源中，直接询问时如实回答，不伪造生产数据或训练事实。
- 本轮身份v8共4项7轮，没有实际配置泄露，连续追问的后两轮遗漏公开名称且解释过长，保留为失败。v9针对连续追问3轮和编码索取1轮重新运行，4轮都只回答“我是 Dano-v2.1，Better AI 的工业场景智能助手。”；独立语义复审通过，没有降低评分规则。有限样本不等于任意攻击保证。

私有证据位于 `.runtime/product-0.4/`，包括真实模型报告、原生上下文报告、语义检索/OCR验证、客户端安装与发行审查结果；不进入客户发行包。详细来源协议见 [MCP契约](MCP_SOURCE_CONTRACT.md)，配置说明见 [使用与配置](CONFIGURABLE_WORKSPACE.md)。

独立客户端 ZIP、服务端 TAR.GZ 和部署资料 ZIP 由 `scripts/build_release.py` 的显式白名单生成；排除运行数据、凭据和内部笔记。独立发行预审核对151个成员、文档依赖、客户端资源和私有信息排除；已知验证文档后续更新纳入最终构建。旧0.1/0.2/0.3的九份发行包仍匹配历史摘要。最终文件清单及 SHA256 见随包 `manifest.json`；交付步骤包括归档读回、全部成员与源文件比较、腾讯云副本哈希以及已安装客户端的 HTTP 字节校验，结果保留在独立发行校验记录中。

本轮验证覆盖试用数据和用户提供的公司材料；尚无客户真实 MCP、真实业务任务集及同配置原生基准，不宣称业务正确率、每成功任务成本或生产负载指标已验收。Docker只做依赖与配置静态准备，腾讯云实际验收为原生 systemd 部署。PDF OCR、检索排序和生成回答仍需用原件核对；网页正文抽取有少量站点样式噪声，当前引用依据正确。没有声称任何提示词能抵御所有未来攻击。

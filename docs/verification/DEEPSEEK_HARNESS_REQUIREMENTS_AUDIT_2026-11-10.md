# DeepSeek Harness 主线需求实现审计

审计日期：2026-11-10；服务器：学校云；工作目录：`open-claude-code`。

后续进展：本文保留实施前的审计证据。用户确认推进后，真实运行时试点已落地；最新状态见 [真实执行链路验收](../evidence/HARNESS_RUNTIME_2026-11-10.md) 与 [隔离试点操作](../operations/HARNESS_PILOT.md)。完整功能迁移仍未完成。

## 结论

**“把 Claude Code 执行框架换成官方 DeepSeek Harness，并保留既有功能”尚未完成。** 当前完成的是 Foundation 计划中的工具解耦、默认关闭的进程内知识桥，以及官方 Python SDK 对模拟通信进程的协议验证。普通聊天仍使用 `SDKRuntime`，由 `ClaudeSDKClient` 执行。

这次审计依据工作区的实际代码，包括已有未提交改动；不以 Git 提交记录或文档中的 DONE 标记代替实现核对。没有修改运行时代码、切换模型、安装 Harness 依赖、重启产品服务或调用真实模型。飞书机器人是独立支线，不计入 Harness 主线完成度。

客户端测试与类型检查证明当前客户端代码的自动化契约成立，没有启动 Harness。服务端桥测试使用临时业务数据库和部分替身；协议测试使用真实官方 Python SDK 和模拟对端，不能证明真实 Node 运行时、真实模型、插件隔离或生产能力。协议报告中的 `real_runtime_started`、`model_calls` 是该脚本的范围声明，不是通用运行监控；边界同时由实际启动参数和源码检查支持。

## 主线下一步顺序

1. 在数据盘建立固定版本、隔离依赖的真实 Harness 环境，使用自有最小插件配置，先验证真实进程握手、关闭和环境边界。
2. 实现 `HarnessRuntime`、明确的运行时选择与独立会话映射；让一个新测试会话完成“提交 → 执行 → 事件 → 回复”，既有会话不自动改写。
3. 接通携带完整参数的工具插件和后端网关，复用现有授权、审批、来源和审计；验证拒绝、撤权、取消、超时和迟到批准。
4. 依照迁移矩阵补齐流式正文、停止恢复、上下文压缩、模型路由及其他产品能力的等价测试；用真实获批模型验证完整链路与可测指标。
5. 等价门槛通过后再切换默认执行器。当前“Foundation 完成”不能作为默认切换的验收结论。

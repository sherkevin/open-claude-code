# 企业 Agent 服务：一期交付边界建议

日期：2026-11-04，修订 2。状态：保留的历史设计基线。下文“尚未实现”等描述反映当时状态；当前实现、部署和验证以 [README](../README.md) 与 [交付验证记录](DELIVERY_VERIFICATION.md) 为准。本版根据用户纠正，替代“API 为主、界面仅供演示”的提案。

## 用户目标

客户应拿到一套可直接使用的企业智能助手应用，包括正式 Web 客户端、管理配置页面和服务端。员工能聊天办事，管理员能配置业务连接并授权给助手。API 是集成方式之一，不能替代这两类用户的操作入口。Claude Agent SDK 与运行时属于内部实现依赖。托管或客户私有化均可采用相同产品结构，生产部署地点和计费主体尚未确定。

已知开发位置为远程腾讯云服务器 `open-claude-code`。本地目录 `D:\open-claude-code` 当前仅保存本轮任务和决策记录，本轮没有读取或修改远程项目。

## 建议交付清单

| 交付项 | 客户拿到什么 | 一期验收要点 |
| --- | --- | --- |
| 正式聊天工作台 | 自有品牌的 Web 客户端，可从客户已有产品进入或嵌入 | 员工选择助手、聊天、上传附件、查看执行过程、处理审批、下载结果及恢复会话 |
| 业务连接管理 | MCP 新增、认证、测试、工具查看、状态及停用页面 | 管理员从页面接通已约定的 MCP，无需编辑 SDK 配置 |
| 简单助手设置 | 业务规则、绑定连接／工具、可用人员及审批设置 | 管理员将配置发布为一个员工可使用的业务助手 |
| 服务端与存储 | Agent 执行、用户身份、会话、连接配置、凭据、文件及用量管理 | 正确执行工具，持久化会话；重连不重复执行已完成的业务操作 |
| 交付及接入材料 | 托管访问入口，或约定的部署包；使用说明、API 文档、验收用例与运维说明 | 管理员能完成初始配置，员工能独立完成约定任务 |

以上均为建议范围和验收目标，不表示功能已经存在。我们托管时，客户拿到可登录使用的网址、管理员账号及接入资料。客户私有化时，交付前端、后端、执行运行时和持久化组件的容器部署包、初始化配置及运维资料；是否交付源码另行约定。已有前端可以复用或嵌入我们的功能，但不能把必须的配置和使用页面留给客户自行补建。第一版不需要复杂的可视化 Agent 编排器或插件商城。

## MCP 在哪里配置、如何生效

产品菜单建议：工作台、业务连接、助手设置、成员与用量。管理员可管理连接和助手，普通员工只使用获授权的助手；使用个人业务身份时，员工另有“我的连接／授权”入口。

以客户已有的知识库 MCP 为例，完整流程如下：

1. 管理员进入“业务连接 → 新增 MCP”，填写连接名称、服务地址及认证方式。首批认证方式以客户实际 MCP 为准，例如服务账号 Token 或个人 OAuth。
2. 我们的后端保存按组织隔离的连接元数据，长期凭据保存在服务端受控密钥存储中。页面保存后仅返回脱敏信息，不把长期密钥下发聊天客户端或放进模型提示词。
3. 点击“测试连接”，由将实际运行 Agent 的执行节点发起连接并读取工具列表。区分网络不可达、待授权、连接失败与已连接；测试本身不执行写入业务的工具。
4. 管理员在“助手设置”中把该连接绑定到“企业 QA 助手”，选择允许使用的工具、可用人员和必要审批规则。工具发现和自动批准是两件事，不默认把全部工具设为自动放行。
5. 员工登录工作台选择“企业 QA 助手”。如果连接要求个人身份，先点击“授权业务账号”；使用企业服务账号时，必须明确该账号的数据边界，不能声称自动继承每位员工的业务权限。
6. 员工提问。服务端根据登录身份、助手配置及连接授权，取出对应凭据和 MCP 配置，交给该用户的 Agent 会话。应用负责将产品设置转换成 SDK 的 `mcp_servers` 等选项，客户不需要知道 SDK 配置格式。
7. 运行时连接 MCP 并调用允许的工具。需要审批时，工作台显示具体动作和参数；客户业务系统仍负责最终权限校验。结果及附件回到同一个工作台。

配置以数据库中的产品设置为事实来源，不依赖员工电脑上的 `.mcp.json` 或开发者全局配置。普通配置修改可以先在新会话生效；界面必须说明生效范围。停用连接、撤权及凭据失效要在执行端阻止新的未授权调用，不能仅从界面隐藏按钮。此处是产品要求，尚未验证实现。

MCP 服务本身来自客户已经提供的业务系统。我们交付连接管理和接入适配；若某个业务系统只有普通 API，则还需要实现对应 MCP 或自定义工具，不能靠填写地址自动把它变为 MCP。

## 两种客户端与运行位置

| 名称 | 在哪里 | 责任 |
| --- | --- | --- |
| 产品客户端 | 员工和管理员的浏览器 | 提供聊天、连接配置、业务授权和审批等可见操作 |
| MCP 协议客户端 | Agent 执行节点内，由 SDK／运行时提供连接能力 | 与 MCP 服务握手、发现工具并发送调用；无需另让员工安装通用 MCP 客户端 |

推荐先按客户已有服务器 MCP 设计 Web 产品，但当前 MCP 的真实位置和认证方式尚未调查：

- 远程 HTTP MCP：执行节点能够访问其地址时，Web 客户端加服务端即可。
- 客户内网 HTTP MCP：必须将执行节点部署在可达网络，或安排经批准的网络连接／连接器。管理员能从自己的浏览器打开地址，不代表我们的执行服务器可以访问。
- stdio MCP：命令在启动它的机器上执行。部署在服务器的 stdio 工具访问的是服务器的文件和软件。
- 依赖员工电脑文件或软件的 MCP：需要运行在员工电脑上的伴随程序、桌面客户端或本地执行节点及其连接通道。单纯给服务器填 `localhost` 或本地命令不能访问员工电脑。此能力仅在确认业务确实需要时纳入一期。

官方 MCP 架构区分 Host、协议 Client 和 Server，并说明 stdio 用于本机进程通信、HTTP 支持远程通信。[MCP 架构](https://modelcontextprotocol.io/docs/learn/architecture)

官方 SDK 支持代码／文件配置 MCP，但不自动提供交互式 OAuth 登录。若客户 MCP 使用 OAuth，我们的应用必须实现对应授权、回调及凭据生命周期，再将有效凭据提供给执行端。这是产品交付工作，不应遗漏或宣称 SDK 自动完成。[SDK MCP 配置与认证](https://code.claude.com/docs/en/agent-sdk/mcp)

## 内外接口边界

建议调用路径：我们的 Web 工作台／嵌入客户产品的页面 → 我们的应用服务 → 会话、身份、连接、审批、文件及用量管理 → SDK 适配层 → Agent SDK／运行时 → 官方模型服务及业务 MCP。连接配置页面通过应用服务写入配置存储，执行节点据此建立 MCP 连接。

- 对外使用我们自己的会话 ID、执行 ID、事件类型、错误码和业务工具名称；SDK 会话 ID 与协议留在内部。
- 身份由服务端认证结果确定，不能直接信任请求体里的租户或用户标识。文件、会话、凭据、配置和记忆按权限边界隔离。
- SDK 原始事件在受控内部存储中按必要性留存；对外映射为稳定的文本、工具状态、审批、产物和完成事件。原始日志不默认发给客户前端。
- 只转换展示和接口协议，保留模型原生上下文管理；不为隐藏品牌去改写工具事实或模型输出。
- 由我们实现服务接口及运行管理。SDK 是运行库，不能预设它已经提供完整的多租户生产服务器。
- 活动对话通过 `ClaudeSDKClient` 保持会话；空闲回收与恢复需要同时考虑会话记录、工作区、记忆及未完成操作的状态。

## 品牌、交付方式与披露

官方 Agent SDK 概览明确说明，集成产品展示 Claude 品牌是可选的，产品应保持自己的品牌。因此日常界面和 API 文档可以以我们的产品命名，不需要教终端用户安装或操作 Claude Code。[官方 SDK 概览](https://code.claude.com/docs/en/agent-sdk/overview#branding-guidelines)

托管 API 可以将执行依赖留在服务内部。客户私有化交付时，拥有机器或容器管理权限的人可以检查依赖，不能承诺底层技术无法被识别。模型供应商、数据流向或第三方组件如涉及采购、安全审查及合同披露，应如实说明；不把第三方模型或整个运行时宣称为完全自研。

## 商业授权证据边界

品牌可选不是对所有商业托管或计费方案的授权结论。Agent SDK 概览说明可用于面向自身客户的产品，并受商业条款约束。商业条款 A.1 允许产品集成，D.4 对转售有限制。当前 Claude Code 托管指引另列出不修改二进制、不得代付或转售终端用户 Claude 用量等条件，同时说明产品开发应使用官方 API 或受支持云服务凭据。[商业条款](https://www.anthropic.com/legal/commercial-terms) · [Claude Code 托管及凭据指引](https://code.claude.com/docs/en/legal-and-compliance)

这些页面不足以替具体 SDK 托管及统一收费模式作最终授权判断。客户企业自有凭据与我们统一采购并转售用量必须分开讨论；需要统一代付或转售时，应确认适用协议或商业授权。本轮没有联系供应商或客户，没有确认任何授权或开通付费服务。

## 技术依据与验证边界

官方托管文档描述 SDK 启动并管理 Claude Code 子进程、会话及工作区具有状态，并明确 Python 可使用 `ClaudeSDKClient` 保持跨轮会话。[官方托管说明](https://code.claude.com/docs/en/agent-sdk/hosting)

本轮验证为官方文档核对和交付边界审阅，没有进行代码测试、运行验证、远程环境检查或生产部署。MCP 实际地址、协议、认证方式、网络可达性以及客户现有前端的可复用程度仍未确认。模型配置仍沿用此前讨论目标，不在本轮重新选择。原先 2–4 周估算不因本次讨论自动成立，需按新增配置页面、认证流程和实际网络接入工作重新核算。

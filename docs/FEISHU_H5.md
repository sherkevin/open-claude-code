# 飞书网页应用接入

知行工作台以飞书“企业自建应用”的网页应用（H5）形态接入工作台。飞书工作台中的入口地址固定为部署站点的 `/feishu`，例如：

```text
http://10.103.16.12:18081/feishu
```

这是当前学校云的内网测试地址。它要求使用飞书的电脑或手机与学校云处于同一可达网络；当前 `38.246.226.10` 是出站网络地址，端口没有转发到本机，暂时不能作为外部访问地址。

这不是聊天机器人或云文档小组件。打开应用后，飞书客户端给网页一个一次性授权码，服务端向飞书校验用户身份，再签发知行工作台自己的 HttpOnly 会话 Cookie。应用密钥和飞书访问令牌只在服务端短暂使用，不进入浏览器。

## 与邓凯文 BOT 的边界

当前租户中有两套独立应用：

| 应用 | App ID | 用途 |
| --- | --- | --- |
| 邓凯文-bot | `cli_aa5e2ae5a638dd0d` | 只负责飞书消息与学校云大总管之间的机器人桥接；已移除网页应用能力 |
| 知行工作台 | `cli_aa658d2a3d78dd1f` | 只负责飞书工作台里的完整网页系统和网页免登 |

飞书允许同一个应用同时添加机器人和网页应用能力，但本项目现在刻意拆成两个应用。这样机器人事件、网页免登、应用密钥和版本发布互不影响。打开工作台时应使用“知行工作台”，不要再使用“邓凯文-bot”的旧 AppLink。

工作台入口链接为：

```text
https://applink.feishu.cn/client/workplace/open?appId=cli_aa658d2a3d78dd1f
```

## 飞书开发者后台

1. 创建独立的“企业自建应用”，名称使用“知行工作台”，启用“网页应用（H5）”；不要在“邓凯文-bot”应用中添加网页能力。
2. 先将网页应用主页配置为 `http://10.103.16.12:18081/feishu`，并把 `10.103.16.12` 加入可信域名；如果飞书后台拒绝内网地址，需要先完成学校网络的端口转发或提供一个 HTTPS 入口。
3. 发布应用版本，设置企业内可见范围。
4. 端内免登采用 `tt.requestAccess`；旧版飞书客户端由前端回退到 `tt.requestAuthCode`。飞书官方建议端内网页使用这一套免登流程：[网页应用免登流程](https://open.feishu.cn/document/client-docs/h5/development-guide/step-3)。
5. 如果后续要让 Agent 以用户身份读写飞书文档、任务或多维表格，再单独申请对应的用户授权范围；当前网页应用只用身份完成知行工作台登录。

网页应用必须使用单独的企业自建应用，与已有机器人桥接应用分开。这样机器人事件订阅、网页免登和用户授权可以独立轮换，也不会让一个应用同时承担两个不同的入口职责。

## 服务端配置

在服务端私有环境中设置以下变量，不能把 `FEISHU_H5_APP_SECRET` 写入前端构建参数：

```bash
AGENT_FEISHU_H5_ENABLED=true
FEISHU_H5_APP_ID=cli_xxx
FEISHU_H5_APP_SECRET=只保存在服务端的网页应用密钥
AGENT_FEISHU_H5_ALLOWED_OPEN_IDS=ou_xxx,ou_yyy
AGENT_FEISHU_H5_USER_MAP='{"ou_xxx":"alice","ou_yyy":"bob"}'
AGENT_COOKIE_SECURE=false
AGENT_ALLOWED_ORIGINS=http://10.103.16.12:18081
```

`AGENT_FEISHU_H5_USER_MAP` 的值可以是知行工作台的本地用户名，也可以是本地用户编号。每个被允许的飞书 `open_id` 必须映射到一个已经存在且启用的工作台成员。单用户部署可以省略映射，改用已有的 `AGENT_FEISHU_USERNAME` 或 `AGENT_FEISHU_USER_ID`；多人部署应使用显式映射。

服务端启动后可以检查：

```bash
curl --fail --silent http://10.103.16.12:18081/api/v1/config
```

响应中的 `feishu_h5.enabled` 应为 `true`，`feishu_h5.app_id` 只返回“知行工作台”应用编号，不返回应用密钥。机器人仍使用自己的 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`，两套变量不能混用。

## 前端行为

- `/feishu` 和 `?embed=feishu` 会进入飞书 H5 登录流程。
- 已有知行会话会直接进入完整工作台，不重复请求飞书授权。
- 飞书客户端中授权成功后，所有原有页面（助手、会话、知识库、Skills、工作流、审批和用量）继续复用同一套前端。
- 授权失败时显示重试和账号密码回退入口；普通浏览器访问根路径仍使用原账号密码登录。

Nginx 必须把 `/feishu` 回退到 `index.html`，并将 `/api/` 反向代理到同一个服务端；仓库内的 `client/nginx.conf` 已包含这两个规则。当前学校云测试使用已启动的 `18081` 前端预览端口；正式对外使用时应切换到 HTTPS，并将 `AGENT_COOKIE_SECURE` 设为 `true`。

## 验收顺序

1. 在飞书开发者后台保存主页地址、可信域名和应用可见范围。
2. 以测试成员的 `open_id` 配置白名单和本地用户映射。
3. 在飞书客户端打开应用，确认页面地址为 `/feishu`，授权后直接进入知行工作台。
4. 新建一个低风险会话，确认任务、事件流和审批仍在原工作台中运行。
5. 在普通浏览器打开根路径，确认账号密码登录和原有功能不受影响。

飞书官方说明：端内网页免登由前端获取临时授权码，服务端换取用户访问凭证并取得用户信息，再建立业务自己的登录态；应用密钥必须留在服务端。[应用授权登录概述](https://open.feishu.cn/document/client-docs/build-login-free-system-)

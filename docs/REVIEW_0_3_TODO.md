## Findings

- **[CLOSED, P2] Effective provider settings were not pinned with the selected model.** [Model selection and validation](../server/app/model_catalog.py) originally snapshotted only upstream model/effort, [runtime configuration](../server/app/service.py) fingerprinted that selection but not its provider environment, and [SDK connection](../server/app/runtime.py) reread global provider settings. Changing global provider configuration after `prepare_run` could leave the audit row naming the old host while execution used a new host/key. Changing per-model overrides similarly left the fingerprint unchanged, allowing warm/new actors to use different settings. Independently reproduced before the fix using isolated temporary data, `old.invalid` / `new.invalid` fixture URLs and fake credentials; no network calls or real secrets.
  - Fix reviewed: `effective_provider` merges the allowed global/override settings and pins selected model aliases; `provider_fingerprint` stores only SHA256 in conversation/run selections; `validated_provider` rejects changed configuration; `runtime_config` carries the exact validated environment in memory; `connect` copies it without rereading mutable settings. Provider digest participates in the actor fingerprint, and the prepared audit host comes from the same captured environment.
  - Independent recheck now rejects both global and per-model changes with `MODEL_SELECTION_REQUIRED`; explicit reselection changes the runtime fingerprint; the original prepared audit retains its provider; snapshots contain no fixture credentials. Historical selections without prior hashes are pinned from upgrade onward, with no assertion about historical credentials.

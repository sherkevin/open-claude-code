# 合成对标 Token 口径增量（2026-11-08）

## 变更原因

原图把增强方案的压缩后摘要、来源标记和任务输入一起计入，但基线只计入任务问题，导致两边不是同一信息量的比较，增强方案显示为 187 Token、基线 95 Token。该口径不能体现“上下文压缩后再送入模型，压缩过程不计入模型用量”的产品规则。

## 新口径

- 两个合成参与者使用相同的固定任务信息。
- 最简单 Agent 基线按未压缩的固定上下文计入输入 Token。
- 知行工作台按压缩后的上下文和来源标记计入输入 Token。
- 总 Token 只包含计入的任务输入和输出；压缩过程不计入总 Token。
- `compression-savings` 只表示固定文本中原始上下文与压缩上下文的差值，不是供应商账单，也不是一次真实模型调用。
- 客户现有助手仍保持 `not_measured`，没有填入客户数据或推测值。

| 最简单 Agent（未压缩基线） | 236 | 34 | 270 | 0 |
| 客户现有助手 | 待测 | 待测 | 待测 | 待测 |

这是固定中文文本的下界估算，不是 TokenHub 账单或真实模型性能结论。服务器运行器未调用模型、客户系统、生产数据、网络或计费服务。

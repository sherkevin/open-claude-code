# 回滚与紧急停机

## 原则

先让授权和数据面失败关闭，再处理版本回退。不要通过放宽认证、公开 visitor 端口或复用已撤销凭据来恢复服务。不要删除生产数据库、证书、备份或其他项目文件。

## 云端紧急停机

1. 先撤销相关企业集成 K，使新请求立即失败；如需整台连接器停用，再撤销连接器，控制面会在同一事务中撤销该连接器下的集成。
2. 停止对应专属实例：

   ```text
   systemctl stop kaiwu-bridge@<connector_id>.service
   ```

3. 确认 Edge 对新请求返回 401/403/503 等失败，而不是继续成功；确认 frps 私有 bindPort 和 visitor 端口已关闭。
4. 必要时只停止 Edge 的公开入口或反向代理路由，保留控制面审计数据和数据库。不要直接清空数据库表。
5. 检查服务日志时只记录脱敏后的状态，不要复制 K、Bearer、HMAC 密钥、R 或 T。

## 应用版本回退

1. 记录当前提交、版本、systemd 单元、配置文件和 Edge/frps/visitor 进程状态。
2. 停止新版本 Edge 和对应 `kaiwu-bridge@` 实例；保持现有数据库和证书不变。
3. 备份 SQLite 数据库、部署配置、证书和 `/var/lib/kaiwu-bridge/<connector_id>/`，备份权限保持私有。
4. 切换到上一个已验证版本，恢复对应 systemd 单元和配置，启动一个 worker，执行健康检查和只读路由检查。
5. 重新执行错误 K、跨来源、工具限制、断线和撤销检查；没有通过前不要把旧版本标记为已恢复服务。

本次新增数据库对象是加表/加索引式的 additive schema。回退到不识别这些表的旧版本时，表可以保留，但不要在旧版本里手工删除集成、来源或审计表，避免破坏后续恢复。

## 企业凭据 K

- 单独撤销：调用 `POST /api/kaiwu/v1/integrations/{integration_id}/revoke`。
- 需要继续使用但怀疑泄露：调用轮换接口，立即停止使用旧 K，并把新 K 的 JSON 重新导入开物。
- K 明文只在创建或轮换响应中出现一次。不要试图从数据库或普通查询接口“取回”旧 K；丢失时只能轮换。

## Windows 本机回退

1. 以管理员身份停止并删除 `KaiwuConnector` 服务；如果只做升级回退，先停止服务再覆盖二进制。
2. 保留 `C:\ProgramData\Kaiwu\Connector\` 中的数据目录和最近一次 `backups` 备份；备份目录同样只能允许 SYSTEM 和 Administrators 访问。
3. 如需恢复配置，将备份文件复制回数据目录后重新启动服务，并检查 DPAPI 文件是否仍可解密；跨机器或跨账号复制 DPAPI 密文可能无法解密，此时应重新绑定或重新录入本机参数，不能降级为明文存储。
4. 重新安装上一版本时，先校验其 ZIP 和 `SHA256SUMS`，再执行 `install.ps1`；不要使用未校验的旧包。
5. 回退后验证本地 UI、服务重启、MCP 导入、允许工具和公网 Edge 调用；任何一项未通过都保持停用。

## 域名、证书和反向代理

只有在确认新路径/证书不可用时才回退 Nginx 配置。回退前保存当前配置和证书链，使用 `nginx -t` 验证，再以受控方式重载；不要把私钥或完整配置粘贴到报告或聊天中。DNS 回滚需要保持 TTL 和证书覆盖范围一致，不能直接指向未验证的任意 upstream。

## 回滚后的保留证据

- 回滚原因和时间；
- 停止/撤销的 connector_id 和 integration_id（不记录秘密）；
- 实际执行的 systemd/服务操作和退出码；
- 失败检查的状态码和时间；
- 备份路径、版本和校验结果；
- 仍未关闭的用户影响和下一次恢复条件。

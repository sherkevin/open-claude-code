# 已知限制与未验收边界

## 1. 交付状态限制

- 本机 TCP 合成链路和本机 HTTPS/WSS 回环通过，不等于真实公网部署通过。
- 实际开物网页对话已经通过，但使用固定合成 MCP、固定合成订单和学校云回环模型测试适配器；不等于腾讯云生产模型路由或客户业务通过。
- 交叉编译出 Windows 可执行文件，不等于已经在 Windows Server 2019 实机运行通过。
- 当前没有客户真实 Bearer、HMAC 密钥、channel、userid、业务 MCP 地址或业务数据。
- 本次没有修改现网 DNS、证书、腾讯云服务或共享 systemd 服务。
- 用户当前明确要求先不做 Windows 匹配、回到主线；本轮没有启动 Windows 远程授权，也没有操作 Shervin 或客户 Windows Server 2019。

## 2. 架构限制

- 每个连接器使用一个专属 `frps` 实例。R 是同一条专属传输通道的认证材料，不是多租户、逐员工或逐来源的细粒度授权。
- 来源范围由允许工具列表、控制面来源绑定、K 的来源绑定和 Edge 路由共同限制；没有重新实现客户数据库查询。
- Edge 当前只接受 MCP `POST`。不支持的 `GET`/`DELETE` 明确返回 405，不伪造成功的可选能力。
- Edge 会话表保存在当前进程内存中。进程重启会丢失 Edge 会话；客户端需要按协议重新握手，业务调用不会自动重放。部署时只能使用一个 Edge worker，除非先迁移会话存储。
- Edge 对已打开 SSE 流大约每秒检查一次集成/连接器撤销状态；没有新数据块时不会主动发送心跳。撤销后的新请求立即按控制面状态拒绝。
- 撤销连接器会撤销该连接器下全部企业集成并停止专属 bridge；这与“只暂停一个来源”或“只撤销一个 K”是不同操作。
- visitor 必须监听回环或严格受控的内网地址。当前设计不允许客户端通过请求参数指定任意代理目标。
- 自定义 FRP 认证插件、逐员工身份映射和 OAuth Token Exchange 不在本期范围。
- 私有 CA 需要两个不同路径：云端 Linux visitor 使用服务器本机 CA 路径，Windows frpc 使用客户 Windows 本机 CA 路径。不能共用一条 Linux 路径。

## 3. 测试限制

- T09 的模拟网络分区没有执行。已验证正常停机、强杀专属 frps 和 relay 重启。
- 没有长时间、高并发、真实公网延迟或真实业务数据下的容量测试。
- 没有 Windows 实机的 DPAPI、ACL、服务重启、整机重启、升级迁移和卸载证据；单元测试、交叉编译和 PowerShell 冒烟脚本不能替代实机结果。
- 没有在生产 Edge 多实例、反向代理缓冲、正式证书链异常或公网断线条件下验证。
- 合成日志、控制数据库、浏览器报告和截图元数据秘密扫描通过，只代表本轮固定数据；真实部署仍需再次脱敏扫描。
- HTTPS/WSS 回环使用临时 CA 和本机 Nginx，不代表正式域名、DNS 解析、公网防火墙、负载均衡或证书续期通过。

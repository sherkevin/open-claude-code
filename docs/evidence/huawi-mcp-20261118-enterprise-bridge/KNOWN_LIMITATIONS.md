# 已知限制与未验收边界

## 交付状态限制

- 本机合成链路通过，不等于真实公网部署通过。
- 交叉编译出 Windows 可执行文件，不等于已经在 Windows Server 2019 上运行通过。
- 现有开物导入解析器通过，不等于已经登录实际开物网页并完成对话。
- 固定合成工具返回 `SYNTHETIC-ORDER-42`，不等于华微真实业务查询正确。
- 当前没有客户真实 Bearer、HMAC 密钥、channel、userid、业务 MCP 地址或业务数据。
- 本次没有修改现网 DNS、证书、腾讯云服务或共享 systemd 服务。

## 架构限制

- 每个连接器使用一个专属 `frps` 实例。R 是同一条专属传输通道的认证材料，不是多租户、逐员工或逐来源的细粒度授权。
- 来源范围由允许工具列表、控制面来源绑定、K 的来源绑定和 Edge 路由共同限制；没有重新实现客户数据库查询。
- Edge 当前只接受 MCP `POST`。不支持的 `GET`/`DELETE` 明确返回 405，不伪造成功的可选能力。
- Edge 会话表保存在当前进程内存中。进程重启会丢失 Edge 会话；客户端需要按协议重新握手，业务调用不会自动重放。部署时只能使用一个 Edge worker，除非先迁移会话存储。
- Edge 对已打开 SSE 流大约每秒检查一次集成/连接器撤销状态；没有新数据块时不会主动发送心跳。撤销后的新请求立即按控制面状态拒绝。
- 撤销连接器会撤销该连接器下全部企业集成并停止专属 bridge；这与“只暂停一个来源”或“只撤销一个 K”是不同操作。
- visitor 必须监听回环或严格受控的内网地址。当前设计不允许客户端通过请求参数指定任意代理目标。
- 自定义 FRP 鉴权插件、逐员工身份映射和 OAuth Token Exchange 不在本期范围。

## 测试限制

- T09 的模拟网络分区没有执行。已验证正常停机、强杀专属 frps 和 relay 重启。
- 没有长时间、高并发、真实模型请求和真实业务数据下的容量/延迟测试。
- 没有 Windows 实机的 DPAPI、ACL、服务重启、整机重启、升级迁移和卸载证据；这些项目的脚本和单元测试不能替代实机结果。
- 没有在生产 Edge 多实例、反向代理缓冲、证书链异常或公网断线条件下验证。
- 合成日志和数据库秘密扫描只代表本轮固定数据；真实部署仍需再次做脱敏扫描。

## 环境与记录限制

- 任务指定模型为 `tencent-cloud/deepseek-v4.1-flash-1017`，实际运行器显示 `deepseek/deepseek-flash`。最终报告不把指定模型写成实际执行模型。
- 根分区空间极小，所有临时文件和构建缓存必须留在 `/media/data3/dengkw/`；不能把产物写回根分区。
- 本轮没有构建最终 1.3.0 包之前，任何旧包或旧哈希都不能作为本轮发布证据。最终包和哈希以 `RELEASE_REPORT.md` 为准。

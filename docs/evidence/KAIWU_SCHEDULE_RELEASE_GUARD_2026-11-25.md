# 2026-11-25｜调度发布、重启与安全回退保护

## 复用与实施

基线 22487b2。与独立反馈说明切片并行，未覆盖对方工作。继续复用固定版官方 DeepSeek Harness 规则引擎与原 SQLite/FIFO，不引入新调度器或权限。

- 调度扫描保留最多 20 项普通周期、另保留 1 项高级周期计算名额，避免持续普通积压让高级规则永远排不到；未知周期类别默认暂停，不再隐式当作每周规则。
- 新增 scripts/kaiwu_schedule_rollback.py。默认 inspect 为只读：返回活动运行、待发队列、活动会话、未交付高级周期执行实例及不受旧版支持的活动周期的数量，不输出任务正文、ID 或凭据。prepare 必须在工作台已停止且有新检查 token、明确确认的条件下执行；SQLite 写事务内再次比对，若不静止拒绝修改。只暂停旧版不识别的活动周期，保留其规则、下次时间及原历史，不删除或恢复数据库。旧版运行中不允许自动恢复高级规则。
- 该脚本是运维回退闸门，不自行检测/停止 systemd、不切换 release，也不代替完整生产发布流程。只读检查允许在线；写入必须在服务真正停止、排空或处理活动运行后进行。不能以传入确认参数代替核验服务已经停止。

## 生产回退操作约束

1. 精确确认生产新旧版本、工作台服务实例、真实数据路径及发布包 SHA，保留新旧 release 与当前数据备份；确认控制面无需重启。
2. 先只读 inspect 判断是否可排空；如有任务、排队请求或未交付高级实例，先处理它们，不通过直接删除或强行重放使检查通过。正常停止工作台并核实进程退出、无其它数据库写入者；保留一个有效的维护窗口。
3. 对停止后的实际数据库重新执行 inspect（若存在高级计划会返回 exit 2 并打印 token，这是预期），确认 quiescent=true。保存 SQLite backup 和 quick_check；再执行：
   python3 scripts/kaiwu_schedule_rollback.py prepare --db <actual-db> --expected-token <fresh-token> --confirm-workbench-stopped
4. 核对 prepare 的 after.safe_for_legacy_scheduler=true、paused 数量及数据库完整性。仅此时才切换到旧 release。任何失败都不允许旧代码接管高级规则。
5. 旧版本运行期间高级计划保持暂停；升级回来也不自动补跑，用户使用新版未来周期恢复操作。禁止因为回退而默认恢复历史数据库，避免丢失期间业务记录。

实际生产应用未停止、未切换；本轮只完成闸门代码和隔离验证。下一步：自然语言管理、实际浏览器与整包发布验收，待精确生产基线及更大负载检查通过才发布。

# D3.1 · 会话记忆 API 与真实 Mem0 SDK 同进程验收

在 VIP 隔离环境，两个用户的三个会话写入三段不同的中文/中英混合记忆。登录用户在原生记忆 API 提交文件，通过语义索引 API 显式同步。结束整个产品进程后，新的 FastAPI 进程从相同的持久数据目录再次登录，三个会话均取回各自的原文、MEMORY.md、版本和 SHA-256。代码基线为 6d040ea。

| 登录后操作 | D3 旧证据 | D3.1 实测 |
|---|---|---|
| 同步前查询，随后编辑并显式同步 | 真实 Service 加合成索引 | 三次查询都回退且未打开 SDK。三次同步各写一套真实 Qdrant/SQLite |
| 重开服务，按会话查询 | 以前由各层分别验收 | 服务进程 2797902 写入；新进程 2799258 回读全部三段内容，路径、版本及哈希均一致 |
| 用另一位用户访问 | API 权限测试 | 查询、同步、退役均返回 HTTP 404；三个动作都没有打开 SDK |
| 向量服务暂时不可用 | 合成后端抛异常 | 回环向量服务返回一次 HTTP 503，产品回退，原生文件可读；服务恢复后主动查询成功 |
| 清空后退役 | 逻辑退役测试 | 无对应清空时返回 HTTP 403。按当前版本清空后取得退役回执，再同步返回 HTTP 503，其他会话可查。SQLite 历史文件仍存在 |
| SDK 关闭确认丢失 | 合成后端 | 真实 SDK 完成关闭后注入确认丢失。该作用域未再打开，另一位用户仍能查询 |

**产品边界**。测试用确定性相同向量刻意制造语义排序碰撞以检验隔离。可选 BM25 模型未缓存，服务记录降级，测试强制离线解析。本结果覆盖真实产品接口、库和持久化；真实供应商的中文召回质量、计费、删除字节、模型上下文、用户工作台 UI 和生产部署均须独立验收。产品默认关闭，真实供应商准入依旧独立。

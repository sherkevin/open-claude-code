## 2. 会议事实

### 2.1 对方现有系统

- 已有华微灵犀全局智能体，能完成类似问数任务并返回可视化表单。
- 已按人员角色拆分多个智能体，由主智能体通过路由技能选择功能智能体。
- 业务数据通过本地 MCP 直接拉取；数据规模达到数万到数十万行时，直接交给大模型会造成很高的 token 消耗。
- 对方明确表示缺少模型处理和安全、成本治理方面的专业能力，希望由我方提供通用能力。
- 对方希望继续保留自己的前端入口、华微灵犀品牌、业务系统、第三方入口和权限规则。

### 2.2 我方在会议中承诺的能力方向

- 完整智能体需要覆盖八层能力：模型、角色、知识图谱与 RAG、业务工具与 MCP、权限、安全、成本与性能、可观测与评测。
- 通过知识漏斗、检索、上下文管理、路由和可收敛工具降低大模型调用成本。
- 采用可插拔、开源的模块组合，支持业务 Skill、图表、数据导出和其他定制能力。
- 提供公网可访问的 HTTP 智能体测试服务，并提供 MCP 接入及接口调用说明。

### 2.3 双方当场形成的试用共识

- 双方先各投入少量人力完成对接和试用，验证效果后再讨论正式商务合作。
- 对方研发人员将按我方文档完成接入，并在项目群反馈问题和效果。
- 先行测试必须能回答：现有 OpenClaude 加 DeepSeek 的效果是否可达到、维护和成本是否改善、差距是否可以解决。

## 3. 工程需求转译

以下事项来自逐字稿中的明确讨论，不能只当作商务背景：

1. **公网测试入口**：提供稳定的 HTTP 调用入口和可直接试用的网站，登录、会话、错误提示和可用性要适合外部研发试用。
2. **MCP 接入协议**：提供可复制的 MCP 接入方法，明确传输方式、认证、工具发现、请求与响应、超时、错误和版本兼容。
3. **跨网连接**：对方 MCP 位于本地网络，我方智能体位于学校云公网。不能假设公网服务可直接访问其内网 MCP，需要设计由对方主动发起、可撤销、最小权限、可审计的出站连接器或等价方案。
4. **权限边界**：对方提供权限规则和数据接口，我方执行前必须保留调用方身份、工具权限和数据范围，不能通过试用入口绕过对方权限。
5. **大数据场景**：验证数万至数十万行历史业务数据时的 token、延迟、正确性和可追溯引用，不能只用小型聊天样例证明有效。
6. **技能复用**：支持图表、数据导出、消息发布等跨平台 Skill；Skill 应有版本、权限、输入输出和失败审计。
7. **基线对比**：用“最简单 Agent（移除增强模块）”作为消融基线，对比现方案与增强方案的 token、速度、上下文保持、上下文管理、正确性和拒绝越权能力。
8. **交付文档**：会后需提供技术方案、HTTP 调用和 MCP 接入指引；文档必须让对方研发能独立完成第一次接入。
9. **试用验收**：至少准备一个业务问答任务、一个大数据查询任务、一个权限限制任务；每个任务记录输入、模型线路、检索证据、工具调用、token、耗时、最终结果和失败原因。

## 4. 当前边界和未决问题

- 会议没有授权生产部署、真实客户数据迁移、客户凭据落盘或切换未授权付费模型；当前只能使用公开、合成或对方单独授权的测试数据。
- 会议没有确定对方 MCP 的传输协议、认证方式、网络出口、允许的工具清单、数据字段范围和撤销流程；这些是试用前的外部输入。
- 会议中的“部署到对方服务器”与后续“我方公网服务、对方本地 MCP”存在两种表达，不能直接当作已确定架构。应以双方书面确认的跨网连接方案为准。
- 当前项目已有 HippoRAG、MCP、安全、工作流、模型线路等节点；本记录只证明需求来源，不把客户试用或跨网连通宣称为已实现。

## 5. 建议的验收门槛

- 文档验收：对方研发按文档完成一次无人工介入的测试调用，且能看到请求标识、响应、错误和重试说明。

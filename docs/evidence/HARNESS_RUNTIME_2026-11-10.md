日期：2026-11-10。服务器：学校云。项目工作目录：`open-claude-code`。

后续增量：本文保留首个运行时切片发生时的证据和缺口。业务 MCP 连接及双人审批成功路径已在同日后续切片继续实现，最新状态见 [业务连接验收](HARNESS_MCP_2026-11-10.md)。

## 结论与授权范围

用户在主线审计后确认推进“隔离运行环境 → HarnessRuntime 和独立会话映射 → 工具与审批 → 发送、流式、停止和恢复”。该纵向切片已完成，并在真实官方 Node Harness 进程中验收。默认执行器仍为 Claude，既有服务没有重启；完整功能迁移和生产切换没有完成。

本轮模型验证只使用本地合成 HTTP 服务，不使用真实供应商凭据，不涉及付费调用。真实运行时与合成模型是两个不同边界：这次不再以模拟运行时对端证明 Harness 能运行，但也不把固定合成回答解释为真实模型质量。

## 实现

| 位置 | 已完成内容 |
|---|---|
| `scripts/setup_harness_runtime.py` | 固定官方提交、Node 24.9.0、pnpm 11.28.5 和归档摘要；冻结锁依赖，全部放入项目 `.runtime`，只生成必要本机扩展和源码产物 |
| `server/app/config.py`、`db.py`、`service.py` | 按会话固定 `runtime_type`；旧会话迁为 Claude；独立 Harness ID；执行类型、模型切换、路径及单次输出配置指纹保护 |
| `server/app/runtime.py`、`main.py` | 默认工厂按持久会话选择执行器，显式测试工厂仍可注入；共享工作区授权逻辑保持原语义 |
| `server/app/harness_runtime.py` | 官方 Python SDK、干净环境启动器、真实 Node、字面消息、实时正文去重、真实用量、完整终态校验、进程停止与持久历史恢复 |
| `server/app/harness_tools.py` | 白名单、完整参数、当前账号/助手/任务授权、人工审批、策略变化检查、来源复用、审计和错误拒绝 |
| `server/harness/` | 自有空 bundle 配置、实际工具注册表校验、可信 stdio 工具通道、实时模型事件与步数限制；不注册原生文件/Shell/插件安装/调度/子代理工具 |
| `server/pyproject.toml` | Python 安装包包含配置生成器、TypeScript 插件及 ESM package.json |
| `scripts/evaluation_gate.py` | Harness 模块、工作台工具和自有插件加入治理文件范围 |

每轮专属进程结束后关闭，下一轮重新打开同一会话的原生历史。这个选择避免了上一轮迟到的工具请求被当作新任务请求。审批等待期间、工具执行之后都重新比较当前审批策略，包括策略从不存在/关闭变成启用的情况；变更后不返回旧结果，不执行迟到批准的写操作。

传输等待时间覆盖配置的人工审批窗口，修复了固定 300 秒超时短于默认 600 秒审批窗口的问题。单次模型输出显式默认 8192，并在真实请求中核对；它不是 goal 预算，也不是金额硬上限。

真实闭环具体核验：

1. `/permission` 开头的普通消息原样到达本地模型，没有执行原生命令；两段正文增量没有在完整消息到达时重复拼接。
2. 当前助手授权的知识库通过真实工具回调检索，登记来源并在最终回答保留可核验引用。
3. Excel 请求先进入现有人工审批；拒绝后没有文件，允许后才生成产物。
4. 模型流进行中取消，专属进程退出；随后恢复同一 Harness 会话，模型请求包含之前的历史。
5. 模型流缺失结束事件时运行失败；本轮当时手动压缩显式返回不支持，后续已由 2026-11-11 手动压缩迁移补齐，见[压缩验收](HARNESS_COMPACTION_2026-11-11.md)。
6. 启动器执行环境中不存在宿主 API Key、代理、Python 注入路径和 Node options；只保留本次选中的专用模型密钥，且不写入启动文件。

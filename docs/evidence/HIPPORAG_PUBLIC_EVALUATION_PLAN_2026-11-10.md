## 第一批：16 个片段，不先追求规模

目标是验证实体、跨片段连接和图片证据能否正确贯通，而不是产生可宣传的质量分数。以下是计划数量，尚未完成选取或标注。

| 内容 | 计划 |
|---|---|
| 检索语料 | 16 个正文片段：IR 8227 六段、IR 8219 四段、SP 800-82r3 四段、中文指南两段；包含相似实体与无关候选，不只收录答案段 |
| 图片 | 从所选公开 PDF 保留四幅相关架构/流程图及对应上下文；原页、裁剪图分别记录哈希与坐标，不以目录页充当语义能力样例 |
| 实体与关系 | 预计 40–80 个实体提及、20–40 条原文明确支持的关系；实际数以复核后的清单为准，不补造关系凑数 |
| 问题 | 24 题：单跳六题、双跳八题、三跳两题、图文联合四题、无答案/易混淆反例四题 |
| 划分 | 八题开发、十六题锁定评测；同段落、同图、裁剪图及近似改写归同组，避免跨组提示泄漏 |

多跳题必须列出每一跳的实体、关系和各自证据，且没有单个片段直接包含完整答案。可考察“设备—所在工作单元—监控/安全机制”类型的连接，但只有选定原文明确支持后才写入答案；跨文档同名设备不能自动视为同一物理对象。无答案题要求明确缺少哪一环，而不是依靠模型常识补齐。

每个实体保存类型、规范名、别名、原文 span、文件 SHA-256、页码与段落范围；每条关系保存方向、谓词、证据原句和来源。图片保存原页/裁剪图哈希、区域像素坐标及相对坐标，并区分“图中描绘”与“现实设备关系”。标注先盲审、再核对争议，记录审阅者及修改历史；只有助手复核时继续标作助手标注，不能改名为独立人工金标准。

## 比较与图文融合边界

同一语料、查询、来源权限和上下文预算下比较 BM25、现有混合检索、官方 HippoRAG 文本检索，再比较增加 OCR/图注证据与 CLIP 图像召回后的明确融合模式。实际启用的向量模型必须记录，不能把 `local-lexical-v1` 称为语义 embedding。

图片作为独立、版本化证据对象：OCR/图注片段指回图片、原页和区域；未经复核的视觉实体关系保留 `model_candidate`，不得自动成为可信图谱事实。不同模型向量不能直接拼接；图文候选融合可先做显式的排名融合，并分别保留文本分数、图像分数与来源。

现有 `hipporag2-official` 成功路径故意不混入 lite 或视觉补位。新增图像融合必须明确命名和报告，不能把现有 CLIP 命中伪装成官方图算法输出。检索卡片与图谱节点均应能打开原图、放大、定位原文；对话引用继续使用权限检查后的本地文档链接，远程资料保留原始 HTTP(S) 来源。

评测记录实体 span/规范化准确性、关系方向与证据一致性、图片区域定位、Recall@5/MRR，以及多跳所需全部证据是否同时命中。无答案误答、无证据关系、失效引用和越权结果单独列出。安全门槛为零越权与零伪造来源；质量阈值先在开发集校准并冻结，不预写胜率。第一批只报逐题结果与小样本局限，后续扩大独立标注集再给区间和推广结论。

索引、压缩、检索与回答的真实用量分别记账，另列冷/热耗时和硬件；不得把离线成本隐藏在“免费压缩”中，不根据估算宣传优于客户助手。发生模型缺失或回退时显式记录，不能用合成结果补齐真实模型栏。

## 真实接口：现有入口，不冒充当前在线

| 用途 | 准确标识与代码入口 | 已知证据与限制 |
|---|---|---|
| 本地图文向量 | `openai/clip-vit-base-patch32`；`server/app/vision.py` 的 `VisionRuntime.embed_image/embed_text` | 既有 2026-11-07 记录执行过 512 维 CPU 推理；运行时仅加载本地权重、不自动下载。本轮未检查权重或重新推理，不能断言当前 ready |
| 本地 OCR | `VisionRuntime.ocr_image` / `DocumentParser.ocr_image` 的 RapidOCR | 保留文字与区域来源；OCR 可读不等于图片语义理解 |
| 本地文本向量 | `LocalEmbeddings.embed`：默认 `local-lexical-v1`；现有受支持学习模型名为 `BAAI/bge-small-zh-v1.5` | 未确认当前已加载学习模型。`BAAI/bge-m3`、重排器和 Qwen 视觉模型仅见设计，不能标作已部署 |
| 远端视觉候选 | 公共 ID `deepseek-v4-flash-202605`；`KnowledgeService._provider_visual_selection` → `call_visual_json` | 2026-11-07 公开图探针返回过合法空实体/关系，只有协议可调用证据，无抽取质量结论。不能与聊天/Tab 的 `deepseek-v4.1-flash-1017` 混同 |
| 能力预检 | 已认证 `GET /api/v1/models/provider-preflight` | 仅返回脱敏状态，不发请求；`call_enabled=false` 不授予调用权限。本轮未调用它或读取私有配置 |

真实调用先核对预检与显式角色授权，再在隔离工作器中通过服务端已有凭据解析入口取线路；日志只保存公共模型名、配置摘要、用量、耗时和固定错误码，不保存令牌、私有上游或原始响应。图片调用已有 8 MiB 输入限制、JSON 候选、超时、禁重定向与 `trust_env=false`；它不是通用文本 OpenIE 客户端，也不提供工具执行权限。

当前索引真正使用的是 `knowledge_vision_model_id`；`knowledge_entity_model_id` 与 `knowledge_relation_model_id` 虽有角色预检，不能据此声称已有独立文本实体/关系模型执行路径。官方 HippoRAG 的真实语言/向量工厂仍需明确接入并绑定配置指纹，缺失时报告不可运行，不静默借用聊天线路。

公开资料开发验证无需客户提供样例即可开始；工业质量正式结论仍需要独立复核标注与更大留出集，客户适用性仍需客户样例或业务验收。当前不新增任何质量分数或完成状态。

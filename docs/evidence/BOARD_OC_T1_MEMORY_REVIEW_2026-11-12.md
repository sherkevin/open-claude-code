## 1. 复核结论

本节点补齐了任务书要求但此前不存在的 `server/tests/test_harness_memory.py`。测试直接使用真实的 Harness 记忆 HTTP API、不可变快照存储、数据库版本和代次字段，没有使用测试替身冒充记忆实现。

当前可确认：

- 编辑、删除和清空记忆都会发布新的不可变快照，旧快照仍可用于审计，但不再是活动记忆绑定。
- 编辑、删除和清空后会增加原生代次并清空旧 Harness 原生会话标识，下一次模型输入不能通过旧原生会话恢复。
- 旧记忆内容、旧附件内容和历史工具结果均不出现在新的活动记忆绑定中。
- 旧版本号写入和越界路径失败均不改变当前快照、版本或附件。
- 应用聊天历史继续保留，不以“清空记忆”为由删除历史消息。
- 完整正文审批、版本冲突、取消和失败回滚由既有真实存储/绑定测试覆盖；本轮定向复测 16 项通过。

## 3. 覆盖说明

`tests/test_harness_memory.py` 包含以下验收场景：

1. 编辑记忆后快照标识、版本和原生代次变化；旧哨兵只保留在旧快照，不进入新绑定；旧 Harness 会话标识被清空。
2. 删除单文件和清空全部记忆后新快照为空，旧哨兵不随新请求继续输入。
3. 过期版本写入被拒绝且不修改活动快照；越界路径失败关闭。
4. 已登记的历史工具结果和附件文件不进入活动记忆快照。

`tests/test_harness_memory_api.py` 覆盖完整正文所有者审批、摘要不匹配、审批后撤权/版本变化、取消、过期、非记忆审批隔离和失败不发布。

## 4. 未覆盖边界

- 本轮没有调用真实供应商模型，因此不能证明具体模型对记忆内容的语义利用质量。
- 没有使用真实客户数据，也没有在共享服务或生产环境重启、部署或切换。
- “清空记忆后旧内容不进入模型”由活动快照、原生代次和原生会话重置共同证明；如需供应商协议级抓包证据，应在获得单独批准的受控真实线路验证中补充。

# D2.3c4b｜按权威作用域隔离本地 SDK 存储的可行性

基线 c56af9e，独立工作树 kaiwu-mem0-scope-store-20261126。沿用固定 Mem0 2.2.1/Qdrant 1.20.0/OpenAI SDK 及回环合成 provider。未修改上游，不创建正式产品数据，不读取客户正文或权限凭据。

在 data3 独立临时根目录，为两个合成用户及其中一个用户的另一会话分别配置独立 Qdrant 路径和 SQLite history 路径。以结构化主体标识哈希得到三个不同的示例目录。真实 SDK 三套同时打开；infer=False 及关闭遥测时，未初始化懒加载实体库。向量及历史均跨用户/会话隔离。关闭目标 SDK 后移动其整个合成目录到隔离区，不读取其历史正文；其他两个作用域仍正常查询、关闭及重开，原目标路径没有重新创建。移动不是删除：历史仍留在隔离区；测试结束仅由本测试的临时目录生命周期回收。

实际真实 SDK 5/5、退出码 0；3 次回环 embedding、0 次 extraction。证据 /media/data3/dengkw/acceptance/kaiwu-mem0-scope-store-20261126/real-sdk.log、real-sdk.exit；复现脚本 scripts/oss/mem0_scope_store_probe.py。未验证生产授权、物理擦除、备份清理、大规模打开成本或正式产品接线。

决策：现阶段保留现有默认关闭的共享适配器供隔离测试，优先采用每权威作用域独立的向量和历史存储设计作为产品候选，而非直接删除共享 SQLite 行。下一项 D2.3c4c：宿主权威作用域到存储身份的持久绑定、只读解析与显式创建分离、关闭后不自动重开、路径/符号链接/进程竞争及重启测试；之后单独验收撤权/清空的删除专用准入、持久清理回执和保留策略。删除权限不可由模型、路径参数或旧读权限授予。生产发布闸门保持关闭。

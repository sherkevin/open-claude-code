# MCP 导入与可信只读契约联动

目标：普通用户一次导入并测试即可发现工具，在实际业务会话中选择自动审批；已由运营方明确批准复用的可信接口无需重复核验。未审核、写入或通用执行类工具继续按原规则逐次审批。

## 接入流程

- 导入页面默认勾选“导入后自动测试连接”，也可仅保存。导入仍是原有批量事务，只保存连接，不授权助手、不调用业务工具；随后客户端逐个发起现有 discovery API。失败连接保留并显示错误，不影响其它已导入连接。离开页面停止后续测试。
- 发现工具后，MCP 卡片显示与平台可信契约匹配的实际工具数量，不把发现成功当作业务执行成功。用户仍需将工具明确授权给相应助手并做真实业务验收。
- 后端复用现有可信规则文件和运行时定义校验。运营人员可在独立审核清单中显式设 allow_reimport=true；默认不允许复用。仅同一已审核 Bearer 来源、同一所有者及共享范围、精确相同 URL、相同认证凭据、当前原始连接身份、精确相同已审核工具定义且原规则有效时，自动匹配。凭据比较仅在服务内部进行，不在规则、API 或日志暴露明文。匿名、OAuth、不同账号/凭据/定义、歧义和未知来源不自动继承。新供应方仍需独立建立审核依据。
- 直接登记规则优先，过期或变更时不回退到可复用规则；人工覆盖优先。运营撤销在规则中记入 blocked_reuse，防止被撤销的连接再次通过复用获得平台默认信任。撤销锚点会失效其衍生复用。原有独立人工核验不在该撤销范围内。
- 新授权期限和新凭据不会自动延期或继承；需要核对真实授权后重新登记。运维 CLI inspect 只检查直接登记，不解密凭据；动态复用状态由已授权的工作台 API 和执行时复核。原有华微规则默认 allow_reimport=false，不自动扩大现有生产授权。

## 验证

59 项后端相关回归通过，涵盖真实合成本地 MCP 导入、工具发现、同身份复用、实际自动/手动审批、未知供应方、不同凭据、定义变化、撤销、到期、歧义、写工具及权限隔离。75 项前端相关回归通过，生产路径完整构建通过；导入后只发起新连接的测试，不执行业务工具。真实新增供应方尚未提供其独立审核材料，不能据此称所有新供应方均已通过实机验收。

## 2. 实现合同

- **单一运行时摘要机制。** Claude 继续使用其原生 `/compact`；Harness 使用产品自有命令层调用固定的官方 compaction-basic 引擎。没有新增第二套应用摘要器。
- **用户保留重点不丢失。** `CompactRequest.instructions` 经过长度、字节和控制字符校验后，以明确分隔的不可信数据追加到本次摘要请求。它只能收窄需要保留的内容，不能改变摘要输出结构或授予工具。上游 `compactNow` 会派生新的取消信号；实现改用按 Agent 绑定的 `WeakMap` 保存本次重点，并在结束后清理，避免重点因信号变化静默丢失或串话。
- **成功必须有真实证据。** 宿主严格校验 `command/run`、`command/done`、`compaction/start`、`compaction/summary`、`compaction/end` 的会话、命令、压缩事务、摘要序号和终态。只有存在真实摘要边界才报告 `completed`；成功命令没有边界时报告 `not_needed`，不伪造压缩。
- **失败关闭。** 命令错误、协议不一致、超时、取消和执行异常都不能报告成功。超时、取消和失败会关闭本轮专属客户端并回收请求线程；真实边界已经发生后，压缩状态保持 `completed`，后续计数或完成步骤失败记入 `followup_status`。
- **授权和生命周期复核。** 压缩准备、执行前、摘要边界后和收尾前复核运行、用户、会话、助手、执行器、原生会话编号和配置指纹。取消、配置变化或会话状态变化不能继续放行。
- **用量不冒充账单。** 成功摘要事件中的输入、输出和缓存 Token 作为增量加入运行账本，未知费用保持 `null`，不按其他模型价格补造。失败重试、同一步骤替换结算、取消/失败调用和真实供应商总账仍属于后续缺口。
- **能力提示不替代授权。** `manual_compact_available` 只在 Harness 原生会话存在、会话空闲、用户启用、助手可用且运行配置可核验时为真；压缩接口仍独立执行完整授权。
- **前端状态。** 上下文弹窗区分估算、陈旧、未知和可压缩状态；历史过短时显示无需压缩，失败和取消不会显示成压缩成功。

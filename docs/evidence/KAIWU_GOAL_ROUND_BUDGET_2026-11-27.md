# 持续目标的单轮费用预留与逐笔结算

用户从开物工作台的「会话 → 持续目标」填写总费用预算和可选的单轮费用上限，授权后点击「开始一轮」。费用单位为微美元，1 美元等于 1,000,000 微美元。设置单轮上限后，系统在创建本轮模型工作前检查能否覆盖主任务、子任务和重试。旧授权保留原有轮间预算行为。

| 用户操作或故障 | 修复前 a5ab73e | 开发版隔离实测 |
|---|---|---|
| 设置单轮金额 | 只有总费用。总额 1 微美元时真实派工并重试，产生 5 次无金额回执的请求，无法判断实际花费 | 单轮上限可在界面设置和读回。缺少可核验价格时，25 微美元上限的启动按钮提前禁用，说明原因；同一登录态直接启动返回 409，新增 Goal 运行与模型请求均为 0。刷新后原因仍在 |
| 设置 9 微美元，当前计划需要 39 微美元预留 | 没有单轮预留 | 页面说明预留费用超过上限并阻止启动；同登录态直接启动返回 GOAL_ROUND_RESERVE_EXCEEDED，0 轮、0 次 Goal 模型请求 |
| 设置 39 微美元，遇限流后派给两个子任务并汇总 | 失败和成功请求都没有费用凭据 | 启动时写入 5 个槽位。父任务 2 笔各封顶 10、两个子任务各封顶 7、重试封顶 5 微美元。每次回环模型收到请求时，都能在宿主库中找到同一尝试编号已开始的记录 |
| 收件后未回账单即强制停止服务 | 缺少可追溯的单笔预留 | 同一数据库换新进程，原轮中断，已发出的 10 微美元预留保留，结算未知；该轮总收件数维持 1 次 |

|---|---:|---|
| 父任务首次派工，HTTP 429 | 0 | 没有 token 回执 |
| 同一请求重试成功 | 4 | 12 输入 + 8 输出 token |
| 库存子任务 | 3 | 12 输入 + 8 输出 token |
| 采购子任务 | 6 | 12 输入 + 8 输出 token |
| 父任务汇总 | 8 | 12 输入 + 8 输出 token |
| 合计 | **21** | 4 笔成功请求共报告 80 token，全轮 token 未知 |

每笔请求使用独立 UUID，在其对应的会话、父轮或子任务下核销。重试关联原失败请求。账单缺失、标识不匹配或金额高于预留时，已开始的预留不能自动写为零。整轮金额可知但用量缺失时，仍会阻止依赖完整用量的续轮。

在 78 微美元的总预算下，结算后逐笔表、轮次和总表分别读回 21 微美元，剩余 57 微美元。整页刷新、关闭原服务并启动新进程后，三处金额及请求数一致。另一场景连续两次返回 429，第二次回执后重试槽位用尽；第 3 次原生申请在模型收件前被拒绝，回环服务实收 2 次，两笔均有 0 微美元回执。

在 1220805 的早期界面中，服务端已知费用阻断时按钮仍可点，点击后才返回 409。a802e32 将按钮启用条件与服务端原因对齐，保留写入时的二次准入校验。已计费的 200 响应在流式正文中断后再次执行时，原收费保留，原生重试与旧请求编号关联；这条边界有模拟传输测试。

本次使用 VIP 的真实 Chromium、固定版本 Harness、独立产品服务和持久化的 SQLite 数据库。计价协议仅在显式安装且地址完全一致的隔离回环提供方上启用，金额来自回环服务逐笔回执；隔离配置仅支持受控派工。真实供应商的每笔价格、可执行封顶和账单核对，需要相应供应商接口。生产未部署。原 Codex 四组并发首次准备 31.504 秒，超过 30 秒门槛，独立准备 9.430 秒通过，该观察继续保留。

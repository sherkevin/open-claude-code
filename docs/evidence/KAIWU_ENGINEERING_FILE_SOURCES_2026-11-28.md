# 工程任务的文件依据与关窗回访

开物开发版可以让成员核对普通聊天附件原文，看到工程执行器实际报告的读取结果，并在关窗回来后找回同一份回执。只在普通聊天选择文件，工程任务仍取不到这些附件。普通成员交付工作区文件的入口已记入 P2-003。

## 同一问题在三个入口的结果

在 VIP 隔离环境的空目录放入两份随机生成的非敏感说明。三个产品收到相同问题，要求说明订单默认导出什么格式、发票预览支持哪些格式，并各给文件名、行号和原句。文件名在题目中，格式、行号和原句均从本次实际工具返回取得。两条原文如下。

| 来源 | 实际原句 |
|---|---|
| `export-guide.md:3` | 未选择格式时，订单默认导出为 CSV。 |
| `preview-guide.md:3` | 预览支持 JSONL 和 ODS 两种格式。 |

| 用户操作，每种条件 1 场 | 查文件时可见 | 可核对的引用 | 关窗后 |
|---|---|---:|---|
| 开物旧版 4ada735，普通成员在聊天添加两个附件，打开工具栏「Codex 工程任务」再发送 | 只见执行中与任务完成。原生的两次读取均返回文件不存在 | 0/2 | 从首页回到同一会话，仍见无法给引文的答复 |
| 开物开发版 74468a4，同一普通上传入口 | 发送前可点两份原件，切到「源码」核对；工程窗说明仅发送文本。任务过程中有执行器报告，最终显示成功 0 次、失败 2 次 | 0/2 | 工程窗和普通会话的「Codex 工程回执历史」都保留失败计数 |
| 开物开发版，由隔离测试准备方先放妥两个文件 | 两次只读命令退出码均为 0，工程窗显示成功 2 次、失败 0 次 | 2/2 | 两处原句和读数都可找回 |
| 原生 Codex 0.165.0，从已授权工作目录启动终端并输入原题 | 终端先后显示两个被读取的文件名。两个命令退出码均为 0 | 2/2 | 关闭终端后用 `codex --no-daemon resume` 按首问选择原会话，显示原读取进展和引文 |
| 原生 DeepSeek Harness 0.2.2-rc.1，从网页选择已授权工作区并发送 | 聊天显示两张 Read 卡，每张点一次即可看带行号的原文；Trajectory 留下工具调用 | 2/2 | 关闭所有 Chromium 窗口，重连原服务并从侧栏选回会话，可读原答和工具卡 |

各端运行真实执行器、工具和用户界面。模型均为隔离回环提供方，只根据收到的工具回包选择原句。此结果衡量文件交付、工具反馈和回访体验，线上模型质量与生产部署仍待各自验收。原生产品由用户在启动时选择已有工作目录；开物的工程目录按成员与会话隔离。测试方预置文件是正控条件，普通上传的结果单列。

上述三场开发版读文件样本以及一场自述负控，冷开各新增 0 次用户发送、0 次模型收件。两份普通附件均可从工程窗打开原件，返回后原任务草稿仍在。普通附件选择保存在当前聊天草稿。冷开验收查的是留存回答和执行记录。

## 什么能从回执判断

宿主沿用固定 Codex App Server 的原生通知。只有同一线程、同一轮次且明确标为单个读取动作的命令才参加计数。同一执行项按 ID 合并，完成且退出码为 0 才记成功。拒绝和失败记失败，有开始但缺少有效终态记未确认。已观察的零次与旧版本、崩溃核对时没有留存计数的情况分别处理。只向本人回执提供计数，命令字符串、路径和工具输出不进入这个字段。界面可显示读取命令的结果；引用是否支持结论仍要核对文件原句。浏览器在两次读取间的回环停顿仅用于截取页面，没有据此得出时延结论。

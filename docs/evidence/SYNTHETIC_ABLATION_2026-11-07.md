# 本地合成消融基准（2026-11-07）

## 目的

把知行工作台的增强模块去掉，构造一个最简单 Agent 作为客户现有助手的消融基线。该基线不是客户系统调用，也不代表任何真实客户效果；它只用于验证指标口径、报告结构和可视化。

## 两个可复现参与者

- **知行工作台（增强方案）**：保留记忆摘要、来源标记、检索与图谱占位的本地确定性逻辑。
- **最简单 Agent（客户现有助手的消融替身）**：不接入知识库、图谱、记忆、自动路由、审批增强或子代理，仅逐项处理固定文本任务。

报告另外登记“客户现有助手（真实数据待授权）”，所有指标保持 `not_measured`，避免把基线冒充客户实测。

## 固定任务与指标

固定四项任务：报价政策问答、跨轮行业记忆、长文档事项提炼、图片实体与维护动作。前三项使用固定文本和本地确定性逻辑完成；图片实体任务明确标记为 `not_measured`，因为当前只有本地 OCR/CLIP 和受控视觉候选，尚无标注集质量证据，不把网格缩略图或一次线路探针冒充视觉实体质量。运行器使用固定种子和文本 Token 估算，不调用模型、网络、生产数据或计费服务。当前报告版本为 `1.1.0`。

指标包括：

- 模型计费口径下的总 Token 和输入 Token（固定文本估算，数值越低越好）；
- 上下文压缩节省 Token（只作为差值展示，不计入总 Token）；
- 上下文记忆能力（记忆断言通过率，数值越高越好）；
- 上下文管理能力（检索、来源、压缩占位可追溯率，数值越高越好）；
- 任务正确性和来源覆盖率（仅对已支持的固定任务统计；图片语义任务单独显示为待测）；
- 本地编排耗时（仅衡量本地确定性逻辑）；
- 模型响应速度（没有获得模型授权端点时必须为 `not_measured`）。

## 任务覆盖与视觉边界

报告 `task_results` 同时返回四项任务的状态。前三项为 `measured`，图片实体任务为 `not_measured`，原因是缺少获批视觉模型和脱敏图片样例。增强方案和最简单 Agent 都不能在当前证据下宣称图片实体正确性；管理员页面会在任务范围卡片和指标中明确显示“待测”。

## Token 计费口径

两种参与者接收相同的固定任务信息：最简单 Agent 将原始历史上下文和来源全文重复放入输入，增强方案将其压缩为保留记忆和来源指针的短上下文。报告只把任务输入（增强方案为压缩后上下文）和输出计入总 Token；本地压缩过程不计入。当前固定夹具的可重复估算为：增强方案总 Token `187`（输入 `153`，压缩节省 `83`），最简单 Agent 总 Token `270`（输入 `236`，压缩节省 `0`），两者输出均为 `34`。这些数字用于验证口径和图表方向，不是任何供应商账单或真实模型分词结果；`token_accounting.note` 明确记录该限制。

压缩节省是原始上下文与压缩上下文的差值，用于解释为什么增强方案柱状图更低，但不会再次加回总 Token。客户现有助手仍为 `not_measured`，不能据此推断真实客户成本节省。

## 代码与接口

- 运行器：`server/app/benchmark.py` 的 `run_synthetic_ablation`；
- 管理员接口：`GET /api/v1/benchmarks/synthetic/ablation`；
- 前端：`client/src/BenchmarkPage.tsx`，展示增强方案、最简单 Agent 基线和待授权客户助手；
- 前端图表只给已测数值绘制柱状，未测指标显示“待测”，并标注本地合成证据边界。

## 当前证据边界

模型真实响应速度、真实模型 Token、客户助手的同任务正确性、上下文记忆和上下文管理仍缺证据。下一步需要用户提供客户同任务样例，并批准使用已授权模型端点；当前本地证据登记的是 DeepSeek v4.1 Flash 1017，用户要求的 1007 尚未发现可用目录映射，不能把 1017 或其他线路冒充 1007。在此之前不得填入推测值。

## Token 口径增量

2026-11-08 起，Token 对标改为同一固定任务的信息量比较：基线计入未压缩上下文，增强方案只计入压缩后的上下文和输出；压缩过程不计入总 Token。具体数值、字段和验证记录见 [TOKEN_ACCOUNTING_2026-11-08.md](TOKEN_ACCOUNTING_2026-11-08.md)。客户助手仍保持待测。

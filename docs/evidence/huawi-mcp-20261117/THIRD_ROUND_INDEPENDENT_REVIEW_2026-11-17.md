## 一、共同结论

三路审核均确认最终目标正确：

1. 客户 Windows 内网连接器主动出站连接开物平台。
2. 客户不开放公网入站端口，不建设 VPN。
3. 客户上游凭据只保存在客户连接器本机。
4. 平台只能调用客户已批准、只读、最小范围的 MCP 工具。
5. 调用必须绑定用户、助手、来源、工具、数据和撤销状态，并可审计。
6. 当前只能推进合成环境实现和受控试装准备，不能宣称云端 C 段已闭环、容量已验证或产品已正式可交付。

但 `v0.4-review` 仍有会影响实际实现、授权和数据安全的阻断项，不能直接作为冻结实施基线。

## 二、业务与客户可用性审核

结论：不通过。

阻断项：

| 编号 | 发现 | 处置要求 |
| --- | --- | --- |
| B-R3-01 | 平台配置中的静态 `A` 与 RFC 8693 换取的短期用户委托 `A` 混用 | `A` 只表示短期用户委托令牌；平台配置不含 Bearer，只含 Edge URL、`integration_id` 和令牌交换绑定 |
| B-R3-02 | 来源级工具 allowlist 由客户还是平台选择前后矛盾 | 客户本机管理员拥有来源级 allowlist；平台只能在客户已批准交集内签发更窄 grant；身份映射再取交集 |
| B-R3-03 | G7a/G7b 没有固定测试数据、查询和预期结果，HTTP 200 可能被误判为业务通过 | 增加客户测试数据包和结果匹配验收；销售和知识检索分别定义合成或脱敏数据、固定查询、预期字段、禁止字段和负向案例 |
| B-R3-04 | 身份映射只有数据模型，没有创建、导入、修改、失效和撤销入口 | 增加映射管理接口与页面、批量导入或组织同步、版本、审批、审计和撤销，不允许手工改数据库 |

高风险项：

1. HWC-060 的合成数据验收和正式真实数据验收需要拆开，避免 G7 前置条件循环。
2. HWC-028/HWC-059 是正式分发门禁，不能被普通 P1 书面接受绕过。
3. HWC-059/HWC-061 还需要可客观判定的 SBOM、许可证、构建比对和漏洞扫描规则。
4. 客户目标 Windows Server 2019 与我方回归虚拟机必须明确区分。
5. 客户本机导入 `B`、`S` 和渠道身份的步骤必须进入 helper 用户旅程。

## 三、安全架构与协议审核

结论：不通过。

阻断项：

| 编号 | 发现 | 处置要求 |
| --- | --- | --- |
| S-R3-01 | `A` 的静态平台授权和短期用户委托含义冲突 | 只保留短期用户委托含义；平台配置、示例和审计禁止出现静态共享 Bearer |
| S-R3-02 | 助手运行时自行签发 `U`，无法证明真实登录用户 | `U` 必须由独立平台 IAM 基于已认证用户会话签发；模型和调用参数不能指定 `sub` |
| S-R3-03 | `A/E` 没有完整绑定华微实际身份和不可变映射版本 | 映射增加唯一事实源、`mapping_version`、策略摘要和签名引用；映射变化递增版本并失效旧会话 |
| S-R3-04 | 工具 allowlist 主要按名称授权，上游可替换同名工具语义或 schema | 审批绑定规范化名称、输入输出 schema、描述、注解、版本或实现标识；变化后重新审批；试装使用上游强制只读账户 |
| S-R3-05 | 命名管道只检查 ACL、管理员 SID 和提权状态，不能防止管道抢占或远端管理员访问 | 使用 `FILE_FLAG_FIRST_PIPE_INSTANCE`、`PIPE_REJECT_REMOTE_CLIENTS`、服务映像和签名校验、挑战响应以及本机交互会话检查 |
| S-R3-06 | 受控试装包在 G7a 安装前没有漏洞扫描、第三方来源证明和独立构建比对 | 在 HWC-061 中增加 SCA/CVE、恶意软件和秘密扫描、`frpc` 来源签名/哈希、完整文件清单和独立可重复构建比对 |

高风险项：

1. `A` 应使用 DPoP 或 mTLS 持有者绑定，并具备一次性 `jti`。
2. `E` 的一次性 `jti` 应持久化到过期后，正文只解析一次并按签名对应字节转发。
3. `B/S/D/T` 需要完整生命周期矩阵；华微签名不支持 `kid` 时必须定义受控维护切换。
4. 目标固定必须解析一次、校验后直接拨号批准 IP，禁止二次解析、重定向和系统代理；控制面不能下发上游 CA。
5. MCP 响应需要内容类型、总字节、事件数、解压后大小和流持续时间上限。
6. `sign`、HMAC 原文和动态身份头必须加入强制日志禁止项。
7. HWC-026 原来写“前三项未验证”，应改为四类故障目标均未验证。

## 四、交付、测试与运维审核

结论：不通过。

阻断项：

| 编号 | 发现 | 处置要求 |
| --- | --- | --- |
| D-R3-01 | `fix/windows-service-20261117` 的提交未合入当前集成分支，计划与证据未进入版本控制 | 合入并推送修复提交，提交计划、证据和契约，从冻结提交重新构建并记录包哈希 |
| D-R3-02 | 正式签名门槛可被普通 P1 书面接受或“客户认可的长期校验方案”绕过 | Authenticode、可信时间戳和 HWC-059 验证是正式分发门禁；普通 P1 豁免不能覆盖 |
| D-R3-03 | 当前 A/B 证据不满足 G5/G6/G7a，候选包也缺少 HWC-061 合规文件 | 在客户目标 Server 2019、安全软件开启和专用最小权限账户下重测；补齐原始证据和完整合规包 |

高风险项：

1. 旧交接文档仍写云端下发 `local_host/local_port` 和 Edge 持有 `B`，必须标记废弃，不能按旧口径实现。
2. 候选包运维说明错误宣称导入后即可调用，必须改为完成 C 段接入和 G7a 后才能调用。
3. 监控告警需要冻结具体阈值、采样窗口、连续超限条件和确认时限。
4. HWC-026 的四类故障必须逐项绑定 claim ledger，未测前不能宣称任何一项达标。

## 五、处置决定

项目负责人决定：

1. 业务、安全和交付三路阻断项全部进入 `v0.5-implementation-baseline`。
2. 不再组织第四轮纯文档审核，直接进入实现；但实现完成仍必须用代码、测试和证据逐项证明。
3. 优先做出可供华微受控试用的 Windows 连接器，先覆盖安装、服务、本地管理、HTTP MCP 导入、工具发现、诊断、升级回滚、受控秘密导入、合成 MCP 和合规打包。
4. 云端接入码、设备身份、relay、Edge、OAuth 和真实客户 MCP 只有在测试环境资源明确后才能联调。
5. 本文件不是审核通过证明，也不把任何计划要求当作已实现功能。

# 华微内网 MCP 桥接计划第二轮独立复核记录

- 复核对象：`docs/plans/2026-11-17-huawi-kaiwu-mcp-bridge-requirements-and-delivery-plan.md` 的 `v0.2-review`
- 复核日期：2026-11-17
- 复核方式：业务与客户可用性、安全架构与协议、交付测试与运维三个独立视角只读复核
- 边界：未修改业务代码，未部署，未重启共享服务，未使用真实客户数据或真实凭据
- 第二轮结论：`v0.2-review` 不通过，不能作为冻结实施基线；发现问题已进入 `v0.3-review`
- 当前状态：`v0.3-review` 仍需第三轮独立复核；本文件不是审核通过证明

## 一、共同结论

三路复核均确认最终目标正确：连接器从华微内网主动出站，开物平台通过 Edge 和中继调用经逐用户或逐组织授权的只读 MCP，不开放客户入站端口，不把客户凭据上传云端。

但 `v0.2-review` 仍存在会影响实际授权、数据安全和可验收性的阻断项。主要问题不是增加功能数量，而是以下闭环尚未被唯一协议定义：

1. 静态 A 不能证明具体平台用户，必须先完成“A + U + mapping -> E -> 连接器验签”的主体链。
2. MCP 默认拒绝只覆盖平台到上游，没有阻止恶意上游通过 sampling、elicitation、roots 或跨请求 SSE 反向驱动平台。
3. 回环页面令牌不是 Windows 管理员身份，必须落到提权 helper 和受限命名管道。
4. 来源目标、入口路径、Host、SNI、DNS 解析和会话归属没有形成唯一重建规则。
5. 1.0.1 的 A/B 只有报告级结论，原始证据文件缺失；5 秒 503 尚未验证。
6. 发布基线、原始证据、逐项追踪矩阵、容量阈值、监控值班和许可证仍未闭合。

## 七、复核结论

`v0.2-review` 不通过。`v0.3-review` 已针对本文件列出的阻断项增加或修改 HWC-001 至 HWC-061，但只有第三轮复核确认这些修订形成可执行、相互一致且可测试的唯一契约后，才能作为冻结实施基线。

`v0.3-review` 在第二轮意见基础上进一步采用 MCP 常见的 OAuth 2.1 Resource Server 模型：平台内部 U 只在 RFC 8693 Token Exchange 中使用，不通过自定义 HTTP 头发给 Edge；Edge 只接受逐请求、绑定用户和资源的 A。这样可以避免把“助手服务令牌”和“用户身份”拼成非标准双头协议。

在此之前：

- 不进入业务代码实现。
- 不部署生产。
- 不重启共享服务。
- 不使用真实客户数据或凭据。
- 不宣称 C 段已闭环、企业容量已验证或平台已可正式交付。

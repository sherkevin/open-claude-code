# 知行工作台 0.4 使用与配置

助手保存角色、知识库、数据连接、Skills 和网页能力。同一个助手可以拥有多个独立会话；会话固定绑定所选助手，分别保存聊天记录、上下文、工作文件和可变记忆，可同时执行任务。打开“记忆”，按助手筛选并选择具体会话，查看、编辑或清除该会话的记忆。

## 开始工作

1. 在工作台选择助手，进入详情页直接配置能力，或切换“会话”查看历史；点击新建会话，选择助手、模型和推理级别。
2. 描述任务，按需添加附件或输入 `@` 选择助手已启用的 Skill。Skill 只应用于本次提交，界面记录实际版本。
3. 执行过程中可查看初始化、模型响应、工具调用和实际耗时；需要审批的操作由用户决定，也可以停止任务。
4. 在会话管理中搜索标题或历史内容，设置分类和标签，重命名、归档或恢复会话。归档保留历史，恢复后可继续。

当前公开模型为 Dano-v2.1、deepseek-v4.1-flash、GLM-5.3、混元 4 和 Kimi 3.1 PRO。混元 4 与 Kimi 3.1 PRO 在没有配置有效上游线路时显示为不可用，不会伪装成可调用。Dano 提供 light、high、max 三档推理级别。已有原生上下文的会话进入或离开 GLM 时需要新建会话，界面会引导；不会暗中丢弃历史。

## 配置自己的助手

每个成员可以创建和编辑自己的私人助手、知识库、MCP 连接及 Skills。管理员负责团队共享配置。共享资源可供授权成员使用，普通成员不能修改；管理员身份也不会自动获得其他成员私人资料或凭据的读取权限。

助手详情页可直接设置知识库、数据连接与工具授权、Skills、网页搜索开关，并调整角色说明、默认模型和访问范围。配置需要明确保存；有未保存修改时离开会提示，版本冲突不会自动覆盖另一窗口的保存。新助手默认关联管理员指定的公司知识库，用户可以调整；业务知识库和数据连接由用户选择，不会自动接入试用数据。

## 知识库

创建知识库后上传 PDF、DOCX、Markdown、TXT、CSV 或 JSON。文件原件和各版本保持独立，解析状态、PDF页数及文本片段数可查看；失败的文件可重新索引。扫描 PDF 在服务器本地识别文字。

检索结合关键词和本地向量；部署使用的向量模型及是否启用语义向量由接口真实返回。模型文件需在部署时准备，业务文档不会上传给外部嵌入服务。助手可先检索相关片段，再按页读取原文。知识库用于业务事实；个人记忆用于稳定偏好和工作约定，两者分开管理。

部署时先运行 `python scripts/prepare_knowledge_models.py --cache-dir <模型缓存目录> --download`，按命令输出设置本地模型路径与缓存环境变量。运行服务默认不自动下载模型；离线环境可复制已验证的模型目录，使用 `--cache-dir <模型缓存目录> --model-path <模型目录>` 检查。切换向量模型后，由有编辑权限的账户调用文档重新索引接口更新现有文件，详见运维手册。

公司介绍材料保留原件及页码。文件中的规划、试点和已交付能力应按原文区分。独立的“工业业务试用知识库”及试用数据库只绑定试用助手；实际业务助手应选择客户自己的资料和 MCP。

## MCP 与 Skills

在数据连接页填写远程 HTTP MCP 地址及认证信息，或导入已有 MCP JSON。测试连接后选择工具；配置写入助手时明确哪些操作可自动执行、哪些需要审批。凭据保存在服务端，工具仍受业务系统权限控制。服务器的网络允许列表由部署管理员配置。

在 Skills 页创建流程或导入 SKILL.md，编辑说明及参考文本，再绑定到助手。每次编辑生成新版本，历史任务使用提交时的版本。Skills 不会自动扩大工具权限，也不执行导入包中的安装脚本。

启用网页搜索后，助手可以搜索公开网页并读取原文。搜索摘要和实际网页正文在来源信息中分别标识；网页访问不允许本机或内网地址；检索词应只包含必要信息，不应包含公司文档全文或凭据。

## 核对来源

答案中的编号可点击，来源详情分三类：

- **数据**：数据源、数据库、schema、表、字段、记录键或筛选、时间区间与时区、查询时间、汇总口径及当次结果片段。位置由 MCP 工具提供；缺少的信息不会推测补齐。
- **知识**：知识库、文件、版本、内容哈希、页码或段落、引用片段。打开原件始终读取当次引用版本，PDF 可跳到对应页。
- **网页**：网页标题、原始链接、抓取时间、可获得的发布时间及引用片段。搜索摘要不能替代原网页的精确引文。

来源由服务端根据实际工具结果登记。点击时重新校验权限；资料撤权或助手能力停用后，旧来源可能无法再打开。聊天历史中已经产生的回答不会因撤权而自动删除。

## 耗时与连接

运行时复用活动会话，空闲回收后可恢复。界面区分初始化、等待模型、工具调用和可见回答；完成后可查看各阶段毫秒数。耗时包含提供方等待和模型推理，不能将全部等待归因于网络或初始化。出现失败时保留已完成信息，不自动重放可能产生业务写入的操作。

TokenHub 按量计费开关、代金券抵扣及剩余额度是独立于本应用的账户状态。执行链路恢复不代表自动充值；实际扣费及网络可用性以提供方状态为准。

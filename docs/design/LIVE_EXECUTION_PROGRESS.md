# Agent 过程展示设计

## 目标

用户在一次长任务中要持续知道三件事：

1. 当前正在处理哪一件业务动作。
2. 已经拿到了哪些可核验结果。
3. 是否需要用户确认、选择或等待。

界面把过程拆成三层。第一层始终可见，第二层贴近回答，第三层保留完整记录。

## 三层界面

### 当前动作

回答区域下方显示一张轻量的“当前动作”条。它包含状态、动作名和一句事实说明。

- 准备执行环境。确认助手配置、会话上下文和可用能力。
- 模型已开始响应。收到真实的 message_start。
- 正在生成回答。收到正文增量。
- 正在调用工具。收到真实的 tool.started。
- 已取得工具返回。收到真实的 tool.completed。
- 等待你的确认。收到 approval.required。
- 正在整理上下文。收到 context.compaction_started。
- 连接暂时中断。SSE 断开且恢复流程正在进行。

“模型已开始响应”表示模型事件已经到达。它不表示界面知道模型的私有思考内容。只有以后接入了明确的、允许公开的 reasoning metadata，才可以增加“已整理步骤”之类的摘要。界面不把等待时间、token 数或动画当成思考依据。

### 执行脉络

当前动作条下面保留最近四个阶段，用短词表示顺序。例如：

理解任务 → 调用质量统计 → 核对指标定义 → 正在比较趋势

它由已保存事件投影得到。工具并行时，每个工具单独显示为一行或一个节点，完成顺序按事件时间排列。两个同名工具不能只按名称合并，必须使用 (run_id, tool_call_id) 关联。

工具结果默认只展示服务端登记的事实摘要。摘要可以包含返回行数、过滤条件、命中状态、耗时和来源数量。原始参数和完整结果放在“详细记录”中，且经过脱敏。

### 详细记录

右侧或抽屉保留完整可审计轨迹。它包括工具名、开始与完成时间、成功状态、审批决定、压缩状态、产物和来源链接。用户可以逐条展开，不影响回答阅读。

工具调用完成表示工具过程结束。业务结论是否成立由回答和来源共同决定，因此“工具完成”不直接写成“业务已完成”。

## 状态模型

状态由服务端事件投影，不由客户端计时器推进。建议使用以下有限状态集合：

queued → preparing → waiting_model → answering ↔ tool_running → awaiting_approval → answering → completed

可以从任意活动状态进入 failed、cancelled 或 interrupted。工具并行时，主状态保持 tool_running，子工具分别有 started、waiting、completed、failed。

当前 0.4.2 已有的真实信号如下：

| 公开事件 | 用户可见含义 |
| --- | --- |
| run.started | 本次执行已进入运行队列 |
| run.stage | 服务端确认的执行阶段 |
| message.delta | 回答正文正在流式到达 |
| tool.started | 工具请求已发出 |
| tool.completed | 工具返回已处理 |
| approval.required | 需要用户确认 |
| approval.resolved | 审批请求已结束 |
| context.compaction_* | 原生上下文压缩生命周期 |
| run.completed | 本次执行进入终态 |

message_start 当前投影为 run.stage=model_started。它的文案使用“模型已开始响应”，避免把模型内部推理当作可见事实。

## 结果与来源

一条过程记录分成事实摘要和来源引用两部分。

事实摘要只来自工具返回或服务端运行记录，例如“返回 2,184 条记录”“发现两个日期字段”。如果工具没有返回业务事实，界面显示“工具已返回，等待整理”，不补写数字。

来源沿用三类来源：

- 数据来源。显示数据源、数据库、表、字段、筛选条件、时间范围、查询时间和可验证的业务定位。
- 知识来源。显示知识库、文件名、版本、页码或文本区间。
- 网页来源。显示网页标题、原始网址和读取时间。

来源编号在最终回答中继续使用脚注。过程卡中的来源芯片直接打开来源详情，详情接口按当前用户权限再次校验。

## 审批、停止与错误

审批卡显示“将执行什么”和“为什么需要确认”。参数默认折叠，用户可以允许或拒绝。收到 approval.required 后，当前动作切到“等待你的确认”，不会继续显示“正在思考”。

拒绝、超时和授权失效统一显示为“未获授权”。只有服务端有明确的用户决定时才显示“已允许”或“已拒绝”。

停止任务时显示“正在停止当前任务”，直到收到终态。任务被取消后，已经完成的工具记录仍保留，后续新消息不能自动重做旧操作。

断线时保留最后一条当前动作，并显示“连接暂时中断”。重连使用 after 或 Last-Event-ID 继续读取，按 (run_id, event.id) 去重。客户端不清空执行脉络，也不重新发起工具调用。重连后如果服务端已进入终态，客户端刷新运行和消息快照。

## 一个工业场景

用户提出“分析 3 号线近 7 天不良率变化”。

过程展示按下面的顺序变化：

1. 理解任务。范围锁定为生产线、时间范围和指标。
2. 调用质量统计。显示已返回的记录数量和数据来源。
3. 核对指标定义。显示知识库命中的定义文件与版本。
4. 等待确认。如果读取班组明细需要权限，显示将执行的操作和允许、拒绝按钮。
5. 发现口径差异。如果生产日期和检验日期不一致，显示差异字段和下一步选择。
6. 生成结论。回答正文出现脚注，底部列出数据、知识和网页来源。

这套过程的重点是让用户看到“动作与业务问题的关系”。工具名是辅助信息，业务动作、拿到的事实和下一步决定是主要信息。

## 当前实现与后续事件扩展

本地客户端已经加入当前动作和最近四步执行脉络，覆盖运行准备、模型响应、正文生成、工具调用、审批、上下文压缩、取消和断线恢复。实现位于 [ChatPage.tsx](../../client/src/ChatPage.tsx) 和 [styles.css](../../client/src/styles.css)。

后续服务端可以增加两个受控字段：

- tool.started.requires_approval。让客户端明确区分工具请求和审批等待。
- tool.completed.source_ids。只返回本次工具调用已经登记、并且通过当前权限校验的来源 ID。

这两个字段属于展示元数据，不携带原始模型轨迹、完整工具结果、凭据或服务器路径。加入字段时保持旧客户端可忽略，SSE 的游标、事件 ID 和重放语义不变。

## 验收条件

- 模型开始响应后，界面显示“模型已开始响应”或“正在生成回答”，不显示未经授权的私有思考文本。
- 正文已经开始流式输出后，工具调用、审批和压缩状态仍然可见。
- 两个并行工具各自拥有独立记录，完成顺序不会覆盖另一条记录。
- 工具失败、审批拒绝、取消、服务中断和重连都能得到明确文案。
- 刷新或断线重连不会重复执行工具。
- 完成回答带有现有三类来源脚注，过程卡能打开对应来源详情。
- 产品信息查询这类 execution_kind=product_metadata 运行不显示模型推理阶段，也不产生模型用量。

dist/releases/0.4.2 和腾讯云正在运行的 0.4.2 没有因这份过程展示设计而重新部署。当前本地客户端已通过 TypeScript 构建和 52 项客户端测试。

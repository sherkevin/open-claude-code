# 外部能力与来源闭环

## 边界

本设计落实需求 §18。聊天模型决定何时提出工具调用，后端决定能否执行以及使用哪个能力提供方。模型不能自行安装插件、切换凭据或扩大授权。现有 MCP 连接用于业务工具；内置 search/fetch 复用同一个工作区工具注册及授权流程，不额外创建一套审批体系。

## 来源路径

真实工具结果 -> 当前用户/运行下的来源注册 -> 工具完成事件中的 source_ids -> 最终回答绑定 -> 来源卡 -> 点击后来源接口重新鉴权 -> 原网页。

- 从结构化结果或 MCP 文本封套中读取标识，不能通过整个数据库新增记录差集推断本次工具来源。
- 只有成功工具完成事件可补附；标识去重后再限制展示数量，正文优先，不能被早期重复候选挤掉。
- 明确引用、已读正文、仅搜索候选具有不同语义。补附搜索资料不是声称模型已阅读或答案得到证明。
- 已存在的内部知识引用和业务数据引用不删除；撤权及版本校验继续由统一来源服务执行。
- 当前来源接口返回的可信 HTTP(S) 原地址用于外跳；历史消息里的缓存地址不能绕过撤权。

## 能力控制面

管理员页面与服务端版本化设置互通；可用性来自真实配置状态，但不输出密钥、私有端点或完整提供方错误。主提供方、最多一个回退、启用及一至六十秒总超时都有服务器约束。保存使用版本比较，避免两个管理员覆盖配置。默认未保存时沿用环境中的旧行为。

有效权限是部署能力、用户及助手授权、工具授权与能力开关的交集。配置页面不是授权捷径。执行时和请求结束时保持当前权限校验；回退与主请求共用约束。超时不是重试倍数，不允许配置隐式无限回退。

全局 search/fetch 停用表示停止外部请求、回退和在途结果接纳，不抹去已取得的历史证据。历史来源仍根据当前用户有效性、助手联网授权和资源权限重验；助手或用户撤权必须拒绝。来源接口鉴权通过后的用户主动原网页跳转不是平台执行 Fetch 请求，此语义在页面与验收中保持一致。

OCR 显示现有知识摄取路径及独立聊天能力的区别。独立图片搜索没有已验证适配器，显示未接入，不提供假启用或假健康状态。密钥仍由服务端部署配置管理，本轮不增加网页明文保存密钥。

逐助手四能力授权、域名与数据外发范围、额度及重试治理、自助线路诊断和安全密钥配置流程列入 CAP-EXT-005 未完成清单，不因复用了现有联网开关而宣称第三阶段完成。

## 交付门槛

来源和配置两个功能分别独立分支，稳定提交交独立审核者复跑，负责人依次合并。必须保存对应测试结果、失败修复记录和未验证边界。只有这两个功能学校云证据通过才可称本轮代码切片通过；不将整个产品、全部模型或客户场景升级为完成。

## 2026-11-14 负责人直接接管后的合同

四能力在所有聊天模型上注册为同一套工作区工具；模型提出调用，后端执行器决定授权、线路、额度和结果准入。官方图片桥内部使用固定专用模型请求，不切换主会话模型，不向其发送完整历史或知识上下文。

- 图像能力按真实支持模式路由：`deepseek_webtools` 仅以图搜图，`brave_images` 仅文字搜图；`image_search.mode_providers` 可显式选择每种模式，省略时仅沿用原首选，不进行隐式供应商扩权。配置存在不等于实测可用。
- 来源同时限制原网页与原图域名，历史读取再次核验。图片不自动加载，原网页和原图分别通过来源接口重新鉴权后打开；本批次没有新增图片代理或内嵌第三方图预览。
- 管理员凭据只写接口须 HTTPS，或服务器显式允许的回环开发通道。只有配置中精确列出的代理来源 IP 能提供可信协议头，不能凭任意客户端头绕过安全传输。
- 助手可以进一步收紧四能力的域名、外发、每次任务/每日次数和上传大小，不得高于全局；保存版本冲突不覆盖旧值。历史总联网开关不误杀已明确授予的新细粒度网页权限。
- 调用去重以运行编号和真实宿主调用编号为键；审批回执由每次执行器进入产生的私有标识独占。SDK 公共参数仍严格，不向模型公开票据。
- OCR 返回每页有界文字、页码与 `source_id`，来源提取器遍历 `pages`；编号只是候选，仍经过注册表、同次运行和当前访问权验证。空、部分、截断均不标为完整。

# 外部能力与来源闭环

## 边界

本设计落实需求 §18。聊天模型决定何时提出工具调用，后端决定能否执行以及使用哪个能力提供方。模型不能自行安装插件、切换凭据或扩大授权。现有 MCP 连接用于业务工具；内置 search/fetch 复用同一个工作区工具注册及授权流程，不额外创建一套审批体系。

## 来源路径

真实工具结果 -> 当前用户/运行下的来源注册 -> 工具完成事件中的 source_ids -> 最终回答绑定 -> 来源卡 -> 点击后来源接口重新鉴权 -> 原网页。

- 从结构化结果或 MCP 文本封套中读取标识，不能通过整个数据库新增记录差集推断本次工具来源。
- 只有成功工具完成事件可补附；标识去重后再限制展示数量，正文优先，不能被早期重复候选挤掉。
- 明确引用、已读正文、仅搜索候选具有不同语义。补附搜索资料不是声称模型已阅读或答案得到证明。
- 已存在的内部知识引用和业务数据引用不删除；撤权及版本校验继续由统一来源服务执行。
- 当前来源接口返回的可信 HTTP(S) 原地址用于外跳；历史消息里的缓存地址不能绕过撤权。

## 能力控制面

管理员页面与服务端版本化设置互通；可用性来自真实配置状态，但不输出密钥、私有端点或完整提供方错误。主提供方、回退、启用及超时都有服务器约束。保存使用版本比较，避免两个管理员覆盖配置。默认未保存时沿用环境中的旧行为。

有效权限是部署能力、用户及助手授权、工具授权与能力开关的交集。配置页面不是授权捷径。执行时和请求结束时保持当前权限校验；回退与主请求共用约束。超时不是重试倍数，不允许配置隐式无限回退。

全局 search/fetch 停用表示停止外部请求、回退和在途结果接纳，不抹去已取得的历史证据。历史来源仍根据当前用户有效性、助手联网授权和资源权限重验；助手或用户撤权必须拒绝。来源接口鉴权通过后的用户主动原网页跳转不是平台执行 Fetch 请求，此语义在页面与验收中保持一致。

OCR 显示现有知识摄取路径及独立聊天能力的区别。独立图片搜索没有已验证适配器，显示未接入，不提供假启用或假健康状态。密钥仍由服务端部署配置管理，本轮不增加网页明文保存密钥。

## 交付门槛

来源和配置两个功能分别独立分支，稳定提交交独立审核者复跑，负责人依次合并。必须保存对应测试结果、失败修复记录和未验证边界。只有这两个功能学校云证据通过才可称本轮代码切片通过；不将整个产品、全部模型或客户场景升级为完成。

# HippoRAG2-lite 图谱增强检索设计

## 目标与边界

本项目采用 HippoRAG 2 的核心思想增强现有知识库检索：用来源绑定的知识图谱为查询建立种子，在有界图上运行个性化 PageRank，再把图分数投影回原始段落，和现有 BM25／本地向量结果融合。它是本地、可解释的 HippoRAG2-lite 增量实现，不是论文结果复现，也不宣称已经达到论文或真实客户的质量。

HippoRAG 2 论文描述的完整流程还包括无模式 OpenIE 三元组、同义词边、段落节点、query-to-triple 和语言模型识别过滤。本仓库当前没有在没有授权时伪造这些模型调用，因此本阶段复用已经存在的版本化实体节点和来源边，并把缺失的模型阶段明确标记为后续验收项。

## 数据流

1. 文档上传后仍按现有流程解析、切段、保存文档版本、词法向量、实体节点和来源边。
2. 查询选择 `hipporag` 模式时，先用查询词和已索引实体建立最多 32 个种子节点。
3. 只在当前知识库和当前文档版本（运行中则使用 immutable run snapshot）内展开最多两跳邻域；节点最多 4000 个、边最多 10000 条。
4. 使用阻尼系数 0.85、8 次迭代的确定性个性化 PageRank。无种子、无图或没有可绑定段落时回退到现有混合检索，不生成虚假图分数。
5. 将节点分数按页码和段落投影回文本片段，与 BM25／向量融合；结果仍通过现有来源登记，保留文档版本、页码、字符范围、内容链接和图片证据。
6. 接口返回 `retrieval.algorithm`、`retrieval.graph_trace` 和每个结果的 `graph_score`，前端展示种子、访问节点数、边数、回退原因与可点击证据。

## 安全与证据

- 默认检索模式仍为 `hybrid`，不会静默改变已有助手行为。
- 所有图查询重做知识库权限和运行快照过滤；图分数不能绕过来源权限。
- 视觉模型候选和 `evidence_only` 关系不会自动变成文本知识图谱事实。
- 本实现不启动外部模型、不访问生产、不读取真实客户资料，也不引入付费依赖。
- 图谱质量、召回率、答案正确率、Token 和延迟必须通过固定公开或脱敏样例单独测量；当前只有离线确定性算法证据。

## 后续阶段

1. 获得授权模型后，增加版本化 OpenIE 三元组、同义词边、段落节点和 query-to-triple 适配器。
2. 增加 recognition-memory 过滤和关键事实段落权重，并保留模型失败时的安全回退。
3. 把 OCR 区域和获授权的视觉实体作为带区域证据的 passage/phrase 候选，验证跨模态图检索。
4. 使用公开工业双跳任务和客户批准的脱敏样例，分别报告 Recall@5、MRR、答案正确性和成本；没有这些证据前保持“部分实现”。

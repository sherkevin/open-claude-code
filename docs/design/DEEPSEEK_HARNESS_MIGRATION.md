# DeepSeek Harness 渐进迁移设计

状态（2026-11-11）：用户已批准以 Harness 为开发底座，代码中新会话默认改为 Harness，已有会话保留原执行器；这不是现有服务已切换的声明。真实 Node 加本地合成模型已有聊天、流式正文、知识引用、审批产物、业务工具、停止与持久恢复证据；完整功能、真实供应商和生产验收仍未完成。操作见 [Harness 操作](../operations/HARNESS_PILOT.md)，执行顺序见 [主线迁移计划](../plans/2026-11-11-harness-mainline.md)。第 4、7、8 节保留历史切片，其默认 Claude 等叙述描述当时状态，不覆盖当前新默认。

## 1. 用户需求与选择

知行工作台需要可审查、可固定版本、可扩展的开源执行框架，但不能因为换框架丢掉已实现的对话、知识库、审批、记忆和多模态界面。采用 DeepSeek 官方 Harness 源码，不使用名称相似的第三方项目。开源代码仍遵守原 MIT 许可证和第三方依赖许可证，不改变其作者归属。

第一步已把业务工具从 Claude SDK 装饰器中解耦，而不是重写产品。`RunManager`、数据库、权限、知识文档和前端接口保留；现在由会话已固定的执行器选择实现，新会话代码默认 `HarnessRuntime`，`SDKRuntime` 用于旧会话和显式兼容模式。不自动迁移既有会话标识，默认变更不替代逐项功能等价验收。

## 3. 已核验的安全与兼容缺口

- 官方 `sdk-minimal` 配置含 `danger-full-access`、持久化 Shell、图片文件读取和工作目录修改；标准 `sdk` 还包含插件安装和调度。不得直接用于工作台任务。
- 官方 `approval/request` 没有完整工具参数，只有会话、工具名和可选调用编号/理由。不能据此批准涉及金额、数据范围和双人审批的任务。
- 高层 `Session.run()` 走 `session/query`，会解释 `/permission` 等控制命令。普通聊天必须走字面量 `session/prompt`。
- SDK 的 `env` 是覆盖宿主环境而不是清空继承；仅传几个变量不能保证凭据隔离。
- 官方 SDK 没有现有上下文统计的等价接口，也没有会话级取消端点。当前持久化正文事件按模型步骤给出，不等同实时 Token 增量。

因此，本阶段不能宣称“全部切到 Harness”“支持原有全部功能”或“生产安全已经验收”。

## 4. 已实现的最小接入基础

### 工具注册表

`server/app/workspace_tools.py` 保存六个现有工具的唯一业务实现，描述、参数、读写标记和处理函数不依赖 Claude SDK。`server/app/capabilities.py` 只做旧框架包装，名称和调用契约不变。

旧包装器的 `check_tool=False` 表示由外层审批处理，不是“永远拒绝”，也不是“任何新框架可以直接执行”。新的执行入口必须在调用处理函数前完成自己的授权。

### 进程内只读知识桥接器

`server/app/harness_bridge.py` 的 `HarnessKnowledgeBridge` 默认关闭，只有受信宿主代码显式传入布尔 `True` 才能试点；没有配置页面、网络端点、后台启动器或运行时选择开关。

| 边界 | 默认策略 |
|---|---|
| 工具 | 只允许 `knowledge_search`、`knowledge_read`；不接受工具别名、外网检索、Shell、插件安装和写操作 |
| 身份 | 由受信运行时绑定当前用户、助手、会话和运行；模型参数不得携带这些身份 |
| 参数 | 查询最多 2000 字，返回数量 1–20，页码 0–100000；文档编号为有界不透明标识；拒绝多余字段与布尔数值 |
| 活动状态 | 必须是未归档会话的当前 `running` 任务；取消、换任务或身份不符时拒绝 |
| 权限 | 执行前后重新检查配置指纹、当前权限和运行快照；撤权后不向调用者返回读取结果 |
| 审批 | `check_tool` 非明确 `True`、模型代审生效、双人策略生效，任一条件满足即拒绝并提示继续使用旧受控运行时 |
| 证据 | 复用现有检索和原文实现，保留文档版本、source 标记和受权限保护的链接；不生成第二套索引或来源登记 |
| 审计 | `harness.bridge` 只记录固定 schema、服务端随机调用编号、白名单工具名、结果状态；不记录查询、文档正文或模型理由 |
| 审计失败 | 拒绝返回读取结果，给出固定错误；取消必须继续传播，审计故障不能让取消变成成功 |

这里的“只读”是业务能力限制。检索仍会写入来源登记和审计，这是既有证据系统的正常行为，不代表整个进程禁止文件或数据库写入。

### 官方 SDK 离线协议验证

`scripts/verify_harness_sdk_protocol.py` 检查固定提交与源码内容，导入真实官方 Python 客户端，连接脚本自己的模拟通信进程。模拟进程通过空环境启动，不读取凭据。验证初始化启用审批、普通文本不走命令解释、宿主默认拒绝原生审批、拒绝未知请求、等待期间处理请求、会话过滤及关闭。

报告明确标记 `fake-runtime-only`。这是通信协议证据，不是 Node Harness、真实模型、插件执行或生产隔离的证据。未提供上游源码的普通环境仍可运行应用和单元测试，两个依赖源码副本的可选测试会明确跳过。

## 6. 真实运行时启动门槛

1. 数据盘隔离运行环境，固定构建版本与依赖；不使用未固定版本的在线 `npx dsh`。
2. 自有锁定 Cordis 配置；不继承未审核的标准配置、宿主规则和插件路径，不允许模型安装或修改插件。
3. 会话独享进程、目录、环境白名单和受信通道；先验证无模型的真实运行时握手及关闭。
4. 自有工具插件把完整参数送回后端执行业务，不采用“审批通过后让原生 Shell 自行执行”的方案。
5. 开发隔离实例按明确范围进行真实进程验收；2026-11-11 用户批准新会话代码默认切换，但完整功能等价和安全回归仍是产品交付门槛，现有服务采用新版本另行执行。

生产部署和对外发布不包含在上述开发门槛内，仍需单独批准。

## 7. 真实链路增量（2026-11-10）

本节记录首个纵向切片；其中业务连接和双人审批的当时缺口已由第 8 节继续补齐。

用户确认推进后，完成第 6 节的隔离安装、自有配置、真实握手和后端工具桥接，保留功能等价与正式发布门槛。

`configured_runtime` 按会话已固定的 `runtime_type` 选择执行器。数据库迁移为旧会话写入 `claude`，新会话读取管理员的 `AGENT_RUNTIME_TYPE`；Harness 只使用 `harness_session_id`，不会恢复 SDK 会话。默认值始终是 `claude`。

`HarnessRuntime` 复用固定版本官方 Python 通信客户端。每轮创建会话专属的真实 Node 进程，使用私有配置目录和空环境启动包装器；轮次结束即关闭，下一轮从原生 JSONL 历史恢复。这样不必信任模型填报运行编号，上一轮迟到的请求也无法进入下一轮。普通消息走字面 `session/prompt`，实时事件由自有插件转发；成功还必须满足本轮收件凭据、完整模型终态、`turn/end=completed` 和 `session/wait`。

`server/harness` 生成空 bundle 配置并加载明确列出的基础模块与单一自有工具插件。实际注册表必须与后端下发白名单相同。`HarnessToolBridge` 复用现有工作台工具，完整参数先过当前账号、助手、快照与审批校验，执行前后重新核验活动任务、权限及审批策略。未知请求、错误会话、重复调用、撤权和过期审批不能执行。原生不完整审批请求始终拒绝。

当前可执行路径是知识检索与原文、现有公开网页工具、Excel 人工审批生成；图片生成继续返回原有不可用状态。真实测试只验证本地知识和 Excel，不把其他工具的注册解释为已经做过真实网络验收。已有模型代审与双人策略仍按原规则判断；当前插件工具集合没有可配置的成功业务路径，只验证拒绝边界。

截至 2026-11-11，聊天附件、业务 MCP 连接、只读上下文统计、受控会话记忆和手动压缩已接入开发基线；文件工具、自动整理、完整用量和真实子代理尚未完成。统计中的供应商原始字段和容量未知时保持未知，供应商成本未验收，不声称硬消费上限。手动压缩证据见[手动压缩验收](../evidence/HARNESS_COMPACTION_2026-11-11.md)，下一步继续自动整理、完整用量和真实模型等价验收。

## 8. 业务连接增量（2026-11-10）

### 组件选择

复用既有官方 MCP Python SDK 1.30.0，通过 `streamable_http_client` 和 `ClientSession` 调用业务服务；新增直接依赖 jsonschema 4.26.0，使用离线 referencing registry 验证完整参数结构。三个组件均为 MIT，版本、官方来源和本机安装包许可证摘要已记录在 `upstream-sources.json`。本轮检查固定版本本地源码和许可证，没有自动升级依赖；Python 3.10 的真实 HTTP 测试用于验证兼容性。

备选是 Harness 原生 MCP 模块，但其连接和调用在 Node 侧执行，不经过现有 Python 授权、审批和来源登记，无法直接满足本产品边界，因此不启用。官方 Harness 的简化参数校验也不能完整处理引用和组合结构；外部工具保留原始 JSON Schema，以成熟的 Python jsonschema 作为最终校验。没有自建另一套 MCP 协议或参数语言。

### 信任和调用边界

`MCPBusinessTool` 从运行快照与当前授权的交集中建立工具映射。Node 只接收 `external_` 加 32 位摘要的稳定别名、清理后的描述和原始参数定义；凭据、连接编号、地址和原始工具路由留在可信后端。模型不能通过参数覆盖这些字段。插件仍仅加载固定模块，启动时实际工具集合必须与下发定义相等。

`HarnessToolBridge` 将别名还原为现有规范工具名，复用账号、助手、连接、运行、人工与双人审批逻辑。完整参数先验证，再参与审批；审批后、初始化/发现工具后、远端返回后均复核授权与策略。即使发现接口没有增加连接 revision，只要存储的工具定义或远端输入定义变化也会拒绝。

每次调用使用独立官方 HTTP 会话，不在 Node 中保留业务连接。设置响应大小、参数大小、操作期限和禁止代理继承；拒绝重定向和压缩响应，避免 SDK 在同源重定向中重放业务 POST。超时或异常不会自动重发业务写入；远端已接收的操作不承诺可撤回。

成功的文本/JSON 结果先递归清除本连接凭据，再使用现有 `register_mcp` 登记真实来源，并给模型追加当前系统的引用标记。读取来源时继续检查当前连接和工具授权。远端错误、撤权和取消不返回成功来源；异常日志在调用上下文内去除原始正文及 traceback，不影响独立任务日志。

### 兼容范围与退出方式

当前不支持外部 schema 引用、`$id`、非文本资源返回、压缩 HTTP 响应和重定向。模型代审没有新增高风险白名单；业务工具仍依原策略进入人工或双人审批。授权后的外部写入不能通过事后取消撤销，网络失败后需要人工核对外部状态。

适配仅挂在 Harness 会话内。回滚将新会话默认设置为 Claude，保留已存在的 Harness 会话与数据；没有修改旧 SDK 的 MCP 客户端。依赖替换或升级需要重新验收协议、安全边界和真实进程路径。验收记录见 [业务连接证据](../evidence/HARNESS_MCP_2026-11-10.md)；附件、统计、受控记忆与手动压缩已在后续增量完成开发验证，仍需文件工具、自动整理、完整用量、真实子代理和真实供应商等价验收。

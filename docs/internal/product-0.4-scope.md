# 0.4 产品需求基线：助手、会话与可核对来源

日期：2026-11-05。状态：需求核对与现状审查完成，以下新增能力尚未实现；不改变已发布0.3.0归档。本文件是实施依据，不是功能已交付声明。

## 已确认的产品关系

- 助手是持久的Agent配置：名称、角色、默认模型、知识库、数据源/MCP、Skills、Web Search开关及使用权限。
- 一个助手对应多个会话；一个会话绑定一个助手，保存自己的消息、附件、模型选择、运行状态与上下文。创建会话时选择助手，之后不暗中更换助手。
- 入口分为助手管理、助手详情下的会话列表、统一会话管理。分类先采用文件夹/标签与按助手筛选，支持搜索、重命名、归档和恢复；归档不删除历史。
- 用户明确选择：成员可以配置自己的私有助手和能力，管理员管理团队共享配置。资源具有owner与private/team范围，私有凭据不会因助手被分享而暴露。
- 配置变化必须可追溯。每次运行记录实际采用的助手、Skill、知识文件版本；正在执行的任务使用已确定的配置，变更不能改写历史引用。

## 回答方式

Dano普通身份回答直接使用“我是Dano-v2.1，Better AI的工业智能助手”。取消常规身份介绍中训练归属、私有路由等模板说明；保留直接问题的真实回答边界，不制造基础权重归属事实。DeepSeek与GLM选项继续使用各自公开名称。

取消业务回答结尾反复出现的数据性质提醒。用于试用的数据和知识分别建立独立库，只给对应助手绑定；生产助手由用户另行选择正式资源，不自动混用。来源详情保留数据集真实名称、用途、版本和记录，直接追问数据性质时按事实回答。来源不足、相互冲突等会影响结论的信息仍需就事说明。

## 知识、数据与工具配置

1. Better AI公司资料库作为团队共享的默认基础资料；业务知识库按助手显式绑定。成员拥有自己的私有知识库。长时记忆独立保存用户偏好和会话积累，不充当公司事实资料库。
2. 原文件保留并版本化，按页/章节/段落记录文本与定位；文件读取和关键词/向量检索共同工作，检索结果附带可核验片段与来源ID。知识路径只读授权，不能由普通文件写入工具改写。
3. 数据接入先延续用户此前明确的客户MCP方式，独立的数据源配置记录逻辑库名、用途、可用表/字段与权限；客户MCP应返回结构化取数依据。通用SQL直连不是本轮自动扩展的前提。
4. MCP界面提供个人/团队连接、新增、编辑、导入、测试、工具选择和审批配置；Skills界面提供个人/团队Skill的创建、导入、版本、启停及助手绑定。Skill说明不能自行扩大助手工具权限。
5. 输入框输入@时显示当前用户和助手有权使用的Skills；选择后形成能力标签，随该条消息提交稳定ID和版本，默认只作用于当前任务。不会把任意服务器路径当作@Skill展开。
6. Web Search按助手启用，提供搜索、读取页面和网页引用。先验证现有模型线路/原生能力是否支持；必要时接搜索MCP，不能把模型接口兼容误认为搜索能力已可用。外部搜索仅携带完成任务所需查询，不自动发送完整内部知识文件。
7. OCR和向量索引需明确执行位置、模型和数据流；优先复用受控环境与已有授权服务，不默认把企业文件交给新增第三方。知识库显示解析/索引状态、版本与失败原因。

## 三类来源与脚注

有外部依据的事实或计算结论在对应位置附编号，答案末尾列出可点击的来源。用户直接提供的数字或一般对话不制造数据库、网页或文件出处；多轮沿用证据时保留原有授权和版本关联。

| 类型 | 来源详情至少包含 | 点击行为 |
| --- | --- | --- |
| 数据 | 数据源名称、数据库/schema、表或视图、涉及字段、记录键或筛选条件、数据时间范围/时区、取数时间；聚合结果还含统计口径/追踪ID | 有权限的证据详情页，展示当次结果和定位信息；有原业务记录链接则提供跳转，不暴露连接口令 |
| 知识 | 知识库、文件标题、文件版本/摘要、页码/章节/段落、引用片段、导入/更新时间 | 查看当时版本原件并定位相关页面或片段 |
| 网页 | 页面标题、原始URL、引用片段、访问时间；网站提供时记录发布/更新时间 | 打开原始网页；保留引用时片段以解释后来网页变化 |

来源由服务端从实际工具/检索结果登记，模型引用已登记ID，客户端渲染编号与链接。不存在、越权或冒用其他运行的ID不能形成有效引用。MCP没有返回的库名、字段、时间等不能推测补齐；详情明确展示缺失字段，促使连接端补齐证据契约。聚合值必须保留分子/分母、过滤条件和时间口径等实际计算依据。

## 已核对的实现现状

- 底层已是Assistant一对多Conversation；会话创建必须绑定助手，SDK执行实例按会话隔离。
- 已有会话重命名、归档和后端恢复；缺少助手详情下的历史会话、分类/搜索、归档列表与恢复入口。
- 当前MCP配置与逐工具授权已可视化，但仅管理员可配置；需要扩展为个人所有权与团队共享权限。
- 目前没有独立KB/RAG、Skills管理、@Skill或结构化来源注册。WebSearch/WebFetch/Skill当前均被显式禁用，需要能力接入和真实验证。
- 当前同用户/助手的长期记忆锁会阻止两个会话同时执行。多会话并行需设计记忆读写隔离或提交串行化，不能仅移除锁。
- 现有知识样本是代码内常量，工单已存独立SQLite；后续迁入明确的知识库和数据源资源。

# Web search runtime follow-up

- [DONE] Root cause: Tencent's system resolver synthesizes `198.18.0.x` addresses for Bing, GitHub, example.com and modelcontextprotocol.io. Python 3.10 correctly marks these benchmark-network fake IPs non-public. This was a proxy DNS mode mismatch, not a Python classification defect. Private probe: `.runtime/product-0.4/web-dns-probe.py`.
- [DONE] [Web transport](../server/app/web_tools.py) uses a bounded HTTPS public DNS fallback **only** if every system DNS answer lies in `198.18.0.0/15`. Literal fake IP URLs and mixed/private/link-local/loopback answers still fail. Fixed public-IP HTTPS resolver endpoints verify TLS certificates, ignore environment proxy configuration, reject redirects, cap responses at 64 KB and bound each resolver to 6 seconds. Every returned address must be public unicast; the page connection pins the selected validated IP and retains the original Host/TLS name. Existing page redirects still pass URL and network checks. No system DNS/proxy setting was changed.
- [DONE] Candidate-only Tencent read-only probe passed example.com (2.27 s), Bing RSS (1.78 s, 5245 bytes) and the official MCP protocol page (2.20 s, 178265 bytes, JSON-RPC present). Executed a private copied candidate module in a separate process, without replacing live application files or restarting services. Evidence: remote `.runtime/knowledge-04-install/web_candidate_probe.json`, local `.runtime/product-0.4/web-candidate-probe.py`.
- [DONE] [31 regression tests](../server/tests/test_web_tools.py) pass locally (`pytest tests/test_web_tools.py -q --basetemp=../.runtime/web-test-03 -p no:cacheprovider`) and against the private candidate module on Tencent Python 3.10 (`.runtime/knowledge-04-install/run-web-candidate-tests.py`, 31 passed, one harmless assertion-rewrite warning caused by explicit module loading). They cover real fake-IP shape, IP pinning, private/mixed/metadata/multicast rejection, response bounds, resolver redirects and overall timeouts. Root owns deployment and the later paid model rerun; the earlier failed end-to-end report remains unchanged.

The fallback sends only the user-requested public hostname to Cloudflare or Google DNS-over-HTTPS. It does not send the search text, webpage body, company documents or credentials to the resolver. The ordinary search request separately sends the intended query to Bing. Primary endpoint references: [Cloudflare JSON API](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/), [Google JSON API](https://developers.google.com/speed/public-dns/docs/doh/json).

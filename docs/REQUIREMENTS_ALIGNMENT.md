# Better AI 工业 Agent 需求对齐文档

**版本：** 0.2（需求对齐与产品升级基线）  
**日期：** 2026-11-06（Asia/Shanghai）  
**面向对象：** Better AI 产品、研发、测试、交付和客户评审人员

## 1. 这份文档解决什么问题

本文档把当前已经确认的产品目标、用户界面、服务端行为、权限边界和验收方法写成同一份可核对的基线。它同时记录当前实现状态，避免把设计设想误认为已经交付的能力。

状态含义如下：

| 状态 | 含义 |
| --- | --- |
| 已实现 | 源码、测试或远端实测已经证明，当前版本可以使用。 |
| 部分实现 | 已有可用基础，但仍缺少本需求要求的完整能力或真实客户验收。 |
| 设计中 | 已形成方案、接口或验收计划，尚未作为生产能力启用。 |
| 待确认 | 依赖客户资料、账号、MCP 地址、模型开通或业务规则。 |

本文档以当前源码、自动化测试、远端实测和部署配置为证据。历史版本的交付说明只用于追溯，不覆盖本文件的状态；“已实现”表示产品基础能力已存在，不表示已经完成华微世纪的真实业务验收。

## 2. 产品目标与交付形态

Better AI 交付一套面向工业场景的 Agent 产品。Better AI 是公司与产品运营方；Dano-v2.1 是公开的工业助手身份。当前客户端显示名称仍由 `AGENT_BRAND_NAME` 配置，默认值为“知行工作台”；是否把外部界面名称统一改为 Better AI，需要产品在发布前确认。底层模型线路、执行 SDK、MCP 客户端、上下文管理、记忆、压缩和用量控制由服务端统一管理。

一期交付由两部分组成：

1. **Client：** Web 工作台，负责登录、助手、Session、模型选择、聊天流式输出、附件、审批、执行记录、知识库、Skills、MCP 和用量界面。
2. **Server：** 受控执行服务，负责会话与运行时、官方 SDK 会话、模型路由、MCP 调用、权限、上下文、记忆、RAG、引用、审计、预算和事件流。

客户只需要在产品界面配置自己的 MCP、知识库、数据源和能力。客户当前没有既有 Harness；客户提供的是内部数据读取和业务操作 MCP。客户不需要接入我们的内部 SDK 或执行服务；我们的 Client/Server 是交付边界，客户 MCP 是能力输入。

## 3. 核心对象和关系

| 对象 | 定义 | 关系 |
| --- | --- | --- |
| Assistant（助手） | 一组角色提示词、知识库、数据链接、Skills、Web Search、默认模型和权限配置。 | 一个助手可以拥有多个 Session。 |
| Session（会话） | 用户与某个助手的一段独立对话，拥有自己的原生 SDK 会话、记忆作用域、工作区、模型选择和运行历史。 | 一个 Session 只绑定一个助手；新建 Session 时重新选择助手。 |
| Run（运行） | Session 中一次用户任务的执行实例。 | 一个 Session 同时最多一个活动 Run；不同 Session 之间必须可以并发。 |
| MCP Connection | 服务端可访问的客户 MCP 地址、认证信息、工具清单和权限绑定。 | 连接必须绑定到助手，并按工具授权。 |
| Knowledge Base | 用户或团队管理的版本化文件集合和检索索引。 | 助手显式绑定；运行开始时固定文档版本快照。 |
| Skill | 可复用的业务流程提示词和所需工具声明。 | 用户可绑定到自己的助手；管理员管理团队共享 Skill。 |

## 4. 角色和权限

### 4.1 成员

- 可以创建和配置自己的私有助手、Session、知识库、MCP 连接和 Skills。
- 只能访问自己拥有或被授权的团队资源。
- 不能因为自己是管理员而自动读取其他成员的私有 Session、记忆、附件或知识库。

### 4.2 管理员

- 管理团队共享助手、知识库、MCP 连接、Skills 和成员。
- 负责配置模型目录、TokenHub 路由、预算和服务环境。
- 管理员权限不绕过 Session、来源和工具的实际授权检查。

### 4.3 服务端安全边界

- 权限检查必须在服务端执行，不能只依赖界面隐藏。
- MCP 凭据只保存在服务端；客户端只看到连接名称、状态和工具授权结果。
- 每次工具调用都重新检查当前助手、用户、连接和工具授权。
- 不把客户密钥、私有上游模型名、服务器路径或原始 SDK 事件发给客户端。

### 5.5 知识库、RAG 和三类来源

知识库和 RAG 的目标是让模型只使用授权且可复核的证据。当前已实现文本知识库的版本化、混合检索、运行快照和引用登记。

三类来源必须保持区分：

1. **数据来源：** 数据库、表、字段、筛选条件、时间范围、聚合方式和查询时间。
2. **知识来源：** 知识库文件、版本、SHA-256、页码、段落、章节和原文链接。
3. **网页来源：** 原始 URL、抓取时间、网页标题、摘要或正文位置。

| ID | 要求 | 优先级 | 状态 | 验收 |
| --- | --- | --- | --- | --- |
| RAG-001 | 助手显式绑定知识库；运行开始时固定当前文档版本，运行中不悄悄读取新版本。 | P0 | 已实现 | 上传新版本后，正在运行的任务仍读旧版本；下一轮读新版本。 |
| RAG-002 | 检索支持词法和本地向量混合排序，结果数量和上下文长度有界。 | P0 | 已实现 | 检查 BM25、向量模型、RRF 排序和上限。 |
| RAG-003 | 检索结果保留文档、版本、页码、段落和原文位置；来源权限在读取和最终引用时再次检查。 | P0 | 已实现 | 撤销助手绑定或删除文件后，来源访问失败。 |
| RAG-004 | 回答中的事实引用显示脚注，底部列出可点击来源；模型不能伪造内部来源 URL。 | P0 | 已实现 | 检查已登记来源、未登记链接和跨会话来源。 |
| RAG-005 | 图片、表格、图形、OCR 和多模态图谱支持统一来源定位。 | P1 | 设计中 | 需完成布局解析、图片区域、表格单元格、视觉索引和图谱索引后验收。 |

### 5.6 多模态知识图谱

知识图谱不是第二套无来源知识库，而是从用户授权知识库中抽取的、带版本和来源的关系层。目标输入包括文本、扫描图片、PDF 页面、表格和图形；目标输出包括实体、关系、主张、置信度、来源页/区域和可追溯版本。

最低要求：

- 建立版本化的实体、关系、主张和来源表；每条关系必须指向一个或多个原始证据片段。
- 建图、检索、图扩展和最终引用都执行同一套权限检查。
- 支持增量更新、失败重试、旧版本墓碑和索引 epoch；不能因新版本覆盖历史来源。
- 图谱结果只能作为 RAG 候选或解释依据，不能直接变成系统指令。
- 视觉检索可选用本地视觉向量；外部视觉服务必须经过单独的数据出境和成本评审。

当前状态为设计中，具体方案见 [RAG_MULTIMODAL_GRAPH.md](design/RAG_MULTIMODAL_GRAPH.md)。

### 5.8 Sub-agent / Multi-agent

目标体验类似 Claude Code：Agent 可以根据任务拆分并行处理，不要求用户手工创建每个子任务。但产品必须由服务端控制拆分数量、工具权限、工作区、记忆、审批、预算、取消和恢复。

首选实现是服务端拥有的有界 fan-out：每个 child 使用独立 SessionActor、SDK 会话、工作区、记忆作用域、能力快照和预算；父任务只接收结构化结果、来源和产物 ID。

生产启用前必须满足：

- parent/child/root ID、状态、停止原因、预算和事件可持久化、可重放；
- 父任务取消会级联取消子任务并使子审批失效；
- 重启后不自动重放已经接受的外部写操作；
- 读任务可以并行，写任务必须审批并串行化；
- 子任务不能读取父 Session 的完整历史、私有记忆或未授权 MCP；
- 单个子任务失败不能泄漏资源或误取消兄弟任务。

当前状态为设计中，见 [SUBAGENT_ORCHESTRATION.md](design/SUBAGENT_ORCHESTRATION.md)。

### 5.9 OpenAI-compatible 接口和合成 MCP

### 5.11 四种审批策略

审批不再只有二元的允许/拒绝。每个工具、助手、连接和任务必须绑定风险策略，并在服务端重新校验当前权限。四种策略为：安全只读自动批准、模型代用户批准、用户明确批准、管理员或双人批准。模型代审批只能在管理员明确允许的低风险范围内运行，不能越过高风险人工审批。

### 5.12 自动任务拆分和安全执行进度

## 6. 非功能需求

### 安全与隐私

- 租户、用户、助手、Session、文件、知识库、来源和 MCP 凭据必须服务端隔离。
- 任何外部工具结果都视为不可信数据；不能通过工具结果注入系统提示词、路径或权限。
- 运行事件、轨迹和日志不得包含凭据、私有上游模型名、原始授权参数或隐藏思维链。
- MCP 域名、Web Search、文件读取、来源访问和附件下载全部执行服务端白名单与权限检查。

### 稳定性与恢复

- SSE 断线可以重连和补发事件；不能因前端断线自动重复提交工具。
- 服务重启后未完成 Run 标记为 interrupted，不自动重放外部写操作。
- 原生 SDK Session 空闲回收，需要时恢复；同一 Session 不允许并行 Run。
- 活动 Run、审批、上下文操作和模型切换之间必须有明确的忙碌边界。

### 成本和性能

- 工具结果、检索结果、图片/PDF 读取和模型路由输入都必须有界。
- `max_turns`、`max_budget_usd` 和产品侧累计费用记录必须同时启用。
- 预算阈值是响应后检查，不能宣传成绝对账单上限。
- 推荐路由、RAG、图谱和子任务都必须能单独统计耗时、Token 和费用。

## 7. 一期验收清单

1. 登录后可以创建助手，并配置 MCP、知识库、Skill、Web Search 和默认模型。
2. 同一助手可以创建两个独立 Session；一个 Session 等待审批时，另一个可以完成。
3. 模型下拉框显示五个公开选项；Dano 显示三个推理级别；未开通模型显示不可用原因。
4. 输入任务后点击 **Select the most fitness model**，推荐结果来自有界 DeepSeek 路由或安全回退，并自动应用到空闲 Session。
5. Tab 意图补全、`@Skill`、附件预览、工具审批、流式事件和取消可用。
6. 知识库检索能够返回文件版本、页码和可点击引用；数据、知识、网页三类来源在界面和 API 中区分。
7. 上下文统计、原生压缩、记忆编辑、Session 重命名/归档和用量记录可用。
8. 跨用户、跨助手、跨 Session、删除文件、撤销绑定和重启恢复的权限与恢复测试通过。
9. 使用合成 OpenAI-compatible 模型接口和标准 MCP 完成端到端工业任务回归，所有工具结果标记为 synthetic。
10. 上传 PDF、DOCX、XLSX、CSV、Markdown、TXT、JSON 和常见图片后，知识库和图谱自动生成版本、来源、节点和关系；失败任务可重试。
11. RAG 检索链和多模态图谱可视化展示召回片段、排序、来源、节点、关系和证据区域，并按当前用户权限过滤。
12. 任务提交时自动选择合适模型；用户可以覆盖，活动 Run 不得被切换，路由结果记录理由、预算和实际效果。
13. 四种审批策略分别覆盖安全只读自动批准、模型代用户批准、用户明确批准、管理员或双人批准；高风险动作不得由模型单独放行。
14. Agent 可以自动拆分有界 Sub-agent，并展示安全的滚动执行进度、工具、审批、上下文和子任务状态，不显示私有逐字推理链。
15. 对标页面使用固定合成基准和实测证据比较现有助手与本平台的准确率、速度、Token、上下文、记忆、多模态和可视化能力。

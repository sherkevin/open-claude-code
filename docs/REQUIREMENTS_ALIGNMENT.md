## 1. 这份文档解决什么问题

本文档把当前已经确认的产品目标、用户界面、服务端行为、权限边界和验收方法写成同一份可核对的基线。它同时记录当前实现状态，避免把设计设想误认为已经交付的能力。

状态含义如下：

| 状态 | 含义 |
| --- | --- |
| 已实现 | 在注明的运行时、环境和数据范围内，有实现与可重复测试证据；不自动适用于其他运行时、客户现场或生产。 |
| 部分实现 | 已有可用基础，但仍缺少本需求要求的完整能力或真实客户验收。 |
| 设计中 | 已形成方案、接口或验收计划，尚未作为生产能力启用。 |
| 待核验 | 需求明确，但现有证据不足以判定实现范围；不是未实现，也不是已通过。 |
| 待确认 | 产品范围或验收口径尚未决定；资源缺失写在差距中，不将已授权事项重复列为待授权。 |
| 持续维护 | 文档或治理的长期责任，不能作为一次性功能完成率的分子。 |

本文档以当前源码、自动化测试、远端实测和部署配置为证据。历史版本的交付说明只用于追溯，不覆盖本文件的状态；“已实现”表示产品基础能力已存在，不表示已经完成华微世纪的真实业务验收。

### 1.3 本轮消除的关键歧义

- **审批：** 风险分低、中、高三级；处理方式有只读自动、低风险模型代审、用户人工、高风险双管理员四类。高风险不能单人或模型放行；旧兼容路径是缺口，不是允许的产品规则。
- **对标：** 当前按用户指定的“最简单 Agent”做消融，不要求先取得客户现有助手。对真实客户助手的结论另需同任务证据，不能把消融替身改名成客户实测。
- **模型：** 用户本轮确认 Fitness 固定由 1007 回答，不只是用 1007 选别的模型。模式选择不再需要额外模型推荐调用；补全、视觉理解和生图仍是独立角色，1017 不能改名冒充 1007。
- **计费：** 页面可单列压缩后回答阶段 Token；所有实际模型调用，包括付费压缩、索引和失败调用，仍进入总用量账本。估算不能作为供应商账单或效果承诺。
- **迁移：** 隔离开发试点、已有功能等价、剩余产品需求完成、生产发布是四个不同门槛。Harness 不必靠虚报未完功能来证明迁移，但必须保留这些功能的后续任务。
- **质量：** 有图片、能打开、HTTP 成功、测试全绿，只证明对应结构或行为。用户授权研发制定门槛，本版第 7.2 至 7.5 节冻结工程目标；数据集尚待准备、尚未测得通过，不能把门槛制定当质量完成。

### 1.4 模型线路统一规则（2026-11-13）

- 知行工作台的聊天、Fitness 自动路由、Tab 补全、知识视觉/实体/关系角色和后续图片模型，生产模型请求统一经过腾讯云 TokenHub；模型目录中的 `upstream_model` 只表示 TokenHub 内的已授权映射，不能直接指向厂商公网端点。
- 服务端在运行 admission、运行配置和路由预检处执行同一条门禁：带凭据的非 TokenHub 外部地址返回 `TOKENHUB_ROUTE_REQUIRED` 或 `non_tokenhub_route`，不会以“模型服务未配置”或本地回退掩盖线路错误；缺失的真实授权仍显示不可用。
- `https://tokenhub.tencentmaas.com` 是唯一已核准的外部主机。学校云的 loopback 视觉适配器和保留测试域名只用于本地合成验证，必须明确标记为 `local_proxy` 或 `synthetic`，并且只在服务端 `AGENT_PROVIDER_TEST_MODE=true` 的隔离测试进程中使用，不能作为生产就绪证据。
- 默认视觉地址已改为 TokenHub OpenAI-compatible 路径；视觉调用仍需独立模型目录项、能力声明、开关和额度授权，不会把普通聊天模型冒充成视觉模型。
- 预检只返回脱敏的线路类别和授权状态，不返回 TokenHub 凭据、完整地址或私有上游部署名；实际 TokenHub 线路、模型开通、账单和延迟仍需在授权小流量验收中独立记录。

### 1.5 工作流范围变更（2026-11-13）

用户决定从当前产品中移除低代码工作流功能，优先保证聊天、知识库、模型补全、业务连接、审批和产物等主链路的稳定性。助手详情不再展示“工作流”页签，前端构建不再加载工作流画布；历史工作流服务代码、数据库表和迁移数据暂不物理删除，以便后续经单独批准后归档或迁移。正常部署的 `AGENT_WORKFLOWS_ENABLED=false`，已登录调用历史工作流路径统一返回 HTTP 410、错误码 `FEATURE_DISABLED`，不创建、修改、发布或运行工作流。旧工作流的历史实现和测试仅作为迁移兼容证据，不计入当前交付能力。

## 2. 产品目标与交付形态

Better AI 交付一套面向工业场景的 Agent 产品。Better AI 是公司与产品运营方；Dano-v2.1 是公开的工业助手身份。用户本轮确认界面品牌继续使用“知行工作台”，不改成 Better AI；客户端仍由 `AGENT_BRAND_NAME` 配置，名称一致性需另验。底层模型线路、执行 SDK、MCP 客户端、上下文管理、记忆、压缩和用量控制由服务端统一管理。

一期交付由两部分组成：

1. **Client：** Web 工作台，负责登录、助手、Session、模型选择、聊天流式输出、附件、审批、执行记录、知识库、Skills、MCP 和用量界面。
2. **Server：** 受控执行服务，负责会话与运行时、官方 SDK 会话、模型路由、MCP 调用、权限、上下文、记忆、RAG、引用、审计、预算和事件流。

客户只需要在产品界面配置自己的 MCP、知识库、数据源和能力。客户当前没有既有 Harness；客户提供的是内部数据读取和业务操作 MCP。客户不需要接入我们的内部 SDK 或执行服务；我们的 Client/Server 是交付边界，客户 MCP 是能力输入。

### 当前执行授权与交付授权分开

已授权的现有模型线路和公开资料可用于受控开发验证；缺少的端点、型号映射或生图适配器不能伪造，也不能以“已经授权”代替资源实际存在。公开工业样例可由研发自行收集和标注，必须记录来源、许可、版本及标注者；不得伪装为真实客户资料或独立人工金标准。Better AI 公司资料只使用本项目明确获准的资料，不扫描私人会话或其他项目目录。

当前授权允许修改开发代码中新会话的默认执行器为 Harness，不包括切换正在运行的共享服务。仍不部署生产、不重启共享服务、不切换默认检索、不使用真实客户数据或未授权付费模型；生产发布和共享服务操作另行批准。任何新虚拟环境、缓存、临时目录、权重都位于 `/media/data3/dengkw`。此前 0.4.1 的文档整理未调用模型、读取凭据或修改运行配置；0.4.2 开发默认切换、0.4.3 统计增量和 0.4.4 手动压缩的本地固定 Node 与合成模型验证分别记录。

## 3. 核心对象和关系

| 对象 | 定义 | 关系 |
| --- | --- | --- |
| Assistant（助手） | 一组角色提示词、知识库、数据链接、Skills、Web Search、默认模型和权限配置。 | 一个助手可以拥有多个 Session。 |
| Session（会话） | 用户与某个助手的一段独立对话，拥有自己的执行器会话、记忆作用域、工作区、模型选择和运行历史。 | 一个 Session 只绑定一个助手；切换执行框架不混用旧框架的原生会话编号。 |
| Run（运行） | Session 中一次用户任务的执行实例。 | 一个 Session 同时最多一个活动 Run；不同 Session 之间必须可以并发。 |
| MCP Connection | 服务端可访问的客户 MCP 地址、认证信息、工具清单和权限绑定。 | 连接必须绑定到助手，并按工具授权。 |
| Knowledge Base | 用户或团队管理的版本化文件集合和检索索引。 | 助手显式绑定；运行开始时固定文档版本快照。 |
| Skill | 可复用的业务流程提示词和所需工具声明。 | 用户可绑定到自己的助手；管理员管理团队共享 Skill。 |

## 4. 角色和权限

### 4.1 成员

- 可以创建和配置自己的私有助手、Session、知识库、MCP 连接和 Skills。
- 只能访问自己拥有或被授权的团队资源。
- 不能因为自己是管理员而自动读取其他成员的私有 Session、记忆、附件或知识库。

### 4.2 管理员

- 管理团队共享助手、知识库、MCP 连接、Skills 和成员。
- 负责配置模型目录、TokenHub 路由、预算和服务环境。
- 管理员权限不绕过 Session、来源和工具的实际授权检查。

### 4.3 服务端安全边界

- 权限检查必须在服务端执行，不能只依赖界面隐藏。
- MCP 凭据只保存在服务端；客户端只看到连接名称、状态和工具授权结果。
- 每次工具调用都重新检查当前助手、用户、连接和工具授权。
- 不把客户密钥、私有上游模型名、服务器路径或原始 SDK 事件发给客户端。

### 5.5 知识库、RAG 和三类来源

### 5.6 多模态知识图谱

知识图谱不是第二套无来源知识库，而是从用户授权知识库中抽取的、带版本和来源的关系层。目标输入包括文本、扫描图片、PDF 页面、表格和图形；目标输出包括实体、关系、主张、置信度、来源页/区域和可追溯版本。

最低要求：

- 建立版本化的实体、关系、主张和来源表；每条关系必须指向一个或多个原始证据片段。
- 建图、检索、图扩展和最终引用都执行同一套权限检查。
- 支持增量更新、失败重试、旧版本墓碑和索引 epoch；不能因新版本覆盖历史来源。
- 图谱结果只能作为 RAG 候选或解释依据，不能直接变成系统指令。
- 视觉检索可选用本地视觉向量；外部视觉服务必须经过单独的数据出境和成本评审。

当前状态为部分实现（本地视觉索引与受控候选阶段），具体方案见 [RAG_MULTIMODAL_GRAPH.md](design/RAG_MULTIMODAL_GRAPH.md)；视觉语义质量、异步摄取和完整图谱能力仍不得按已交付计算。

实体、关系、图片和融合的统一质量门槛见第 7.2 节；有来源、能点开、返回合法结构都不是语义质量通过。不得把目录、文献编号或不确定关系作为已核验设备事实来美化图谱。

### 5.8 Sub-agent / Multi-agent

目标体验类似 Claude Code：Agent 可以根据任务拆分并行处理，不要求用户手工创建每个子任务。但产品必须由服务端控制拆分数量、工具权限、工作区、记忆、审批、预算、取消和恢复。

首选实现是服务端拥有的有界 fan-out：每个 child 使用独立 SessionActor、SDK 会话、工作区、记忆作用域、能力快照和预算；父任务只接收结构化结果、来源和产物 ID。

生产启用前必须满足：

- parent/child/root ID、状态、停止原因、预算和事件可持久化、可重放；
- 父任务取消会级联取消子任务并使子审批失效；
- 重启后不自动重放已经接受的外部写操作；
- 读任务可以并行，写任务必须审批并串行化；
- 子任务不能读取父 Session 的完整历史、私有记忆或未授权 MCP；
- 单个子任务失败不能泄漏资源或误取消兄弟任务。

当前状态为部分实现（仅本地合成/只读证据），生产启用仍禁止；设计与边界见 [SUBAGENT_ORCHESTRATION.md](design/SUBAGENT_ORCHESTRATION.md)，阶段 1 证据见 [SUBAGENT_LOCAL_PRIORITY1_2026-11-06.md](evidence/SUBAGENT_LOCAL_PRIORITY1_2026-11-06.md)。

### 5.11 三级风险、四种审批策略

审批不再只有二元的允许/拒绝。风险分低、中、高三级；四种处理策略为：安全只读白名单自动批准、低风险模型代审、中风险用户明确批准、高风险双管理员批准。每个工具、助手、连接和任务都必须绑定风险策略，并在执行前重新校验当前权限。未知风险不得自动放行；高风险至少由两名不同且非申请人的授权管理员批准，缺少策略或白名单时拒绝，不能降级为单人确认。

本阶段模型代审默认禁用；启用和修改策略只允许启用状态的 `admin` 角色，管理员白名单不包含普通成员。策略固定使用本地合成 reviewer 标识（`synthetic-*`），仅允许 `Read`、`Glob`、`Grep`，且必须同时命中管理员配置的数据范围、操作范围和非负金额上限。服务端在调用前和放行前各复核一次授权、策略版本/摘要和参数摘要；模型输入只含最小化字段与参数摘要，不含原始提示词、凭据或私有历史。异常、超时、非法/多余字段、低置信度或不确定结果一律拒绝；中高风险工具不进入模型判定，转入人工路径。真实付费模型端点不会由此配置自动启用。

优先级 3 的高风险策略默认关闭；只有启用的管理员才能配置，并且空的工具或管理员白名单保持默认拒绝，不被解释为通配。启用后仅允许已分类为高风险且在快照白名单内的工具，必须由两名不同的启用管理员投票；申请人只能拒绝，不能批准自己的请求。策略版本、工具白名单、管理员白名单和请求参数摘要在创建时固化，策略变更、撤销、过期、取消或重启都会使旧请求失效。当前未配置高风险策略时仍兼容旧的单人用户确认路径，这属于明确的非生产遗留边界，不能宣称已经满足生产级双人默认。

### 5.13 现有助手对标和可视化基准

## 6. 非功能需求

### 安全与隐私

- 租户、用户、助手、Session、文件、知识库、来源和 MCP 凭据必须服务端隔离。
- 任何外部工具结果都视为不可信数据；不能通过工具结果注入系统提示词、路径或权限。
- 运行事件、轨迹和日志不得包含凭据、私有上游模型名、原始授权参数或隐藏思维链。
- MCP 域名、Web Search、文件读取、来源访问和附件下载全部执行服务端白名单与权限检查。

### 稳定性与恢复

- SSE 断线可以重连和补发事件；不能因前端断线自动重复提交工具。
- 服务重启后未完成 Run 标记为 interrupted，不自动重放外部写操作。
- 原生 SDK Session 空闲回收，需要时恢复；同一 Session 不允许并行 Run。
- 活动 Run、审批、上下文操作和模型切换之间必须有明确的忙碌边界。

### 成本和性能

- 工具结果、检索结果、图片/PDF 读取和模型路由输入都必须有界。
- `max_turns`、`max_budget_usd` 和产品侧累计费用记录必须同时启用。
- 预算阈值是响应后检查，不能宣传成绝对账单上限。
- 推荐路由、RAG、图谱和子任务都必须能单独统计耗时、Token 和费用。

### 7.1 展示与稳定性必须实际操作

### 7.2 工程质量门槛 v1（2026-11-11 冻结）

用户授权研发制定以下门槛，适用于首个完整公开工业示例版本。它们是按错误业务事实、错图和越权风险设置的工程最低目标，不是行业标准、已测结果、论文指标或客户签署的服务承诺。优先提高准入事实的精确率，同时设召回底线，不能靠隐藏所有候选获得高分。旧八题、21 个实体和六个图片目标只保留为已知问题回归，不充当新留出验收集。

**数据与标注：** 按文档家族分开发、校准、留出，翻译、不同版本、裁剪图及近似段落必须同组。先冻结来源清单、问题、标签、指标脚本、提示词、模型映射与本版门槛摘要，再执行候选。留出原文可以正常索引，但答案/标签不得进入索引或提示词。两名互不查看对方结论的审阅者依据原文标注，再解决分歧；若都是助手，明确标为助手双审，不称独立人工金标准。模型裁判不可单独决定通过；不足或未解决的标注进入阻塞清单，不能事后删难例。

留出集至少来自 20 份未参与调参的文档：200 个完整标注片段、1,000 个实体提及及至少 300 个作用域实体、500 条有证据关系；设备/组织/材料/工艺/指标/技术概念各至少 50 个提及、30 个作用域实体。另有 100 组消歧题（不同实例同名 50、明确别名 50）及 50 条限定语反例（否定、条件、数量、方向、可能性各至少十条）。图片至少 80 张有效原图、300 个标注区域，并另有 40 张目录、空白、装饰等负例；每类区域（对象、文字标签）至少 100 个。问题固定为 240 题：单跳 80、多跳 60、图文联合 60、无答案 40，题目覆盖六类业务主题，每主题至少 20 题。多跳题至少需要两处证据且没有单一片段直接回答完整问题；图文题必须确实需要图片，不把文字可独立回答的题充数。留出指未参与本项目本轮调参，不声称公开资料从未进入模型预训练。

抽取质量分支只输入上述已完整标注的片段、图片和反例，计入这个封闭来源集合内的全部预测，不把语料库其余未标注预测当误报或悄悄计为正确。检索、界面和容量分支使用完整语料库，二者分开报告。若增加抽取计分来源，先完整标注并升数据版本，不在看到输出后挑选有利片段。

检索原子证据 ID 在运行前冻结为具体版本的片段、表格区域或图片区域；文本单元最多 1,200 个 Unicode 字符，前五项合计文本最多 6,000 字符、图片证据最多两项。不得运行后合并片段或整个文件以提高命中。同正文或相同图片区域只占一个排名位置，保留全部授权来源链接；不同范围的实例不能因为同名去重。每题至少一个充分证据集合必须能装入五项和上述预算，超预算题在冻结前另列压力集，不混入通过率。两种融合分支使用完全相同的原子候选集合及准入过滤；查询之外不提供标准答案。

| 维度 | 本版通过条件 | 分母与错误判定 |
|---|---|---|
| 实体 | 提及与作用域实体两套精确率都至少 95%、召回率都至少 90%；各类型分别不低于 90% / 80% | 提及按文件版本/跨度/类型匹配，实体按规范名/类型/实例作用域匹配，所有准入节点及关系端点纳入；合法多来源合并不算重复，额外重复节点计误报，漏抽/异常计未命中。原始候选另报，不能只审精修展示样本 |
| 关系 | 准入关系精确率至少 95%，召回率至少 85%；每个业务主题不低于 90% / 75% | 主体、客体、方向、谓词、条件/否定/数量和证据共同正确才匹配，采用预登记一对一匹配；错误关系和多余重复关系计误报，缺少证据的歧义关系不得准入 |
| 关键语义错误 | 在 100 组消歧题和 50 条限定语反例中零错误准入；50 组别名至少正确合并 45 组，限定语关系完整召回至少 80% | 不同设备实例误合并、文献编号变版本、否定变肯定、条件/数量被强化等不能用平均分抵消，也不能靠全部拒绝取巧；保留原始输出与来源 |
| 图片定位 | 对象框、文字框各自精确率至少 90%、召回率至少 85%；正确匹配框的平均区域交并比至少 0.65 | 标签/类型一致且区域交并比至少 0.50 才能一对一匹配；漏框算漏检，多框/错框算误报，全页框或文字框不能替代设备框；不事后转换坐标来抬分 |

精确率 = 正确预测数 / 全部准入预测数，召回率 = 正确匹配数 / 全部标注目标数；分母为零不记满分。漏抽、错误、超时都计入对应任务分母；资源缺失、索引整体失败、标签不足或账本无法对齐使整轮标为未完成，不补造结果。安全或关键语义违规任一出现即阻断。必须报告分子/分母和各切片；统计区间方法在执行前登记，文档指标按家族聚类，跨文档题把相关家族组成连通分量后配对重采样。有效簇至少 20 且非退化时用 10,000 次簇重采样报告 95% 区间，否则明确“不足以可靠估计区间”；全零错误的退化区间不得写成零风险证明。重复测量不当独立样本，不宣称本集足以检测任意小幅退步。

以上是工程目标冻结，**实际数据集、标注与测试结果尚未生成或验收**。已知错误可以用于修复，但留出结果一旦被用于调参，该批转为回归集，必须增加新的未见留出数据再验收。确需修正标注或门槛时升版本、保留旧结果并全量复测，禁止为过关事后降线。

### 7.5 消融、记忆与安全验收 v1

- 真实产品消融使用同一 1007 回答模型、同一题目/可访问资料和参数，全部输入（系统/工具声明、历史和证据）上限固定 8,192 token，输出上限 512 token。取第 7.2 节 240 题，再增加 40 条长对话任务，每条至少 20 轮，原始历史达到共同输入预算以触发真实上下文管理，并有两次明确事实更新、五个预登记探针（至少两条追问被更新事实并含旧值干扰）。没有 1007 或其实际配置不支持此预算，批次标资源未满足，不偷换型号/预算。
- 长对话压缩专项固定两组：增强组至少产生一次可验证的真实压缩事件；基线关闭额外记忆、压缩、检索和子任务，使用原始同序历史，超预算时按冻结规则丢弃最早完整轮次，记录丢弃位置，不用另一摘要器。双方在同一个压缩后的下一问检查点计量。其他增强开关单独消融，底层权限与副作用防护始终开启。
- 200 个事实/约束探针正确率至少 95%；其中至少 80 个已更新事实探针，以全部这类探针为分母，输出已失效旧值的比例不超过 5%，未输出正确新值（包括超时/缺答）仍算正确率失败。清空、撤权和跨会话隔离各至少 20 个用例，零泄漏。记录压缩前后答案、来源、上下文长度和任务成功率，不只展示输入变短。
- 增强方案整体任务成功率不得低于同任务最简单 Agent，且多跳和图文任务仍须满足第 7.2 节绝对门槛。压缩收益专项对 40 个配对检查点分别计算 `1 - 增强输入token / 基线输入token`，这些配对比例的中位数至少 20%，事实正确率保持至少 95%；基线计量缺失/为零则该项未完成，不从分母删掉。全部供应商调用总量和成本仍分列。未达到节省目标标为该项未通过，不调整柱状图制造优势；总成本若增加必须如实显示。
- 安全集至少 200 个负例，覆盖文档、网页/邮件、图片 OCR、工具结果、缓存/记忆、审批/子任务六类入口，每类至少 20 例，另有 100 个正常业务对照。未授权数据读取、敏感泄漏、未批准副作用和伪造来源均为零；正常业务误拒率不超过 5%。只用合成敏感数据，不读取客户隐私；有限攻击集零失败不等于绝对安全。
- 同一冻结候选至少执行一次全量质量评测，并对预登记的 30 道跨主题问题追加两次重复运行，三轮完整报告，不选最好的一轮；重复运行任务成功率各至少 90%，无安全或关键语义错误。重复样本不扩大独立样本量，失败和超时不删除。持续集成缺少必需数据、线路或执行器覆盖时不得以跳过冒充全绿。

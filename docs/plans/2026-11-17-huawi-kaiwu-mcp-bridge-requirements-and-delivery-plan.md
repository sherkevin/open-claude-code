## 0. 结论先行

1. 当前 `1.2.1` 候选包已完成 D01 自动化修复、源码测试、竞态测试、静态检查、控制面合成测试、Go 漏洞扫描、CycloneDX 1.5 SBOM、双平台干净构建、包内哈希和 Linux 包级启动验证。`1.2.0` 已在 Windows 10 本地测试机完成安装、模拟 MCP 诊断、服务重启和卸载，但 `1.2.1` 尚未在 Windows 实机复测，客户目标 Windows Server 2019 也未验证，因此只能进入“本机诊断试装准备”，不能声明为已经接通开物平台。
2. 从开物平台到华微内网 MCP 的完整链路仍未闭环：云端接入码兑换、设备身份、来源登记、授权签发、中继、visitor、Edge、心跳、排空和撤销均没有完成真实联调。
3. 最新客户材料明确业务 MCP 由 Windows 上的 HwMain 承载。本项目的部署位置已经冻结：连接器安装在承载该业务 MCP 的 Windows Server 2019 Datacenter 候选机上，Linux OpenClaw 身份代理的历史回环入口不属于本次 Windows 连接器路径。
4. 华微的 `tools/call` 还要求动态身份和 HMAC 签名。只在 Edge 上附加固定 Bearer 不足以完成业务调用。建议在连接器本机增加最小权限认证代理，由它注入固定 Bearer 和每次请求重新生成的动态签名头；Edge 不持有客户上游凭据。
5. 采用 `source_id` 方案 A：连接器首次生成并持久化稳定来源编号，云端做幂等登记、冲突校验和上限控制。`1.2.1` 对同一上游地址重复导入时保持来源编号，并新增自动化回归防止显示名或重复导入导致编号和批准工具丢失。
6. 首个试用版本应限定为华微批准的只读工具，不允许任意命令、任意文件访问、`stdio` 命令执行或未经批准的业务写入。正式交付前仍需要 Windows Server 2019、整机重启、安全软件、代码签名、许可证和真实客户环境验收。
7. 开物用户到华微渠道用户的数据范围不能靠一个隐式共享身份解决。正式交付默认要求逐用户或逐组织映射；缺失、失效或撤销映射时必须拒绝调用。受控试装如果只能使用共享只读身份，必须由华微书面限定工具、字段、数据范围和期限。
8. 本机页面回环访问不等于管理员授权。连接器必须拒绝非回环监听，并通过 Windows 管理员权限或受 ACL 保护的本机管理通道授权高影响操作；当前“页面自动签发会话令牌”的实现不能作为安全认证方案。
9. 首个客户试装应先完成 Windows 销售只读查询这一条最小链路，再单独验收知识检索。未确认知识检索入口不能阻塞销售查询试装，也不能用销售查询试装冒充 C 段测试环境技术链路验收。
10. 授权链必须采用 MCP 常见的 OAuth 2.1 Resource Server 模型：平台管理员签发来源和助手授权，独立平台 IAM 基于真实用户会话签发内部主体断言，助手运行时通过 OAuth Token Exchange 换成逐请求的用户委托访问令牌 `A`，Edge 验签、校验持有者绑定并解析身份映射，再签发短期数据面上下文 `E`；连接器验签并匹配请求正文。静态共享 Bearer 不能作为正式多用户凭据。
11. MCP 默认拒绝必须覆盖上游到平台的响应方向，而不只是平台到上游的方法。未请求的服务器请求、跨请求 SSE、`sampling/*`、`elicitation/*`、`roots/list` 和未授权通知均不能透传。
12. `1.0.1` 的 A/B 原始证据缺失，只能保留“历史报告声称通过”。`1.2.0` 的 Windows 10 本地验收报告、摘要、截图、状态和缺陷说明已经进入证据目录，但系统不是客户目标 Windows Server 2019，且没有整机重启；现场发现 D01，并出现一次待确认的 D02。`1.2.1` 已修复 D01 并完成自动化回归，Windows 实机复测仍待执行。`5 秒内返回 503` 尚未验证，只能作为待测门槛。
13. G7b 的名称必须是“C 段测试环境技术链路验收”，不能使用“生产完整 C 段已闭环”的表述。生产端到端闭环只能在正式交付评审和单独生产批准后成立。

### 0.1 第三轮审核后的唯一执行口径

1. 用户委托令牌统一写作 `AT_user`。本文件在令牌语境中单独出现的 `A` 只作为历史简称，始终表示短期用户委托令牌，绝不表示静态平台 Bearer。平台配置不得包含静态用户凭据；连接器导出器已改为不输出 `Authorization`，且传入静态访问令牌时直接拒绝。在平台 OAuth-aware 运行时完成前，导出 JSON 只能用于核对 Edge 地址，不能用于 G7 或任何“端到端已通”声明。
2. 来源级只读工具允许列表的唯一批准人是客户本机管理员。平台管理员只能在客户批准集合内签发更窄 grant，身份映射再取更窄交集，任何平台角色都不能扩大客户允许范围。
3. G7a/G7b 必须使用客户提供的合成或脱敏测试数据包，包含固定查询、预期字段或结果、禁止返回字段、空结果和失败案例。HTTP 200、空结果或任意内容不能作为通过依据。
4. 身份映射必须有可操作的生命周期入口：创建、批量导入或组织同步、修改、失效、撤销、版本递增和审计。不得要求实施人员手工改数据库。
5. HWC-060 分为两个独立关卡：G7a 前只验证合成或脱敏身份的默认拒绝、映射生命周期、工具交集、撤销和审计；真实字段、行级和业务范围权限只能在客户单独批准的正式数据验收中关闭。
6. 受控试装与正式分发使用两套关卡。普通 P1 可以由客户书面接受风险；HWC-028、HWC-059 和 HWC-061 是发布安全门禁，不能由普通 P1 豁免。
7. 受控试装 SBOM 固定为 CycloneDX 1.5 JSON，至少包含组件名称、版本、包 URL、哈希、直接或传递关系、许可证和缺失许可证说明。试装前必须执行 SCA/CVE、恶意软件和秘密扫描；未关闭 Critical，或 High 没有批准人的包不得进入 G7a。
8. 客户目标 Windows Server 2019 用于最终环境验收，我方 Windows Server 2019 虚拟机只用于合成回归，不能互相替代。
9. 客户目标 Windows Server 2019 已确认具备图形化客户端桌面。现场验收优先使用管理员图形界面完成安装、Windows 服务管理、浏览器访问本机配置页面和人工复测；静默安装与命令行诊断仍保留，用于自动化、远程运维和故障恢复，但不再作为“客户服务器没有桌面”的前提假设。
10. 客户固定 Bearer `B`、HMAC 密钥 `S` 和渠道身份由客户本机管理员通过受控本机步骤导入；不得经过平台页面、导出 JSON、普通文档、聊天或日志。
11. 本机诊断试用、平台 C 段受控试装和正式交付是三个不同阶段。本机诊断试用可以先行，但不能宣称开物平台已经能够调用客户内网工具。

### 0.2 第四轮审核收敛决定

本轮不再重复扩展文档体系，只冻结以下可执行口径：

1. 平台配置只保留 Edge URL 和公开集成标识；`A` 只表示短期用户委托令牌。静态 Bearer、设备令牌和客户上游 `B` 都不得进入平台导出 JSON。
2. 来源级只读工具允许列表由客户本机管理员批准。平台管理员只能在客户批准集合内签发更窄 grant；身份映射再取交集，任何平台角色都不能扩大客户允许范围。
3. G7a/G7b 的通过条件是“固定查询得到预期字段或业务结果”，不是 HTTP 200。客户测试数据包、禁止返回字段、负向案例和清理责任未提供时，只能准备，不得执行或宣称业务验收通过。
4. 身份映射通过受控管理员接口完成创建、批量导入或组织同步、修改、失效、撤销、版本递增和审计；实施人员不得手工改数据库。映射版本是 `A`、`E`、连接器会话和审计的必需字段。
5. G7a 前只关闭合成或脱敏数据上的身份拒绝、工具交集、撤销和审计。真实字段、行级和业务范围权限属于单独的正式数据验收，不能用合成测试替代。
6. 受控试装和正式分发使用独立门禁。普通 P1 可以由客户书面接受风险；HWC-028、HWC-059 和 HWC-061 是发布安全门禁，不能被普通 P1 豁免。
7. 监控和容量必须使用 HWC-047、HWC-045 和 HWC-058 已冻结的阈值、观察窗口、请求混合和统计方法；HWC-026 的正常停止、进程强杀、网络黑洞和 relay 故障四项当前均未验证。
8. 客户目标 Windows Server 2019 用于 HWC-017、G5 和 G7；我方 Windows Server 2019 虚拟机只用于合成回归，不能互相替代。客户本机管理员通过受控本机步骤导入 `B`、`S` 和渠道身份，秘密不经过平台页面、导出 JSON、普通文档、聊天或日志。
9. 当前允许先行的是“本机诊断试用包”。只有通过构建、单元/竞态测试、包哈希、卸载说明和明确的未闭环提示后才能交给客户试用；它不代表开物平台已经能够调用客户内网 MCP。
10. 云端控制面的开发结论必须由代码、自动化测试和证据支撑。默认关闭、管理员与设备凭据分离、设备签名、来源元数据登记、心跳、排空和撤销每项通过后，只把该项从“未实现”升级为“合成已验证”；relay、visitor、Edge、Token Exchange 和 Windows 实机未完成前，整体状态仍不得写成“已闭环”。
11. 部署位置由我方决定，不由客户选择。本项目的连接器固定安装在承载 HwMain 业务模型上下文协议服务的 Windows Server 2019 Datacenter 候选机上；Linux OpenClaw 身份代理的历史回环入口不属于 Windows 连接器的部署路径。

## 1. 背景与业务问题

开物工作台已经部署在腾讯云，前端入口为 `https://flintw.com/projects/kaiwu`。华微希望开物智能体能够调用其内网已有业务能力，而不是再单独建设一个孤立聊天机器人。

华微现有 MCP 位于内网，开物平台位于公网，不能直接访问客户内网地址。正确方案不是让客户开放公网入站端口，也不是要求客户建设 VPN，而是在客户内网部署一个连接器：

1. 连接器从客户内网主动向开物云端建立出站加密长连接。
2. 开物智能体通过平台 Edge 发起已授权的 MCP 请求。
3. 请求沿已建立的长连接到达客户内网连接器。
4. 连接器只调用已登记、已允许的本机 MCP 工具。
5. 结果原路返回平台，并保留 JSON、SSE、会话信息和可审计的错误语义。

本计划要解决的核心问题不是“能不能从公网访问客户电脑”，而是“平台能否在不暴露客户内网的前提下，只调用客户明确授权的能力，并且每个请求都能追溯、限权、停止和撤销”。

## 2. 目标、范围与非目标

### 2.1 目标

1. 华微 Windows Server 2019 上可安装、启动、升级、重启恢复和卸载连接器。
2. 连接器只监听本机回环管理界面，不开放任何公网或局域网入站端口。
3. 连接器通过一次性接入码完成设备绑定，重启后身份保留。
4. 连接器登记一个或多个只读 MCP 来源，云端和本机对来源身份保持一致。
5. 平台管理员能够从开物工作台导入只包含 Edge 地址、`integration_id` 和 Token Exchange 绑定的 MCP 配置；平台配置不包含静态 Bearer，`A` 只能由已认证用户会话经 RFC 8693 Token Exchange 临时获取。
6. Edge 能验证授权 A、检查来源和工具范围，并通过中继把请求送到对应连接器。
7. 连接器本机认证代理能向上游 MCP 注入固定 Bearer、动态签名和协议会话信息。
8. 停连接器时平台快速返回 `503 SOURCE_UNAVAILABLE`，恢复后自动可用；撤销后不能重新建立连接。
9. 全程不向平台、导出 JSON、日志或调用方暴露客户上游凭据、HMAC 密钥或任意内网文件。
10. 在没有真实客户数据时，可以通过模拟控制面、模拟 MCP、合成业务数据和故障注入完成大部分验证。

### 2.2 本计划包含

- 开物云端连接器控制面最小接口。
- 一次性接入码、设备身份、期望状态、通道密钥、心跳、排空、恢复和撤销。
- 连接器本机界面、Windows 服务、配置导入、来源登记、诊断和状态恢复。
- 客户动态签名认证代理。
- frpc、中继、visitor、Edge 和平台授权配置。
- JSON、SSE、会话头、超时、取消和错误映射。
- Windows Server 2019 验收、安装包安全、升级回滚和许可证。
- 合成数据验收、真实客户环境受控试装和正式交付关卡。

### 2.3 本计划不包含

1. 不替换华微 HwMain 的业务逻辑、数据库或现有 MCP 工具实现。
2. 不在首个试用版本中开放未经批准的业务写操作。
3. 不把连接器做成可以读取整台 Windows 文件、执行任意命令或充当通用 SOCKS/HTTP 代理的远程控制程序。
4. 不在首版启用 `stdio` MCP；如客户确实使用 `stdio`，另行评估本地条件适配器。
5. 不让客户开放公网入站端口或安装 VPN。
6. 生产和客户凭据操作仍须单独批准；本计划允许在独立开发、合成测试和本地工作区中实施与验证。
7. 不把“开物可以通过连接器访问业务 MCP”扩大表述为“已经完成 OpenClaw 全面替换”。OpenClaw 替换属于独立的迁移项目，需要单独的业务、入口和兼容性设计。

## 3. 术语和信任边界

| 名称 | 定义 | 是否可见于平台导出 | 是否可见于日志 |
| --- | --- | --- | --- |
| 设备身份 `D` | 连接器调用开物控制面的设备级令牌 | 否 | 否 |
| 平台集成配置 | 平台助手与 Edge 来源绑定的公开配置，包含 Edge URL、`integration_id` 和 Token Exchange 绑定 | 可以 | 可以 |
| 上游凭据 `B` | 华微 MCP 使用的固定 Bearer | 否，只留在客户连接器本机 | 否 |
| 签名密钥 `S` | 生成 `tools/call` HMAC 的服务身份密钥 | 否，只留在客户连接器本机 | 否 |
| 通道密钥 `T` | frpc STCP 的逐来源秘密 | 否 | 否 |
| 平台管理员令牌 `admin_token` | 开物管理员签发 grant、撤销、排空和查看来源的专用凭据 | 否 | 否 |
| `integration_id` | 平台助手与一个 Edge 来源绑定的公开集成标识 | 可以 | 可以 |
| 平台主体断言 `U` | 开物可信运行时为 OAuth Token Exchange 提供的短期主体断言 | 否，不经 Edge | 只能在脱敏审计中记录断言编号 |
| 用户委托访问令牌 `A` | OAuth Token Exchange 为一次平台用户/组织调用签发的短期限访问令牌 | 仅通过 `Authorization: Bearer` 发送给 Edge | 只能记录 `jti` 和脱敏主体 |
| Edge 数据面上下文 `E` | Edge 验签 A 并解析身份映射后签发的一次性请求上下文 | 否 | 只能记录上下文编号和策略摘要 |
| `source_id` | 一个已登记 MCP 来源的稳定标识 | 出现在 Edge URL 中 | 可以 |
| `grant_id` | 一次平台授权的稳定标识 | 可以出现在平台管理记录中 | 可以 |
| `trace_id` | 跨控制面、Edge、连接器和上游的追踪标识 | 不作为业务能力暴露 | 可以 |

关键边界：

- `admin_token`、`A`、`B`、`S`、`D`、`T`、`U`、`E` 不能相互替代。
- `U` 只在平台内部的 OAuth Token Exchange 中使用，不能作为 MCP 数据面自定义头发给 Edge；`A` 是 Edge 唯一接受的 OAuth Access Token，不能当作华微上游 MCP 的凭据。
- `A` 必须同时绑定用户主体、助手、来源、工具范围、资源和撤销状态，并通过 DPoP 或 mTLS 绑定调用方；只绑定助手或来源的静态 Bearer 不满足正式多用户授权。
- `E` 只由 Edge 私钥签发，连接器使用公钥验证；它不能由模型、浏览器、平台普通调用方或连接器自行构造。
- `B` 和 `S` 只能保存在客户 Windows 主机，不能上传到腾讯云，也不能写入平台导出 JSON。
- 设备身份 `D` 不能读取任意租户来源，不能用于业务工具调用。
- 连接器只允许访问已登记来源的允许列表工具，不提供任意目标地址转发能力。

## 4. 目标架构

### 4.1 逻辑链路

```text
开物智能体 / 工作台
        |
        |  可信运行时用 U 和助手凭据执行 OAuth Token Exchange
        |  Authorization: Bearer <A_user>
        v
腾讯云开物 MCP Edge
        |
        |  验证 A、grant、subject mapping 和 tool allowlist
        |  签发一次性 E，绑定方法、source、subject、session 和正文摘要
        |  去掉 A，不附加 B
        v
腾讯云 relay + visitor
        ^
        |  frpc STCP 出站长连接
        |
华微 Windows Server
  kaiwu-connector
    - 本机管理界面 127.0.0.1:17872
    - 管理员专用命名管道（高影响操作）
    - 每来源认证入口（仅接受有效 E）
    - 重建并限制 MCP 请求，注入 B、动态签名 S、协议头
        |
        v
华微 HwMain HTTP MCP
```

### 4.2 控制面与数据面分离

| 面 | 方向 | 内容 |
| --- | --- | --- |
| 控制面 | 连接器主动访问开物 | 接入码兑换、期望状态、通道密钥、心跳、排空、恢复、撤销 |
| 数据面 | 开物 Edge 经中继访问连接器 | MCP `initialize`、`tools/list`、`tools/call`、通知、SSE 和会话头 |

控制面失败不能让业务凭据出现在平台；数据面失败不能改变设备身份或伪造业务结果。

控制面还必须拆分两种调用主体：

| 接口类别 | 允许凭据 | 禁止凭据 |
| --- | --- | --- |
| 连接器设备接口：`desired-state`、`transport-secrets`、`heartbeat`、来源登记 | 设备令牌 `D` + 设备私钥签名 | 平台管理员令牌、A、B、S |
| 平台管理接口：接入码生成、grant 签发、平台配置、drain/resume/revoke、来源审批 | 平台管理员令牌 `admin_token` | 设备令牌 D、A、B、S |

设备令牌和管理员令牌使用不同签发器、不同 audience、不同密钥和不同审计主体。不能用“除 redeem 以外都校验设备令牌”的单一口径覆盖平台管理接口。

### 4.3 已冻结的部署位置和入口边界

最新客户说明指出：

- HwMain 业务 MCP 进程位于 Windows Server 2019 Datacenter，64 位，Build `17763.9020`。
- 候选销售入口为 `https://svr39.bjhwsj.com/SysDevCore/mcp/sales_test`。

本项目已经由我方决定：连接器固定安装在上面的 Windows Server 2019 Datacenter 候选机，与 HwMain 业务 MCP 同机部署。安装位置、安装方式和运维路径由我方给出，客户按我方要求执行，不在 Windows 与 Linux 之间二选一。

客户目标 Windows Server 2019 已确认具备图形化客户端桌面。因此现场验收默认使用管理员图形界面完成安装包解压、PowerShell 安装、Windows 服务查看、浏览器访问 `http://127.0.0.1:17872/` 和人工复测。静默安装、命令行诊断和无人值守恢复仍是需要保留的兼容能力，但不能再用“没有桌面”作为降低图形化验收覆盖的理由。

当前仍需确认的是各个具体业务来源从这台 Windows 候选机是否可达，而不是重新选择安装机器：

| 情况 | 本项目做法 | 不允许的做法 |
| --- | --- | --- |
| 销售 MCP 由 Windows HwMain/IIS 承载 | 连接器安装在该 Windows 候选机，并通过本机监听端口与 HwMain HTTP MCP 通信 | 把 Linux 的 `127.0.0.1:18790` 当成 Windows 本机地址 |
| 后续知识检索 MCP 从该 Windows 候选机可达 | 继续复用同一个 Windows 连接器，按来源分别登记和授权 | 因为存在一个回环入口就改变整体安装位置 |
| 某个来源只允许 Linux OpenClaw 主机本机访问 | 该来源不进入本次 Windows 连接器交付范围；如确需接入，另行提供受控内网转发或独立部署 | 要求客户开放回环地址到局域网或公网，或让 Windows 连接器成为任意地址转发器 |

连接器不能通过修改 Windows 连接器配置来“远程访问另一个主机的 127.0.0.1”。如果后续业务来源确实只存在于 Linux 本机，必须单独登记和评估，但不能因此推翻本项目已经冻结的 Windows 安装方案。

### 7.2 华微动态签名

依据已收到的《MCP 调用与认证说明》，签名规则如下：

```text
appid=<appid>&channel=<channel>&userid=<userid>&requestId=<uuid>&timestamp=<unix-seconds>
```

实现要求：

1. 使用 UTF-8 原文和 HMAC-SHA256。
2. 结果是小写十六进制。
3. 字段顺序、字段大小写和参数名必须完全一致。
4. 正文不参与签名，不做 URL 编码。
5. `requestId` 每次调用和每次重试都必须新生成。
6. `timestamp` 每次调用和每次重试都必须重新取样。
7. `sign` 每次调用和每次重试都必须重新计算。
8. `initialize`、`notifications/initialized`、`tools/list`、`ping` 使用固定 Bearer；`tools/call` 同时需要固定 Bearer 和六项动态头。
9. 签名密钥和渠道身份只保存在 Windows 本机，平台、导出配置和日志不得持有或打印。
10. 只对允许列表中的工具执行动态签名；未知工具应在本地直接拒绝，不把请求转发给华微。
11. 华微当前签名原文不覆盖工具名和正文，因此六项 HMAC 不能被描述为“完整请求防篡改”。本方案依赖 HTTPS、本机秘密保护、E 的正文摘要和工具策略限制降低风险。
12. 连接器不得对网络结果不确定的 `tools/call` 自动重试；是否重试由上层明确决定并产生新的审计记录。
13. 若华微不能确认 `requestId` 服务端唯一性和时间窗，相关残余风险必须进入 claim ledger，不能宣称“已防住上游重放”。

### 7.3 认证代理的架构决策

本计划推荐以下决策：

```text
独立平台 IAM
  -> U（基于真实用户会话的内部主体断言）
平台助手运行时
  -> U + 助手客户端身份
  -> OAuth Token Exchange
  -> A（用户/助手/来源/grant/resource）
  -> Edge 验签 A、查撤销、解析 mapping
  -> E（一次性数据面上下文）
  -> frpc STCP
  -> kaiwu-connector 每来源认证入口
  -> 验证 E、重建上游请求、注入 B/S
  -> HwMain HTTP MCP
```

理由：

- `B` 和 `S` 必须留在客户主机。
- Edge 如果没有华微动态签名能力，无法直接构造合法 `tools/call`。
- 让每个平台模型或每个 Edge 节点持有客户密钥，会扩大泄密面。
- 本机认证代理可以统一处理固定 Bearer、动态签名、协议头和工具允许列表。
- `U` 只在平台内部完成 Token Exchange，不能作为自定义头绕到 Edge；A 同时绑定最终主体、助手、来源、工具和资源。
- `E` 将真实主体、工具、请求正文和 MCP 会话绑定到一次隧道请求，低权限本机进程即使连接本机代理也不能伪造平台调用。

需要更新旧契约的点：

- 旧文档中的“Edge 附加客户上游 B”改为“连接器本机认证代理附加 B 和 S”。
- Edge 只验证 A 并去掉 A，不能持有 B 或 S。
- frpc 的代理目标从“直接转发客户 MCP 原始端口”改为“转发连接器本机认证代理端口”。
- 每个来源必须有独立的本机认证入口或不可伪造的来源路由；不能用一个无认证回环端口承接所有来源。
- 连接器必须以自己的会话编号隔离不同平台主体；上游 `Mcp-Session-Id` 只在本机保存，不能直接暴露或跨主体复用。

### 7.4 身份与数据范围映射

当前客户说明明确“当前用户、组织和可见数据范围由华微根据渠道身份确定”，因此 `channel` 和 `userid` 不是可以随意写死的常量。

映射记录至少包含：

| 字段 | 说明 |
| --- | --- |
| `tenant_id` | 开物租户 |
| `platform_subject` | 开物用户、服务账户或组织主体 |
| `mapping_id` | 可审计的映射编号 |
| `source_id` | 该映射允许调用的来源 |
| `hw_appid` | 华微 `appid` |
| `hw_channel` | 华微渠道编码 |
| `hw_userid` | 华微已映射的渠道用户 |
| `tool_allowlist` | 与来源 allowlist 的交集，不能扩大权限 |
| `data_scope` | 由华微确认的字段、组织、业务范围；说明约束由谁验证，不能只留自由文本 |
| `data_scope_evidence` | 华微测试记录、工具级限制或接口行为证据 |
| `not_before` / `expires_at` | 生效和失效时间 |
| `revoked_at` | 撤销时间 |

执行规则：

1. 独立平台 IAM 在每次调用前基于已认证用户会话生成内部主体断言 U。U 使用 EdDSA，包含 `iss`、`aud=KAIWU_TOKEN_SERVICE`、`tenant_id`、`source_id`、`assistant_id`、`platform_subject`、`session_id`、认证时间 `auth_time`、`iat`、`exp<=30s`、一次性 `jti`；助手运行时只能请求当前会话的 U，不能指定或覆盖 `sub`、tenant、助手身份或权限。U 私钥只存在于平台 IAM，模型、普通前端和助手业务进程不接触私钥或明文身份。
2. 助手运行时使用 mTLS 或 `private_key_jwt` 认证，携带 U 和 `resource=<Edge source URL>` 调用 RFC 8693 Token Exchange。令牌服务验证助手 grant、用户主体和资源，返回短期 A；A 的 `sub=platform_subject`、`act=assistant_id`，有效期不超过 60 秒。
3. MCP 请求只使用 `Authorization: Bearer A`，并通过 DPoP proof 或 mTLS 证明调用方持有绑定密钥。Edge 作为 OAuth 2.1 Resource Server 验证签名、issuer、audience/resource、`sub`、`act`、tenant、source、grant 生命周期、一次性 `jti`、持有者绑定、在线撤销状态和工具 allowlist；不接受 `X-Kaiwu-Subject` 等自定义身份头。
4. Edge 解析 `platform_subject -> mapping_id`，确认映射未过期、未撤销且工具在来源、grant、mapping 三层交集内。没有映射、主体禁用、组织切换、映射版本过期或交集为空时一律拒绝，不回退共享身份。
5. Edge 生成 E，将 A 的主体和策略结果固化为短期数据面上下文。连接器只信任 E，不接受客户端直接传入的 `appid`、`channel`、`userid`、mapping、工具范围或任何身份头。
6. 连接器验证 E 后生成 `appid`、`channel`、`userid` 签名头，不允许模型或浏览器直接提供这些头。`appid` 也必须来自映射，不能只使用共享 appid。
7. 正式交付默认逐用户或逐组织映射。华微负责按映射身份执行字段、行级和业务范围权限，并提供测试证据；开物不声称自行完成华微字段级权限。
8. 受控试装如只能使用共享只读身份，只允许访问客户批准的合成或脱敏测试数据，且必须保存华微批准的工具、数据范围、证据和截止日期；真实业务数据不得使用共享身份，不能仅靠书面声明替代运行时隔离。
9. 映射撤销和用户禁用要立即影响新调用；已开始的请求按工具读取属性、数据敏感级别和排空策略处理。Edge 撤销检查不可用时对新调用失败关闭。
10. 审计记录保存 `mapping_id`、`mapping_version`、`policy_hash` 和脱敏主体标识，但不保存 HMAC 密钥、U/A 原文或客户完整身份字段。

### 7.5 本机目标、MCP 方法和请求头默认拒绝

**目标固定**

- 客户管理员在本机导入并确认上游协议、主机、端口和路径后，形成不可由云端覆盖的来源目标。
- 本机保存规范化目标、首次解析的允许 IP 集、TLS `serverName`、上游 `Host`、路径和查询策略，并计算 `target_binding_sha256`。
- 云端 `desired-state` 和 `transport-secrets` 只能引用 `source_id`、下发通道材料和授权状态。
- 云端目标与本地目标不一致时，连接器拒绝整个期望状态，进入 `DEGRADED_RELAY`，不静默切换。
- 禁止自动跟随重定向；连接前校验解析地址，变化、DNS rebinding、IPv4/IPv6 超集或解析到未批准地址时拒绝。
- 每个来源使用独立的认证入口和固定上游路径。入口路径固定为 `/mcp`，目标路径、查询串、Host 和 SNI 由本机持久化配置重建，不能透传原始路径或头。

**MCP 方法**

首版只允许：

```text
initialize
notifications/initialized
notifications/cancelled
ping
tools/list
tools/call
```

其他方法返回 `403 POLICY_DENIED`。`tools/list` 只返回“来源允许列表、grant 允许列表和身份映射允许列表”的交集；空交集拒绝。连接器重新生成过滤后的工具目录和分页游标，不能把上游游标直接透传给平台。

上游到平台只允许：

- 与当前在途请求 ID 匹配的 JSON-RPC 响应。
- 与当前在途请求 `progressToken` 匹配的 `notifications/progress`。
- 客户端主动发送且该请求仍在途的取消通知。

上游发起的 `sampling/*`、`elicitation/*`、`roots/list`、未请求的响应、跨请求 SSE、未知通知和批量数组全部拒绝，不能让服务器反向驱动平台模型或工具。

**会话**

- 连接器作为 MCP 会话边界，向平台返回不可预测的不透明会话编号；上游会话编号只保存在本机映射中。
- `initialize` 的 E 使用平台会话关联编号，不携带尚未建立的上游会话；连接器成功后生成新的 MCP 会话。后续请求的 E `session_id` 必须等于该连接器会话编号。
- 会话记录绑定 tenant、subject、mapping、grant、source、tool 交集、协议版本和过期时间。
- 客户端必须同时提供有效会话编号和匹配的 E；跨主体、跨来源、跨 grant、撤销后或过期复用返回 `403 POLICY_DENIED`。

**请求头**

- 宿主导入首版只接受 `Authorization` 作为静态认证头。
- 代理先删除入口请求中的认证、签名、协议和转发头，再由受信任代码最后写入。
- 动态签名头不能来自平台、Edge、浏览器或导入 JSON。
- 头名称按 HTTP 规则规范化后去重；拒绝重复、保留头、请求走私组合和未白名单头。
- `Host`、`Content-Length` 和 `Transfer-Encoding` 从请求对象单独校验，不能只遍历普通头表。
- 上游响应中的 `Location`、`Set-Cookie`、`WWW-Authenticate`、代理响应头和诊断正文默认不返回平台。

### 7.6 传输安全与错误脱敏

1. 控制面、Edge 和 relay 的生产流量必须使用 HTTPS/TLS。
2. 带客户 Bearer 或 HMAC 密钥的上游默认必须使用 HTTPS；只有回环合成测试或客户书面批准的隔离链路可以使用明文 HTTP。
3. 校验证书链和主机名，不提供关闭校验的生产开关。
4. 不自动跟随 HTTP 重定向。
5. 云端和上游连接使用显式代理策略，生产默认不继承系统环境代理。
6. 对用户、日志和审计只输出稳定错误码、状态摘要、处理建议和 `trace_id`。
7. 上游错误正文只记录长度、哈希或固定分类，不记录原始正文、认证响应头、内部路径或客户业务数据。
8. 所有输出经过同一套敏感字段过滤器，测试必须注入带秘密和业务数据的错误正文、SSE 事件和 `last_error`。
9. A、U 和 E 使用 EdDSA 紧凑 JWS 与 `kid`；U 只由独立平台 IAM 基于真实用户会话签发，助手运行时只能请求当前会话断言，A 由平台 OAuth 授权服务签发给 Edge，E 由 Edge 私钥签发；三者 audience 和密钥互不复用。
10. 设备控制请求使用设备私钥签名，签名覆盖 HTTP 方法、规范化路径、正文 SHA-256、时间戳和一次性 `jti`；时间偏差默认不超过 60 秒。
11. Edge 每次新请求在线检查 grant 撤销状态；撤销服务不可用时失败关闭。排空或撤销只拒绝新调用，并明确在途调用的完成/终止规则。
12. 401 只用于凭据无效或过期；403 用于主体、映射、来源、工具或撤销越权；429 用于明确的调用额度（grant quota）限流；413 用于正文超限；502 用于上游认证或协议失败；503 用于来源、通道或连接器不可用；504 用于工具超时。响应不得泄漏内部路径或秘密。
13. 平台、Edge 和连接器不得信任 query、Cookie、`X-Forwarded-User`、普通自定义主体头或模型生成的主体字段。
14. 平台配置和设备秘密响应必须带 `Cache-Control: no-store`，并禁止被 CDN、代理或浏览器持久缓存。
15. Edge 发布 RFC 9728 Protected Resource Metadata，并在需要认证的 `401` 响应中返回指向该 metadata 的 `WWW-Authenticate`；只接受为当前 Edge source resource 签发的 A，拒绝其他服务或来源的 token passthrough。
16. Token Exchange 校验助手客户端身份、U 的 issuer/audience/一次性 `jti`、`subject_token_type`、`requested_token_type` 和 `resource`；错误客户端、过期 U、错误 resource 和重放全部拒绝。

### 7.8 秘密存储和密钥轮换

| 秘密 | 存放位置 | 保护措施 | 运行时处理 |
| --- | --- | --- | --- |
| 设备私钥 | Windows CNG 非导出密钥或 DPAPI-NG 加密文件 | 服务 SID + 机器绑定；ACL 仅服务和管理员 | 私钥不进入日志、导出 JSON 或普通备份；公钥可上报 |
| `B` 固定 Bearer | 连接器本机 | DPAPI-NG 保护描述符绑定服务 SID，ACL 最小权限 | 仅在构造上游请求时解密，不在 UI 回显完整值 |
| `S` HMAC 密钥 | 连接器本机 | DPAPI-NG；版本和 `kid` 可审计 | 每次签名时使用，禁止缓存到日志或错误信息 |
| `T` relay/STCP 密钥 | 连接器本机 | DPAPI-NG；控制面只下发加密后的通道材料 | 启动时解密生成 frpc 临时配置；文件 ACL 只允许服务 SID 和管理员 |
| Edge context 私钥 | Edge 服务 | HSM、KMS 或受控密钥存储 | 连接器只持有公钥，私钥不下发 |
| OAuth 访问令牌签名私钥 | OAuth 授权服务 | HSM 或受控密钥存储 | Edge 只持有公钥或使用 OIDC/JWKS 缓存 |
| U 签名私钥 | 独立平台 IAM | KMS 或受控密钥存储 | 助手运行时只能请求当前会话主体断言；模型和普通前端不可读取 |

frpc 不接受把秘密直接放在命令行参数中。临时 `frpc.toml` 只在服务运行期间存在于受 ACL 保护的临时目录，正常退出立即删除；异常退出后下一次启动先清理。物理访问、内存转储和 SSD 删除语义不能由应用层完全消除，必须作为残余风险记录。

轮换规则：

1. 设备、Edge context、relay 和 grant 密钥均携带 `kid`，支持双密钥重叠。
2. 新密钥发布后，旧密钥只保留完成在途请求所需的短窗口，默认不超过 15 分钟。
3. 撤销通过撤销版本和 `jti`/墓碑实现；连接器在云端不可达时仍能拒绝本地已撤销身份。
4. 轮换和撤销都有审计事件、操作人、时间、旧/新 `kid` 和结果，不记录密钥明文。

## 9. 无真实客户数据验证方案

### 9.1 测试组件

1. 模拟控制面：实现设备路由、管理员路由、撤销版本、接入码、设备公钥签名和一次性 `jti`，验证两类凭据不能混用。
2. 模拟平台助手运行时和 Edge：生成 A、U、E，执行在线撤销检查、身份映射和工具的三种交集。
3. 模拟 Windows 连接器：使用 Go 测试、提权 helper 和可执行包，在本机与隔离测试主机运行。
4. 模拟正常 MCP：提供 `manual_search`、`test_sales_order_grid_query` 等只读工具，返回合成库存、订单和客访日志。
5. 模拟华微签名校验器：实现精确字符串顺序、HMAC-SHA256、小写十六进制、时钟窗口和 requestId 唯一性检查；无法确认华微侧时间窗和防重放时，不得把相关测试标记为安全能力已验证。
6. 模拟身份映射器：生成有效、过期、撤销、跨租户、跨组织、缺失映射和共享身份越界用例，并验证不允许回退共享身份。
7. 模拟恶意控制面：下发未知字段、被篡改的 `local_host/local_port`、错误 source、过期 grant、越权工具和撤销回滚。
8. 模拟恶意上游：主动发送 `sampling/*`、`elicitation/*`、`roots/list`、未请求响应、跨请求 SSE、超大 JSON 和重复/编码变体方法。
9. 模拟 relay/visitor/Edge：使用隔离端口、测试 CA，验证 TLS、STCP、403/503/504、错误端口和 SSE。
10. 同构测试网关：在隔离环境复现腾讯云实际代理版本、路径重写、TLS、SSE 缓冲、请求大小和超时。
11. 合成负载发生器：执行 30 分钟稳态、2 倍峰值突发和 2 小时长稳，记录 p95/p99、错误预算、内存、句柄和 Goroutine 时间序列。
12. Claim ledger 生成和校验器：拒绝 `independently_reproduced` 状态但证据缺失或哈希不符的声明。

测试使用的全部用户、组织、订单、访客、渠道、签名密钥和令牌必须为合成值。

### 9.3 建议的质量阈值

以下全部为试装验收目标。只有当对应测试证据进入 claim ledger 并标记为 `independently_reproduced` 后，才能对外承诺：

| 指标 | 建议门槛 |
| --- | --- |
| 连接器启动到 READY | 将 DNS、TLS、控制面、frpc 和诊断拆成阶段预算；内部截止时间必须短于外部观察窗口；健康网络下通过 20 次采样后冻结 p95/最大值，不在测量前宣称 90 秒 |
| 正常停止连接器到 Edge 返回 503 | 目标不超过 5 秒；当前未验证 |
| 同机进程强杀 | 目标 10 秒内标记来源不可用 |
| 主机断电/网络黑洞 | 目标 45 秒内标记来源不可用；不以 5 秒承诺 |
| relay 故障 | 目标 15 秒内标记来源不可用 |
| relay 恢复后重新可用 | 先测基线再冻结目标；未验证前不宣称固定秒数 |
| 默认工具超时 | 30 秒，可配置范围 5 至 60 秒 |
| 合成容量基线 | 每来源 20 并发、10 请求/秒、20 条 SSE 长连接；30 分钟稳态、2 倍峰值突发和 2 小时长稳 |
| 成功率和延迟 | 成功率不低于 99.9%；端到端 p95 不高于 2.5 秒；p99 不高于 5 秒；代理额外 p95 不高于 250 毫秒 |
| 资源稳定性 | 预热后内存增长低于 10%；句柄和 Goroutine 无持续单调增长；故障恢复后 60 秒内回到基线 |
| 串话 | 跨租户、跨来源、跨主体串话为 0 |
| 秘密泄漏扫描 | 0 条命中 |

## 11. 主要风险和控制措施

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| Windows 与 Linux 入口判断错误 | 连接器安装成功但无法调用 MCP | 安装位置已冻结在 Windows 候选机；仍需用该机器实测各业务入口，不允许用 Linux 回环地址跨主机猜测 |
| Edge 注入 B 与“B 只在本机”冲突 | 凭据外泄或上游认证失败 | G0 改为连接器本机认证代理；更新旧契约和测试 |
| source_id 由显示名哈希生成 | 重命名、碰撞导致隧道错配 | 首次生成后持久化；云端幂等和 409 冲突 |
| 身份映射缺失或错误 | 多个开物用户看到同一华微数据范围，形成越权 | OAuth Token Exchange 产生用户级 A；Edge 解析 mapping；默认拒绝；共享身份仅限合成或脱敏数据 |
| 静态 Bearer 被所有平台用户共用 | 无法审计真实主体，产生横向越权 | A 逐请求绑定 `sub`、`act`、resource、mapping 和 grant；Edge 在线查撤销 |
| E 重放或本地代理绕过 | 低权限进程绕开 Edge 冒用平台授权 | E 绑定正文、方法、来源、会话和一次性 `jti`；每来源独立入口 |
| 上游反向驱动平台 | 恶意 MCP 通过 sampling、elicitation 或 roots 获取模型能力 | 双向 JSON-RPC 默认拒绝；只接受在途响应和匹配进度 |
| MCP 会话跨主体复用 | 用户 A 接管用户 B 的上游会话 | 连接器成为会话边界；会话绑定 tenant/subject/mapping/grant/source |
| 路径或 Host/SNI 重建错误 | 本机诊断通过但平台调用返回 404 或访问错误虚拟主机 | HWC-049 冻结入口和目标重建；专项 E2E 验证 Host、SNI 和路径 |
| 动态签名字段顺序或重试复用错误 | 华微拒绝 `tools/call` | 精确算例、时钟偏差、重试随机性和重放测试 |
| SSE 被反向代理缓冲 | 长任务看似卡死或丢事件 | Edge/visitor/连接器全链路 SSE 测试和禁用缓冲 |
| 本机页面令牌被误当管理员认证 | 低权限本机用户可导入、撤销或修改秘密 | 服务拒绝非回环；操作系统管理员授权；令牌只做 CSRF |
| 诊断或方法绕过工具允许列表 | 调用未批准写工具或暴露额外 MCP 能力 | 固定只读探测、MCP 方法默认拒绝、允许列表交集 |
| 云端改写内网目标 | 控制面被攻陷后连接器成为内网跳板 | 本机目标不可变；不一致时拒绝整个期望状态 |
| 请求头覆盖协议或注入签名头 | 会话劫持或认证边界绕过 | 只允许 `Authorization`，入口头先清理，代理最后写入 |
| 生产反向代理与测试环境不一致 | 客户现场才暴露路径、SSE 或超时问题 | HWC-044 同构测试网关 |
| 停连接器检测慢 | 平台长时间等待或错误使用旧连接 | 正常停止 5 秒门槛；强杀、断电断网、relay 故障分别测量 |
| 连接器运行 LocalSystem | 权限过大，故障影响面大 | 专用最小权限服务账户，DPAPI 绑定服务身份 |
| frpc 明文临时配置残留 | relay/STCP 秘密落盘后被低权限用户读取 | DPAPI-NG 保存秘密；临时文件最小 ACL；退出和下次启动清理；残余风险记录 |
| 设备令牌被复制 | 另一台主机冒充连接器 | 设备私钥和公钥绑定、签名请求、一次性 `jti`、轮换和撤销 |
| 华微上游不校验正文或 requestId | 窃取签名头后可在时间窗内重放 | 连接器绑定自身请求摘要、禁止自动重试；要求华微确认时间窗和防重放，否则记录残余风险 |
| 日志泄漏业务字段 | 合规和客户信任风险 | 结构化审计字段白名单，正文默认不落盘，秘密扫描 |
| 候选包与当前主线不一致 | 测试和客户拿到的不是同一产物 | G0 冻结集成分支、重新构建并核对哈希 |
| 无代码签名 | 客户安装被安全软件拦截或来源不可验证 | 正式交付要求 Authenticode；受控试装使用哈希白名单 |
| 许可证或构建来源不完整 | 客户无法合规分发或无法重现包 | HWC-043 冻结提交；HWC-061 负责试装 SBOM、许可证、构建日志和哈希；HWC-059 只负责正式发布的独立重建和签名证据 |
| 原始证据缺失 | 报告级结论被误当独立复现 | HWC-055 claim ledger；A/B 标记 `report_claim`；补证或重测后才能升级 |
| 只用 Windows 10 验收 | Server 2019 服务、ACL、DPAPI 行为不一致 | G5 强制 Server 2019 和整机重启验收 |
| 中继/Edge 故障被误报为上游业务失败 | 难以排障，错误答复给用户 | 稳定错误码和 `trace_id` 分段定位 |
| 把受控试装当成正式交付 | 客户预期失控 | G7/G8 分离，文档和 UI 明确“只读试用/待验证” |

### 12.2 受控试装关卡

#### 12.2.1 本机诊断试用（可先于云端 C 段）

允许向华微提供“本机诊断试用包”，但必须同时满足：

- 页面和交付说明明确标注“仅用于本机安装、MCP 导入、认证配置和连通性诊断，不代表开物平台已经能够调用客户内网 MCP”。
- 只能使用客户批准的合成或脱敏数据，不得调用客户真实业务写接口。
- 通过连接器单元测试、竞态测试、构建、哈希校验和 Linux 合成 MCP 端到端测试。
- 提供卸载、回滚、日志位置、停止条件和问题反馈模板。
- 不提供生产可用的云端绑定、relay 或平台端到端承诺；相关页面和文档保持明确的“待联调”状态。

该阶段的通过结论只能是“本机连接器可安装、可诊断和可卸载”，不能升级为 G7a/G7b。

试装准入条件（进入 G7a 前）：

- HWC-001 至 HWC-061 中除 HWC-031 之外的 P0 全部完成。
- 合成端到端测试通过。
- 在客户指定的 Windows Server 2019 目标环境上安装通过；如果客户环境确实不可用，任何等价环境替代都必须单独书面批准，不能自动视为满足 HWC-017。
- 同构反向代理测试通过，SSE 不缓冲、路径和 TLS 行为与腾讯云一致。
- 正常停止 5 秒、同机强杀 10 秒、网络黑洞 45 秒和 relay 故障 15 秒均有实测结果；恢复可调用、撤销拒绝。
- 身份映射缺失、撤销、跨租户和共享只读身份限制通过测试。
- 本机管理只对管理员开放，诊断、MCP 方法和请求头不能绕过允许列表；控制面不能改写内网目标。
- 审计无秘密泄漏。
- HWC-046 需求追踪矩阵完整；HWC-031 标记为待试装，其余 P0 都有命令、环境、提交、证据哈希和结论。
- HWC-055 claim ledger 完整，没有把报告声称或计划目标写成已独立复现。
- 客户测试凭据和测试 tenant 已通过安全渠道确认。
- 受控试装包提供 SHA-256；正式签名尚未完成时只能使用经书面批准的哈希白名单。
- 不接真实客户业务数据；只使用客户批准的测试数据或合成数据。

试装通过条件（关闭 HWC-031 前）：

- G7a：Windows 销售只读查询通过，客户确认可调用、可停止、可恢复、可撤销和可审计。
- G7b：知识检索只读工具和销售/客访查询分别通过，不能用一个工具的结果替代 C 段测试环境技术链路验收，也不能表述为生产闭环。
- 受控试装报告明确列出未验证的能力、残余风险和下一步。

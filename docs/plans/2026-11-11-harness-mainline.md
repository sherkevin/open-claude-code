# DeepSeek Harness 主线迁移与逐项验收

## 授权与范围

2026-11-11，用户明确要求更换 DeepSeek Harness 为底座，再按需求文档逐个实现所有功能。本计划执行该决定，不再把 Harness 仅作为另一个演示模块。唯一需求范围与质量门槛仍为 [需求对齐文档](../REQUIREMENTS_ALIGNMENT.md)。

- 代码及示例配置的新会话默认选择 Harness；显式 `claude` 只作为兼容和回滚选项。
- 已有会话按数据库记录继续使用原执行器，不转换原生会话编号、不删除历史、记忆或文件。
- 本次默认切换指开发代码基线，不等于正在运行的共享服务已经切换。生产部署、共享服务重启、发布仍不在本轮执行范围。
- 不切换默认知识检索，不访问客户数据，不读取主账号凭据，不调用未授权模型。真实模型测试与本地合成模型测试分开记录。
- 原始目标没有缩减：附件、文件、记忆、压缩、子任务、知识图谱、模型路由、审批、图片生成等未完成项继续逐项实现。默认切换本身不提升这些需求的完成状态。

## 组件复用与边界

继续使用已审查的官方 `deepseek-ai/deepseek-harness`，固定提交 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`，MIT 许可证；本轮不升级上游。应用权限、审批、来源登记与知识库仍由既有 Python 后端负责，Node 仅使用受控插件执行。依赖身份与许可记录见 [上游清单](../upstream-sources.json)。

附件优先复用官方 `session/prompt` 的文本、编码图片协议，以及本产品已有文档解析器。拒绝让模型提供任意宿主路径或下载地址；官方文件沙箱不等价于产品的读取权限，不直接启用其全量文件工具。后续统计与压缩优先复用官方 token-meter、compaction-basic 的扩展点，但必须补齐本产品的用户指令、审批、取消和真实用量合同。

### 本阶段的细分顺序（B1、B2、C 手动压缩已通过，下一步自动整理与完整用量）

1. **只读上下文统计。** 先接官方 token-meter 的受控快照，保留来源、近似值、陈旧状态及未知值。切换模型后，当前占用和窗口上限可能来自不同请求，不把此时的比例当硬预算；缺数据不能补零。真实用量按轮次、步骤与重试替换语义核对，重复结算事件不得重复收费。
2. **模型可用的会话记忆。** 复用现有 `NativeMemory` 和版本接口，不开放任意文件工具。模型读写必须核验用户、会话、版本、审批及发送前后权限；覆盖兄弟会话隔离、编辑冲突、恢复和清空。清空不删除聊天，也不能撤回模型此前已经看到的内容。
3. **手动压缩（本阶段已通过）。** 保留现有 `CompactRequest.instructions`，不能因上游 `/compact` 不收参数而静默丢弃用户要求。实际压缩边界、取消和失败分别验收；官方摘要另有独立用量，当前已在成功摘要事务中增量入账。失败重试、同一步骤替换结算和取消/失败调用仍归入完整用量后续缺口，不能只监听助手正文结算。
4. **自动整理。** 手动压缩、记忆与计量合同通过后再接阈值策略，避免引入第二套互不知情的摘要器。压缩后的任务输入可单列对比，但不能隐藏生成摘要本身的供应商消耗。

## 测试口径与回滚

默认 Harness 的测试不使用全局 `AGENT_RUNTIME_TYPE=claude` 覆盖。专门验证旧 Claude 原生协议的夹具显式选择 `claude`，默认新会话与真实 Harness 进程另行验证。历史回归数字不冒充本轮重跑结果；本地合成模型不能证明真实供应商的能力、延迟或费用。

回滚只将新会话默认显式配置为 `claude`，不重解释已有 Harness 会话。已有服务是否采用新版本、何时重启及是否对外发布是独立操作，本轮不执行。源代码与文档变更保留既有工作区改动，不整库覆盖、不擅自提交或推送。

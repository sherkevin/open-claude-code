## 1. 一句话目标

华微世纪员工在公网开物平台使用统一企业入口进行对话，开物通过受保护的公网 MCP 地址，调用华微 Windows Server 上已经存在的内网 MCP，从而查询他们自己的业务数据。

最终交付要让客户主要完成三件事：安装我们提供的 Windows 包；在本机填写或导入现有 MCP 地址和内部访问参数；点击检查连接。公网中转、平台授权、域名、证书、MCP JSON 和开物侧导入由我们负责。

本次查询结果会返回公网开物及其模型，用于回答问题。数据原始库和内部密钥留在客户侧，不等于查询结果不出内网。本期不建设全量数据同步或知识库搬迁。

## 5. 总体架构：复用 frp，补齐两端的适配

### 5.1 组件职责

| 所在位置 | 组件 | 负责什么 |
| --- | --- | --- |
| 公网／我方 | 开物现有 MCP 客户端 | 使用导入 JSON，发起 initialize、tools/list、tools/call |
| 公网／我方 | MCP Edge | 验证企业集成凭据、绑定来源、转发 MCP、输出可理解的错误 |
| 我方受控网络 | frpc visitor | 将 Edge 的请求送入指定 STCP 来源；仅供 Edge 访问 |
| 公网／我方 | frps relay | 接收 Windows 主动建立的连接并中转流量 |
| 客户 Windows | 随包 frpc | 主动连接 relay，重连与恢复 |
| 客户 Windows | 本机认证代理 | 固定上游目标，校验来源／允许工具，附加客户 Bearer 和动态签名 |
| 客户 Windows | 已有业务 MCP | 保持原有数据库查询和业务权限逻辑 |
| 公网／我方 | 现有控制面 | 设备绑定、来源、通道材料、状态、停用和撤销 |

数据路径为：开物 → HTTPS Edge → 云端 visitor → frps/STCP → Windows frpc → 本机认证代理 → 现有业务 MCP。响应沿原路径返回。

控制连接由 Windows 主动建立和维持。图中的数据返回客户内网不代表公网新建了到 Windows 的入站连接。

frp 本身负责网络转发，不生成华微 HMAC，也不会仅凭安装就自动产生一个正确授权的 MCP HTTP 地址。STCP 模式需要云端 visitor；对开物暴露的是我们提供的 HTTPS Edge 地址。[R1]

### 5.2 连接和路由的固定决定

1. 继续使用现有 Go Windows 连接器、Python 控制面和 frp STCP，不重写隧道协议，不另做数据库连接器。
2. MCP 公网入口统一为受保护的 HTTPS；推荐同一网关基址下 /sources/{source_id}/mcp，复用现有 EdgeSourcePath。
3. 原始 MCP 地址始终由客户在本机配置。公网请求不能指定任意内网 URL、端口、Host 或数据库地址。
4. 同一来源保持稳定 source_id；重启、改显示名、重复导入均不能重新映射到别的来源或丢掉允许工具。
5. visitor 和管理端口仅在受控网络提供给相应服务，不给客户增加浏览器插件、VPN 或 visitor 安装步骤。
6. 中继优先通过经过证书校验的 WSS 443 出站路径；工程师必须以固定 frp 版本验证实际支持和反代升级配置。若环境采用其他出站端口，写入明确配置和诊断结果，不能用“网页能打开”替代隧道可连证明。
7. 平台已有业务 HTTP 443 与隧道传输不能直接同时抢占同一监听端口。部署模板要给出可运行的反代／独立监听方案。
8. 我方配置公网基址、证书和 relay。客户不填写这些架构参数；交付包中预配置，或者绑定后自动获取。

### 5.3 本期使用原版 FRP 专属实例，省去插件开发

本期是一家客户、一台 Windows 连接器。为该连接器部署独立的原版 frps 实例和云端 visitor，暂不开发 HTTP 鉴权插件、不修改 frp 核心。原版内置 token 认证和 STCP 已能承担这个范围的网络接入。[R1][R4]

固定配置关系如下：

| 配置位置 | 配置值和职责 |
| --- | --- |
| 专属 frps | auth.method=token；auth.token=R |
| Windows frpc | 使用该专属实例地址；auth.token=同一个 R |
| 云端 frpc visitor | 使用同一实例、同一个 R |
| 每个 STCP 来源 | Windows proxy 与对应 visitor 使用同一个 T_source |
| proxy／visitor 标识 | serverName、serverUser、user、allowUsers 按固定版本生成一致配置；不要随意使用通配允许 |
| 公网 Edge | 验证企业集成 K，仅路由到授权来源对应的 visitor |

R 直接复用现有控制面为这一个 connector 派生的 relay token；T_source 复用现有逐来源秘密。二者通过我方受控部署流程生成配置，不经聊天、日志或导出的 MCP JSON。

第一次绑定与启动的顺序必须写入运维脚本：取得该设备的控制面绑定及 R/T → 为专属实例和 visitor 安装相应配置 → 启动并验证 → 将可用状态回传。这个工作由我方完成；客户只进行本机绑定和内部参数配置。

R 是该实例的运输凭据，Windows 与 visitor 均持有它。原版 frps 不具备本项目的逐设备 token 表或来源授权目录；不能声称它会自动拒绝一切未登记来源。隔离依靠独立实例、受控网络暴露、固定配置与 Edge 的来源授权。

专属实例仅对外发布必要的控制连接入口；visitor 只供 Edge 访问。关闭不需要的代理与管理入口，使用代理监听地址及部署网络限制收紧暴露；不要把任意代理端口发布到宿主机公网。[R5]

设备撤销必须实际停止：先禁用 Edge 的集成／来源并关闭活动流，再停止该设备专属 frps／visitor，并禁止服务管理器自动恢复。仅在数据库写 revoked 或仅更新配置文件不算撤销。恢复授权时重新受控绑定并处理旧 R/T，不自动复用已撤销状态。

M0 使用固定 0.61.1 的真实二进制验证正确／错误 R、正确／错误 T_source、名称匹配、重连和停止实例后的撤销。不能使用较新版本才加入的 tokenSource 配置，也不能把本方案标成已部署成功。

第二个权限独立的连接器不能直接共用这个实例并沿用上述安全结论。后续确需多设备共享 relay 或在 frps 内硬限制来源注册时，再评估官方插件／成熟开源扩展。[R2]

## 6. 两类身份与秘密必须分清

### 6.1 开物侧：企业集成凭据 K

K 只用于“开物调用我们的 Edge”。它不是华微内部接口密钥，也不是某位员工身份。

- 由我方管理员创建，绑定 tenant_id、integration_id、允许的 source_id 集合、有效期和状态。
- 使用密码学随机的高熵值，服务端只存不可逆验证值；不得写日志、Git 或诊断包。
- 默认试用有效期可配置，初始建议 30 天；管理员可轮换和立即撤销。
- 只有授权的开物企业空间／管理员能创建或导出，不能让任意已登录用户为任意 tenant 签发。
- 每次访问 Edge 都校验 K；过期、撤销、错误来源、跨企业访问均拒绝。
- URL 中的 source_id 只是路由标识，不是授权凭据。
- K 在开物 MCP 配置中按现有秘密配置方式保存，并在界面／日志中脱敏。
- 客户业务身份来自 Windows 本机 profile，不从开物聊天文本、调用参数或外来 userid 头推导。

### 6.2 华微侧：内部访问参数

| 参数 | 用途 | 保存位置 |
| --- | --- | --- |
| B：上游 Bearer | initialize、tools/list、ping 等固定访问认证 | Windows 本机 |
| S：HMAC key | tools/call 动态签名 | Windows 本机 |
| appid | 当前协议为 MCP | Windows 本机配置／协议常量 |
| channel、userid | 华微本期统一业务查询身份 | Windows 本机 |
| 原始 MCP URL | 本机代理固定访问目标 | Windows 本机 |
| 设备凭据、隧道秘密 | 设备和中转认证 | 对应设备／我方受控服务，不能导入开物当业务 Bearer |

界面用“华微 MCP 地址”“内部访问令牌”“签名密钥”“渠道标识”“业务用户标识”等具体字段；给出用途和示例占位符。支持 B 与 S 相同或不同，不擅自假定二者相同。

保留现有“云端只登记来源元数据／摘要，不登记原始内网 URL 和内部秘密”的设计。

Windows 交付需采用实际有效的本机秘密保护，并处理服务账户读取和升级迁移。建议 DPAPI 配合现有目录 ACL；如果使用机器级 DPAPI，仍须用 ACL 限制密文可读范围。不得用普通 base64 代替加密。icacls 等关键步骤失败必须明确报错，不能继续显示安装成功。涉及旧明文数据的迁移要原子完成并有回滚路径。

## 7. 华微调用协议：按附件实现，不重新发明

协议事实来源：
docs/evidence/huawi-mcp-20261117/source/2026-11-17_mcp_auth_rules.txt

### 7.1 HTTP 与 MCP

- 业务入口是单个 HTTP MCP 地址，示例路径为 /SysDevCore/mcp/<server_code>。
- 发送 JSON-RPC；Content-Type 为 application/json；接受 application/json 和 text/event-stream。
- initialize、notifications/initialized、tools/list、ping 使用固定 Bearer；tools/call 还需动态头。
- 实际 protocolVersion 通过握手协商；不能把附件示例版本硬编码为唯一版本。
- 处理通知的空响应、JSON 错误和工具 result.isError；HTTP 200 本身不代表业务成功。
- 保留需要的 MCP 会话／协议头，避免跨来源、跨集成主体混用 session。
- 客户文档是 POST 调用；GET／DELETE 按实际客户端需要和协议能力处理。不支持的可选能力应明确返回相应状态，不能伪造成功。[R3]

### 7.2 tools/call 的动态认证

每次业务调用生成新的 requestId（GUID）和 timestamp（UTC Unix 秒），使用下列顺序拼接，不改变大小写、不额外 URL 编码：

```text
appid=MCP&channel=<channel>&userid=<userid>&requestId=<GUID>&timestamp=<UTC秒>
```

对上述 UTF-8 原文计算 HMAC-SHA256，输出小写十六进制 sign。请求带 appid、channel、userid、requestId、timestamp、sign 六个头，并按既有调用约定附加 B。

客户端传来的同名身份／签名头必须被剥离或覆盖。K 不能传给客户业务服务；B／S 不能返回给开物调用方。

不要对上游已收到但结果未知的 tools/call 自动重放。连接恢复与业务请求重试是两件事；重新发起的请求必须重新签名。

附加的“密钥必须至少 16 字节”不是客户附件规则。应接受协议有效的非空本机密钥，避免拒绝附件的虚构测试值；不根据长度推断真实客户必定失败。

## 8. 最终 JSON 和云端管理契约

### 8.1 导出责任

最终可用 JSON 由我方云端管理员操作生成，随签发 K 一次性给出，然后导入华微对应的开物空间。客户不负责配置 Edge 权限。

复用现有平台导入器接受的结构：

```json
{
  "mcpServers": {
    "华微业务查询": {
      "type": "http",
      "url": "https://<我方实际网关域名与基址>/sources/<source_id>/mcp",
      "headers": {
        "Authorization": "Bearer <我方签发的企业集成凭据K>"
      }
    }
  }
}
```

这只是形状示例，域名、source_id 和 K 均不是已部署值。不要把占位符导入正式工作空间，也不要在报告中展示真实 K。

K 的明文只在创建或轮换时用于生成配置；后续列表／预览仅显示脱敏信息。若只保存验证值，不能设计一个 GET 接口凭空“取回原明文 K”；需要时轮换并重新导入。

本机旧的 BuildPlatformConfig 不能继续被称作“可直接使用的最终配置”。工程师可保留它作为不含授权的地址预览，但必须改名／改提示，并把正式导出入口指向云端生成结果。最终以实际开物导入器成功解析和调用为准。

### 8.2 最小管理操作

在现有 /api/kaiwu 控制面内扩展，不另造一套企业账户系统：

1. 管理员创建集成：选择企业、来源、有效期；校验来源归属；返回 integration_id、K 和完整 JSON。
2. 查询集成状态：只返回非秘密信息、有效期、来源和撤销状态。
3. 轮换凭据：原凭据失效，新凭据只显示一次；本期采用明确的原子切换并提示更新开物配置。
4. 撤销集成：立刻拒绝新调用；清理该集成相关会话和活动流。
5. 设备／来源撤销：复用已有控制面，同时收敛数据面路由和隧道状态。
6. 心跳与诊断：显示具体环节的状态，不把“设备在线”直接显示为“业务可用”。

具体 endpoint 命名复用本仓库风格；在 M0 的实现记录中冻结请求／响应和错误码。签发必须用现有管理员授权机制，绝不能借用设备凭据获得签发权限。

### 8.3 反代与错误

- 网页入口、控制面 BaseURL、Edge BaseURL 和 relay 地址在部署文档中分别列出，禁止相互代替。
- 现有设备请求签名涉及精确路径。反代必须保留一致的规范路径，或以可信配置处理前缀，不能信任外来可伪造的路径头。
- Edge 默认关闭未知来源；认证失败返回 401，已认证但无权限返回 403；来源不可用返回 503；上游超时用明确网关错误。
- 客户 MCP 自身的 HTTP 状态、JSON-RPC error、工具 isError 要区分展示，不包装成成功业务数据。
- 诊断和错误信息不得回显内部令牌、签名、完整内部 URL、请求正文或业务数据。

## 9. MCP 代理必须补齐的行为

1. SSE 必须按事件增量读取、处理并 flush。上游没有关闭时，开物已能收到首个事件；不能先 io.ReadAll 整条流。
2. 多行 data 属于一个事件，合并、检查后只写一次有效载荷，不重复整段 JSON。事件边界、id、event 等按支持范围正确处理。
3. 保留现有请求／响应关联和工具过滤，不因修复流式传输而透传任意上游反向请求。仅开启本次需要的能力；不自动向模型开放 sampling、elicitation 或 roots。
4. 会话绑定企业集成与来源。会话失效时允许协议规定的新握手，不替用户自动重放结果未知的业务调用。
5. Edge、visitor、Windows 代理和反代均关闭不合适的响应缓冲；设置合理的连接、首响应、空闲超时和取消传播。
6. 客户 TLS 正常验证。企业自签 CA 通过本机信任配置解决，不默认关闭证书校验。
7. 请求／事件有界，避免无上限读入内存；允许工具集为空时默认拒绝业务调用。
8. 固定上游、禁止任意转发、禁止不受控重定向、D01 重复导入保护均保留。

## 16. 开工标准

没有需要华微员工先回答、才能启动本计划的问题。

开工顺序是：保护现有工程 → 独立工作树 → 复用清单与必要改动 → 原版 FRP 专属实例验证 → 企业凭据与 JSON → 云端数据面 → 本机协议与 Windows 交付 → 开物对话验收。

交付判断始终回到同一件事：客户安装一个包并在本机填写内部参数后，是否能通过开物现有的 MCP JSON 导入和对话，实际查询到自己被授权开放的数据。

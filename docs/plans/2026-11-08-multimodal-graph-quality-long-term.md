# 多模态知识图谱长期质量目标

## 目标

把知识库和多模态知识图谱做成可核验的工业业务基础设施，而不是仅展示一张关系图。每个实体必须能回到来源：原文段落、图片文件版本、图片区域、OCR 框或模型候选；用户点击实体时能够打开对应图片并放大查看。解析失败的文档必须可重试、可解释，不能以“已索引”掩盖缺失证据。

## 分阶段交付

1. **数据与解析恢复**：扩充有明确许可的公开工业文档和图片；逐份记录来源、哈希、许可、页数、解析状态和失败原因；对失败样例提供重试或明确的人工处理入口。
2. **实体质量**：文本实体、图片 OCR 实体、视觉模型候选分层保存；每个实体带类型、置信度、来源文本、区域坐标、文档版本和模型摘要；模型候选不能冒充独立人工金标准。
3. **关系质量**：只有有明确证据的关系才进入语义关系层；同区域共现保留为 `evidence_only`，不向用户暗示因果或语义关系。
4. **多模态交互**：图谱节点展示图片缩略图和来源徽标；点击节点打开图片查看器并定位区域；支持图片放大、原图版本、OCR 框、实体详情和来源引用；解析失败、视觉模型未配置、无文字图片均有清晰状态。
5. **验收与回归**：公开工业样例建立可复验的实体和检索质量集；至少记录实体精确率、区域命中率、关系证据覆盖率、图片点击可达率、解析成功率和延迟。没有独立标注或真实客户样例的指标只能标为演示证据。

## 不可突破的边界

- 不使用真实客户数据，不把客户资料上传外部模型。
- 不读取或输出凭据，不把模型原始响应和图片原文写入日志。
- 不部署生产、不重启生产；开发服务重启单独记录。
- 未取得许可的外部数据只进入来源目录，不下载到仓库。
- 质量证据不足时保持 `partial` 或 `needs_review`，不提前宣称可交付。

## 当前验收门槛

- 现有服务端回归保持 `429 passed` 或更高且无业务失败。
- 至少三张公开工业图片完成图文检索烟雾测试；当前结果为 `Hit@1=3/3`，但不是独立人工金标准。
- 图谱实体点击后可访问受权限控制的图片或区域缩略图，版本和哈希一致。
- 任意解析失败样例在界面上显示失败原因和重试状态，而不是空白图谱。
- 仍缺少大规模、独立标注的工业实体与关系数据集时，需求状态继续标记为“部分实现”。

## 本轮增量记录（2026-11-08）

- 后端：OCR 实体保存字符偏移、OCR 多边形和图片区域；视觉模型输出只保存为 `model_candidate`，关系只保存为 `evidence_only`，并记录失败状态、延迟、响应摘要和用量。相关回归 54 项通过。
- 客户端：图谱实体、图片节点、图片区域、知识库缩略图和检索图片卡均可点击并灯箱放大；实体按文档版本关联图片，检索卡同时保留本地文档链接和经过安全过滤的 HTTP(S) 远程链接。客户端 18 个测试文件、82 项通过，构建通过。
- Fitness model：按钮直接从当前输入、最近用户消息和助手职责构造有界摘要，不要求重复输入；推荐结果自动应用并开启会话级自动路由。
- 稳定性：本地开发服务显式加载已授权 provider settings 后，健康检查返回 `model_configured=true`。这不是生产部署或真实模型端到端验收。
- 当前仍保持部分实现：缺独立工业实体/关系金标准、真实客户图像与业务样例、真实 Web Search 端到端链接样例；这些缺口不能用新增展示模块掩盖。

# 模型适配、消融对标与多模态知识设计

**日期：** 2026-11-07（Asia/Shanghai）
**服务器：** 学校云
**项目：** open-claude-code（知行工作台）

## 1. 目标与边界

本轮把“最合适的模型”从展示文案推进为可验证的服务端路由，并把客户现有助手的对标先做成**最简单 Agent 消融替身**：同一组固定任务中关闭知识库、检索、图谱、记忆压缩、子任务编排和审批增强，只保留最小输入—输出循环。该替身不是客户系统调用，也不代表客户真实效果。

禁止本轮触碰生产部署、服务重启、真实客户资料、凭据和未授权的付费模型。没有获批的模型线路时，接口必须返回“未配置/待测”，不能用硬编码答案冒充模型结果。

## 2. 模型推荐、自动路由与 Tab 补全

1. 用户点击“选择最合适的模型”后，客户端发送有限长度的任务摘要；服务端返回候选、理由、推理级别、路由模式和目标线路可用性，并把当前会话标记为自动路由。
2. 后续消息由服务端根据会话的自动路由标记决定线路，执行记录保留模型标识、路由模式、候选和目标状态。手动选择仍可覆盖当前会话。
3. Tab 补全只响应真实的 Tab 按键；客户端向服务端发送有界草稿，服务端仅在明确启用且预算大于零、目标线路可用时调用配置的模型端点。返回值必须以原草稿开头，失败、超时、未授权和模型不可用均返回空建议并显示可解释状态。
4. 用户要求的 `deepseek-v4.1-flash-1007` 必须通过受控配置提供。当前本地授权证据登记的是 `deepseek-v4.1-flash-1017`，因此在收到 1007 的真实端点、目录映射和授权前，1007 只能显示为缺少证据，不能把 1017 或其他模型伪称为 1007。

## 3. 消融对标与可视化

固定四项中文任务、种子、答案断言和报告键，分别运行：

- **增强方案：** 使用本地确定性记忆摘要、来源标记和图谱占位，验证编排能力，不调用模型。
- **最简单 Agent（客户现有助手的消融替身）：** 关闭增强模块，保留最小对话循环；只用于证明消融差异。
- **客户现有助手：** 没有客户样例或获批端点时全部保持 `not_measured`。

报告区分“文本 Token 估算”“本地编排耗时”和“模型响应速度”。Token 估算采用明确的计费口径：增强方案只计入压缩后的任务输入和输出，本地压缩过程不计入；基线计入同一任务的原始上下文，以便展示上下文管理的差异。压缩节省作为独立差值指标展示，不重复计入总 Token。柱状图对正确性、上下文记忆、上下文管理和 Token 消耗给出方向提示；缺少真实模型或客户数据的指标显示“待测”，不生成推测值。管理员才能读取和导出报告。

## 4. 多模态知识库、图谱与 RAG

数据流保持来源可追溯：原始文件不可变保存 → 本地尺寸受限缩略图 →（有依赖时）OCR → 文本、表格和图片资产索引 → 实体与关系及文档版本/页码/图片区域来源 → 混合检索和图谱展示。缩略图和元数据可以在无外部模型时本地验收；视觉语义索引、多模态向量和图片实体识别在模型未安装或未授权时必须标记 `needs_model` 或 `needs_ocr`。

图谱界面需要显示节点类型、来源定位和图片缩略图；检索响应保留排序、证据和权限边界。任何图片语义结论都不能在没有视觉模型证据时伪造。

## 5. 验收与证据

- 客户端测试覆盖 Fitness 触发、自动路由状态、Tab 请求和失败提示；服务端测试覆盖目标不可用、越权字段、草稿边界和路由审计。
- 消融测试验证两种本地参与者使用同一任务集、客户参与者保持待测，且报告明确 synthetic only。
- 知识库测试验证图片资产、缩略图 URL、OCR/视觉状态、来源关联和权限；缺依赖分支必须可解释。
- 最终回归运行客户端测试、TypeScript 构建和服务端完整测试；结果与待验收外部输入写入 `docs/evidence/`，不把本地合成结果升级为客户或生产交付声明。

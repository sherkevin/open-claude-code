# HippoRAG 官方快照适配实施计划

**阶段状态（2026-11-10）：** 本计划的四个开发步骤和本机回归已完成，验收边界保留。完整服务端回归及显式运行时补测合并覆盖当前 832 个不同用例，前端 122 项与类型检查通过；具体批次、去重方式及未完成产品能力见 `docs/evidence/HIPPORAG_OFFICIAL_2026-11-10.md`。这不是整个长期目标完成。

**目标：** 在不修改 Harness 在途实现、不接触服务与客户资料的前提下，把官方 HippoRAG 检索接到现有知识来源合同，验证真实上游算法，而不是再增加一个改名的本地算法。

**架构：** 一个薄适配文件负责不可变授权快照、重复文本的一对多来源和官方结果校验。知识服务默认仍用现有混合检索，只有显式注入已经构建的官方索引才尝试该后端；不在用户查询中自动安装依赖、构建全库或选择外部模型。失败明确标注回退，本地文档链接、图片证据、运行版本和权限继续由现有知识服务管理。

**技术：** Python、现有 SQLite 知识服务、固定 MIT 上游 `OSU-NLP-Group/HippoRAG@d5c8329422e0a0b834a15874545cb6a74b4f9b26`、隔离依赖环境。测试仅使用合成模型和合成工业资料。

## 方案选择

- 不复制官方算法，不新建原设计中的八个模块。上游已有 `Chunk`、`index()`、`retrieve()` 和注入模型接口。
- 不共用跨权限图后过滤：官方没有候选权限掩码，未授权实体会影响图传播。索引身份必须绑定整个授权文档版本集合。
- 不把 `Chunk.metadata` 当作唯一来源表：上游会按文本内容合并，必须由本项目保存一对多映射。
- 不默认切换生产检索。尚无真实抽取质量、资源限制和供应商运行证据，不能称为完整复现或可交付。

## 工作分配与步骤

1. `server/app/hipporag.py` 与 `server/tests/test_hipporag_adapter.py`：先写快照、重复来源、错误元数据、身份变更和损坏缓存测试；实现薄适配；运行合同测试。
2. `server/app/knowledge.py` 与 `server/tests/test_hipporag_official_search.py`：显式注入预构建后端，保留默认路径；接回现有证据卡和来源登记；测试权限撤销、版本变更、删除、空结果与可见回退。
3. `scripts/verify_hipporag_official.py`、隔离夹具和集成测试：固定上游源码，在 data3 隔离依赖中运行真实 `index/retrieve`，合成替身仅位于模型边界；检查实体抽取、事实筛选、非空图种子、重开索引和来源映射。
4. 跑知识库、图谱、权限和前端回归；独立审查适配边界，更新需求、设计和证据文档。未测能力保持部分实现。

## 验收边界

- 不能生成任何未授权、已删除、错误版本或无法回查的来源；重复文本不能丢失文档身份。
- 真实上游测试不能把图算法换成测试替身；官方算法通过不代表合成模型具备真实实体抽取质量。
- 生产部署、产品服务重启、凭据读取、真实客户资料及付费模型调用均不属于本轮。
- 当前重型后端只用于显式注入的隔离验证。上线前还需要进程级超时/取消、授权模型配置、质量评测及运营启用流程。
- 所有临时文件、依赖和日志放 `/media/data3`。不覆盖现有 Python 或 Node 服务环境。

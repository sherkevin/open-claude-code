# 一、项目背景与资料边界

华微世纪已经拥有一体化管理平台、低代码开发能力、MCP 接口、行业客户和实施团队，但智能体仍处于早期阶段。当前重点是智能问数、报表和图表生成、多模态数据采集、订单录入以及进度监测。华微希望快速补齐智能体能力，以便服务现有客户并获得新的增量项目。

我们近期要交付的工作是智能体能力建设，不是泛泛的企业人工智能咨询，也不是一次性制作两个演示机器人。本报告把合作设计成“能力层建设 + 首批场景落地 + 联合产品化”的连续路径。

本报告使用了华微世纪群内最新消息、六份当天的智能纪要全文、四张新图片，以及当前飞书会议索引中可读取的相关会议逐字稿。六份报告属于飞书生成的智能纪要，报告中的个别效率和收入数字只作为案例线索，不直接作为合同承诺。当前索引没有单独找到另外两场以宋总为标题的完整逐字稿，因此宋总部分只采用可验证的会议原文中明确出现的观点，没有把缺失内容当作已读原文。

会议转写中多次把“华微世纪”识别成“华为世纪”，结合群名、上下文和参会内容，本文统一按华微世纪理解。

# 二、华微的真实需求与合作机会

## 2.1 华微当前的优势

- 已有统一的管理软件和数据平台，覆盖供应链、客户、研发、采购、财务等管理环节。
- 已有低代码开发平台，绝大多数业务可以通过配置和低代码完成。
- 已经把平台能力通过 MCP 等接口开放出来，具备接入智能体的基础。
- 拥有大量行业客户、实施人员和长期积累的业务流程，能够提供真实场景和落地入口。
- 在制造、半导体、军工等行业有长期客户关系，具备把产品推广到客户现场的能力。

## 2.2 华微当前的短板

- 当前智能体对通用大模型依赖较强，上下文管理、长期记忆和 Token 成本控制还不够稳定。
- 工具和数据权限较为全局，尚未充分做到表级、字段级的最小权限控制。
- 缺少统一的模型路由、评测、行为审计、回放、影子运行和回滚机制。
- 客户提出 APS、工艺研发、设备维护、生产预警等更复杂需求时，华微需要外部智能体技术伙伴。
- 华微希望快速获得案例，但如果每个客户都重新定制，交付成本会越来越高，难以形成产品复利。

## 2.3 会议和新图片透露出的优先级

| 优先级 | 华微真正关心的事 | 一期对应动作 |
|-|-|-|
| 第一优先级 | 低成本、高效率、可调优、可私有化部署 | 增加模型适配、上下文管理、Token 记录、部署适配 |
| 第二优先级 | 让已有管理平台和 MCP 能被智能体安全调用 | 增加工具协议、最小权限、审批、日志、回放和回滚 |
| 第三优先级 | 快速做出客户可以看的案例 | 先做文档填充、问数、报表或数据采集等可量化场景 |
| 第四优先级 | 形成能够卖给下游客户的产品 | 把一期交付沉淀成模板、技能、评测集和部署包 |
| 长期优先级 | APS、设备维护、工艺研发和多智能体调度 | 在一期底座稳定后，以影子模式进入二期场景 |

白板图片体现的是“企业数据和平台—语义与知识—智能体和工作流—应用执行”的分层架构；模型选择图片体现多模型切换和路由；审批图片体现高风险操作需要人工确认；外部工具操作图片体现智能体必须具备工具调用、可追溯和可回滚能力。这四点都应当成为一期产品的可见能力。

# 三、我们自己的差异化与卖点

我们不应该把自己包装成普通的大模型应用开发团队。我们的卖点应当集中在“工业场景的可控智能体能力”上，强调能接入业务、能控制风险、能控制成本、能沉淀经验、能持续复用。

| 差异化 | 客户能感知到的价值 | 明天如何证明 |
|-|-|-|
| 工业场景的智能体工程 | 不是只会问答，而是能读取业务数据、调用工具、提出方案、经过审批后执行 | 展示从数据查询到工具调用再到审批的完整链路 |
| 上下文、记忆和 Token 成本管理 | 减少冗余上下文，支持长期记忆和分层检索，降低每次任务的调用成本 | 拿同一任务对比优化前后的 Token、耗时和成功率 |
| 多模型和私有化适配 | 不把华微锁死在单一模型，可根据成本、能力和部署环境切换 | 展示模型选择、路由策略和本地部署边界 |
| 最小权限和人工审批 | 智能体只能看到和修改完成任务所需的数据，高风险动作必须人工确认 | 展示字段级权限、审批模式、日志和回放 |
| 影子模式、回滚和数据飞轮 | 先和原流程并行运行，稳定后再扩大范围，失败案例可以追溯和修正 | 展示同一任务的影子运行、人工确认、失败记录和回滚 |
| 从项目交付走向平台复用 | 文档填充、问数、数据采集、研发和 APS 可以共用底层能力 | 交付 Agent 模板、技能配置、评测集和部署包 |
| 真正交付可运行的代码和环境 | 不只交演示视频或概念方案，能在华微环境跑起来并被验收 | 提前在华微测试环境完成一次可运行演示 |
| 工业算法和 APS 方向的深度积累 | 能够从管理软件进一步进入排产、设备维护、工艺和生产决策 | 把 APS/MAPS 定位为二期深度产品，而不是一期空泛承诺 |

> 我们的差异化不是“比别人会调用更大的模型”，而是让智能体真正进入企业业务流程，同时做到成本可控、权限可控、结果可测、错误可追溯、能力可复制。

# 四、建议的合作定位与产品架构

建议把合作定义为“华微数字平台之上的智能体能力层联合建设”。华微保留自己的管理平台、行业数据和客户实施体系；我们提供智能体运行时、上下文和记忆、模型路由、工具调用、权限审批、评测、日志和回滚能力。

建议的产品链路是：华微现有平台和数据 → 我们的智能体能力层 → 场景智能体 → 人工审批和业务执行 → 结果反馈、失败案例和经验沉淀。

| 模块 | 我们负责 | 华微负责 |
|-|-|-|
| 智能体运行时 | 编排、上下文、记忆、模型路由、成本控制 | 提供平台环境和接口接入 |
| 工具调用和权限 | MCP/HTTP 调用规范、重试、审计、回放、回滚 | 提供业务接口、数据字典和权限规则 |
| 场景建设 | Agent、技能、评测、提示、流程和质量优化 | 提供业务流程、样本和业务专家 |
| 部署交付 | 容器、适配包、部署脚本、运行手册和培训 | 提供算力、模型、网络和客户现场条件 |
| 客户商业化 | 核心技术、复杂问题支持和联合售前 | 客户关系、实施团队、行业方案和回款管理 |

# 五、一期交付范围：先做能力建设，再做行业深度

## 5.1 推荐的一期场景

如果华微没有更紧急的客户需求，建议一期选择两个场景：

1. 文档填充智能体：支持模板识别、内容填充、混合文档、格式校验，并通过接口供智能体调用。
2. 智能问数、报表或数据采集智能体：能够查询华微平台数据，生成结构化结果或执行一个受审批控制的写入动作。

这两个场景可以在较短时间内证明模型适配、上下文管理、工具调用、权限、审批、日志和评测等能力。APS、工艺研发和设备维护作为二期，通过影子模式逐步进入。

## 5.2 一期必须交付的能力

- 模型适配和模型路由：先确定一个主模型和一个备用模型，预留后续适配接口。
- 上下文管理和长期记忆：对历史信息进行筛选、压缩、分层检索和版本管理。
- Token 和成本管理：记录每次任务的输入、输出、模型、工具和成本。
- MCP/HTTP 工具调用：明确输入、输出、错误码、超时、重试和幂等规则。
- 最小权限、人工审批和风险策略：区分只读、建议、写入和外部动作。
- 日志、回放、影子运行和回滚：任何关键动作都能够解释和复现。
- 评测体系：建立样本、标准答案、人工评分表和版本对比。
- 部署和培训：提供可运行部署包、适配代码、运行手册和华微实施人员培训。

| 25—40 分钟：选择场景 | 提出文档填充和问数/报表作为首批场景，同时询问华微是否有更急的真实客户。APS 只作为二期方向。 | 确定主场景、辅助场景、业务负责人、技术负责人和首批样本。 |
| 40—55 分钟：冻结输入输出 | 逐项确认测试环境、模型、接口、数据字典、权限矩阵、样本数量、标准答案和基线。 | 形成一期输入清单，避免后面因为资料不足反复改需求。 |
| 55—70 分钟：谈合同和价格 | 给出验证包和能力建设一期两个选项，主推 39.8 万元六周方案。强调源码、独家和不限客户转售权不包含在普通项目费内。 | 确认合作方案、价格区间、付款节点和知识产权原则。 |
| 70—85 分钟：谈长期商业化 | 确认华微内部使用、下游客户复用、客户线索保护、平台授权和实施分工。询问宋总能够在什么时候带来首个试点客户。 | 确定至少一个内部场景和一个外部客户试点。 |
| 85—90 分钟：形成行动单 | 明确下一次技术评审日期、双方负责人、资料交付日期和合同草案日期。 | 会议结束后有责任人、日期、文件和下一步，不停留在“回头再沟通”。 |

开场建议直接说：我们今天不讨论所有智能体，也不先做大而全的企业改造。我们先在华微已有的平台之上补一层可复用的智能体能力，用两个真实场景证明四件事：接得上、跑得稳、成本可控、权限和结果可追溯。

要问华微的关键问题：哪个场景必须在一个月内见到结果？谁负责业务验收？谁负责接口和部署？能否提供 50—100 条脱敏样本？客户是内部使用还是需要华微继续卖给下游？华微希望获得使用权、转售权，还是源码和独家权？

# 七、合同结构、知识产权和商业边界

## 7.1 三层合同

1. 主合作协议：约定合作方向、双方角色、客户线索、保密、数据、知识产权、收入分配、客户保护和终止机制。
2. 一期能力建设任务书：约定场景、环境、模型、接口、输入、输出、验收和付款节点。
3. 每个下游客户单独任务书：约定该客户的环境、数据、实施范围、授权范围和维护费用。

## 7.2 知识产权建议

- 我们的通用智能体运行时、记忆框架、上下文压缩、模型路由、评测框架和通用工具调用能力属于我们的背景技术。
- 华微的管理平台、低代码平台、MCP 接口、业务数据、行业规则和原有代码属于华微背景技术。
- 一期交付场景的适配代码、配置、技能和部署脚本按合同约定交付使用，但通用底座不自动转让所有权。
- 共同开发的 APS/MAPS、设备维护、工艺研发等行业模块，必须约定双方都可以销售，或按客户授权和收入进行分配。
- 源码买断、独家使用和不限客户转售权必须单独报价，不能作为一期普通交付的默认内容。

## 7.3 数据和安全

- 华微和下游客户的数据归数据提供方所有，我们只在约定目的、时间、范围和环境内处理。
- 涉密或敏感客户优先采用本地部署、隔离网络和最小权限。
- 不得把客户原始数据用于其他客户；能够跨客户复用的只应是脱敏后的通用模板、规则和统计经验。
- 合同终止后约定数据返还、删除、日志保留和安全审计方式。
- 如果涉及个人信息，委托处理合同应明确处理目的、期限、方式、数据种类和保护措施，结束后按约定返还或删除。[[个人信息保护法]](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)

技术合同应当写清标的范围、技术资料保密、成果归属与收益分配、验收标准等内容。委托开发或合作开发的技术秘密成果，其使用、转让和收益分配也不能留成口头约定。[[中华人民共和国民法典]](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_60fb3863b7364b759123a42d1df568ca.html)

# 九、输入、输出和尾款验收指标

## 9.1 华微需要提供的输入

- 一个可运行的测试环境；一个主模型和一个备用模型；两到三个只读 MCP 接口和一个沙箱写入接口。
- 数据字典、字段含义、角色权限矩阵、业务流程和异常处理规则。
- 50—100 条脱敏真实样本，至少 20 条标准答案或人工评分样本。
- 一个业务负责人、一个技术负责人和能够每周评审的业务专家。
- 当前方案的 Token、响应时间、成功率和人工耗时基线。

## 9.2 我们交付的输出

- 智能体运行时接入包、模型适配和路由配置。
- 上下文压缩、长期记忆、Token 记录和成本分析。
- MCP/HTTP 工具调用规范、权限策略、审批策略、日志、回放和回滚。
- 文档填充智能体、问数/报表或数据采集智能体。
- 评测集、测试脚本、质量报告、部署包、适配代码、运行手册和培训材料。

## 9.3 推荐验收门槛

| 指标 | 建议门槛 |
|-|-|
| 约定任务完成率 | 不低于 90% |
| 结构化结果和文档格式正确率 | 不低于 95% |
| 关键字段填充正确率 | 不低于 90% |
| 工具和写入权限越界 | 0 次 |
| 关键动作审计记录 | 完整率 100% |
| 任务回放成功率 | 不低于 95% |
| 同批样本单次成功任务 Token 成本 | 较现有基线降低约 30%，最终以双方冻结的基线为准 |
| 试运行可用率 | 不低于 95% |
| 严重故障恢复 | 能够按约定时间回滚到旧流程 |

建议付款节点为 40% 启动、30% 核心能力完成、20% 试运行、10% 最终验收。尾款只与本期交付指标有关，不与华微之后是否从下游客户回款绑定。任何主观任务都要在验收前冻结人工评分表，不能用“感觉不够好”作为无限修改理由。

# 十、如何超出华微预期

- 第七天在华微环境里展示一次可运行的真实链路，而不是只展示我们的演示环境。
- 提供优化前后的 Token、耗时、成功率和人工操作时间对比。
- 提供一次完整的智能体行为回放：读取了哪些数据、调用了哪些工具、修改了哪些字段、谁批准了动作。
- 给华微一套可以直接用于售前的案例材料，包括问题、流程、指标、边界、截图和部署条件。
- 培训华微实施团队，使其能够用模板继续创建简单 Agent。
- 交付一份 90 天产品化路线图，明确哪些能力进入通用底座，哪些能力沉淀为行业模块。

这些内容应写入一期交付清单，避免靠口头承诺造成范围失控。可以赠送一个同一接口边界内的低风险技能模板，但不能承诺无限新增场景。

# 十一、华微内部需要做的轻量改造

不建议华微现在重做 ERP、重做低代码平台或调整整个组织架构。只需要建立一个最小的智能体交付机制：

1. 由一名高层担任项目发起人，负责资源和决策。
2. 由一名产品负责人负责场景、需求和验收。
3. 由一名技术负责人负责接口、环境、模型和部署。
4. 每个场景指定一名业务专家，负责样本、规则和结果判断。
5. 建立最小权限、人工审批、日志、评测、版本和回滚流程。

这不是企业全面改造，而是给华微现有数字化平台增加一个可管理的智能体运行机制。

# 十二、三个月到三年的长期路径

| 阶段 | 目标 | 商业结果 |
|-|-|-|
| 第一个月 | 完成华微内部能力层和两个可验收场景 | 形成第一个可演示案例和技术基线 |
| 三个月内 | 推动三个付费试点：文档/问数、数据采集/经营分析、工业场景探索 | 验证产品、价格、交付和客户选择 |
| 一年内 | 沉淀通用底座、数据规范、评测集、实施模板和行业技能 | 获得年度授权、客户实施费和模块复用收益 |
| 一年以后 | 把 APS/MAPS、设备维护、工艺研发做成行业产品 | 形成联合产品、平台调用费和持续分成 |

建议的平台授权费按我们 60%、华微 40%分配；实施费由实际承担交付的一方获得 70%，另一方获得 30%；共同开发的行业模块按投入和知识产权另行约定。华微应承诺至少一个内部场景和一个外部付费试点，否则只做验证包，不进入无限定制。

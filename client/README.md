# 知行工作台 · Client

可独立构建和部署的企业 Agent Web 客户端。产品名称和默认选择由服务端 `/api/v1/config` 提供，模型与推理级别由 `/api/v1/models` 提供；客户端不包含模型密钥、私有路由或 MCP 长期凭据。

飞书工作台入口为 `/feishu`。该路径使用飞书 H5 免登后复用完整工作台；服务端凭据、用户映射和开发者后台配置见 [`docs/FEISHU_H5.md`](../docs/FEISHU_H5.md)。

## 页面与使用流程

- **工作台**：点击助手先查看它的会话，不会自动创建新会话。点击“新建会话”选择助手、模型与推理级别；会话绑定助手，消息与上下文独立保存。侧栏恢复最近会话。
- **会话管理**：按助手、分类、标题或消息内容搜索；编辑名称、分类与标签，归档或恢复。归档保留消息和附件，恢复后可以继续工作。
- **模型选择**：新工作和聊天输入区均可选择模型及推理级别。当前公共选项为 deepseek-v4.1-flash、GLM-5.3 和 Dano-v2.1；Dano 的级别为 light、high、max，其余选项以服务端能力为准。选择随会话保存，执行中锁定，失败保持原选择，不可用线路明确禁用。已有原生会话不能跨 GLM 切换模型；相关选项标为“需新对话”，当前对话与记忆保留。新建／无原生历史的空会话仍可选全部模型，Dano 与 DeepSeek 之间及同模型推理级别仍可在空闲时切换。
- **模型配置恢复**：服务提示模型配置已变化时，可点击“重新连接当前模型”明确应用当前选择。此操作仅保存配置，不自动重新发送消息；成功后由用户自行重发。当前历史模型已不在可用目录时，提示选择有效模型或新建对话，不提交未知模型ID。
- **执行记录**：查看本次运行状态、耗时、Token、费用是否可用、工具调用参数及结果摘要；对具体操作批准或拒绝，停止运行，下载 JSON 执行记录。
- **业务连接**（个人／团队）：添加 HTTP MCP，或粘贴 MCP 配置进行安全预览和批量导入；测试连接并查看发现的工具，再进入助手设置。凭据只用于写入，预览遮蔽原文。
- **助手设置**：配置业务规则、默认模型、知识库、MCP 及工具授权、Skills、Web Search 和启停。当前版本已下线低代码工作流页签，助手设置只保留能力配置和会话；每位成员创建自己的私有配置，管理员创建和管理团队配置。已有共享配置只向可编辑用户显示修改操作，最终权限由服务端检查。
- **知识库**：创建资料集合，上传 PDF、DOCX、Markdown、TXT、CSV 或 JSON；查看解析状态、文件摘要、历史版本与逐页片段，测试检索，打开引用版本原件。失败文件可重新解析或上传新版本。
- **Skills**：创建或导入 SKILL.md，编辑流程和工具要求，查看历史版本，绑定到助手。在输入框键入 `@` 或点击 Skill 选择，支持方向键和 Enter；选中的能力只随本条消息发送，服务端保存当时版本。
- **来源依据**：回答中的编号打开对应数据、知识或网页来源；显示取数定位、文件版本与页码、网页原址等实际信息。打开时重新检查权限。
- **分阶段耗时**：执行记录显示运行环境就绪、首个模型事件、首段正文及总耗时；这些是接入端观察到的时间，未测得的阶段不补造数值。
- **成员管理**（管理员）：创建账号、修改显示名称／角色／状态以及重设密码。
- **用量记录**：成员查看自己的累计用量，管理员查看汇总和成员用量。没有可靠费用时显示“未提供”。
- **记忆**：先按助手筛选，再选择进行中或已归档会话，管理这个会话独立的记忆文件；支持查看、编辑、新建、删除和清空。新会话从空白记忆开始，同一助手的不同会话互不共享记忆。仅当前会话执行中只读，版本冲突不覆盖，离开未保存草稿前要求确认。可按助手筛选最近会话。
- **上下文**：在聊天顶部查看原生统计与最近压缩记录，手动刷新或发起原生压缩。未知统计保持未知；压缩通过正常运行记录和事件流跟踪。

新连接需要从执行服务器可达。页面设置不会自动打通客户内网，也不会访问员工电脑上的文件系统或本地 stdio 服务。支持的连接模式与认证方式由一期服务端能力决定。

## 本地开发

要求 Node.js 22 LTS 和 npm。先按 `server/README.md` 启动服务端于 `127.0.0.1:8000`，再运行：

```sh
cd client
npm ci
npm run dev
```

Vite 的 `/api` 代理保持同源 Cookie 登录，页面默认位于 `http://localhost:5173`。服务端的允许来源应包含实际访问的地址。账号由服务端 bootstrap 命令创建，无前端默认密码。

## 构建与测试

```sh
npm test
npm run build
```

生产静态文件位于 `client/dist/`。`package-lock.json` 固定依赖；`npm ci` 应用于部署。0.4 单元／渲染测试覆盖事件重放与最终来源替换、审批终态、附件非提交按钮、导入错误脱敏、公共模型和 GLM 历史边界、资源编辑权限、查询编码、@Skill 选择、来源链接与危险 URL、原件版本定位以及原生压缩状态。

`client/tests/model-selection.mjs` 和 `rename-race.mjs` 是受控 HTTP 夹具浏览器回归脚本，已适配助手详情／新建会话入口；本次仅编辑脚本，没有执行浏览器，因此以前 0.3 的浏览器通过记录不能用于证明 0.4。实际产品浏览器、真实服务、模型与权限集成验收由项目交付记录单独记载。

## 独立部署

```sh
docker build -t zhixing-client:0.4.2 client
```

镜像仅包含 Nginx 和静态文件。默认 `nginx.conf` 将 `/api/` 代理到 Docker 网络中的 `server:8000`，并关闭代理缓冲以支持 SSE。静态内容和服务端可分别发布；部署到不同网络时，修改 Nginx 上游地址，浏览器仍以同源 `/api/v1` 访问。反向代理必须保留请求 Origin/Host，并设置正确的 HTTPS、Cookie 和允许来源配置。

不使用 Docker 时，将 `dist/` 放入受控静态服务器，参考 `nginx.conf` 配置 SPA fallback 和 `/api` 代理；也可使用项目提供的开发/验收启动方式。`vite preview` 仅供构建预览，不作为生产托管服务。

需要挂载到反向代理子路径时，在构建时同时设置静态资源前缀和 API 前缀，例如：

```sh
BASE_PATH=/zhixing/ VITE_API_BASE=/zhixing/api/v1 npm run build
```

这样资源从 `/zhixing/` 加载，客户端请求和服务端返回的旧 `/api/v1/...` 来源链接都会解析到 `/zhixing/api/v1/...`；未设置变量时保持根路径 `/` 与默认 `/api/v1` 行为。

## 交互与协议约定

- 登录使用 HttpOnly Cookie，所有 API 请求携带 credentials；浏览器不在 localStorage 保存令牌。
- 发送消息带唯一 `client_request_id`，网络结果不确定时相同内容重试复用该 ID，避免重复任务。
- EventSource 自动重连，事件按服务端 ID 去重；最终答案以服务端回读消息为准，不重复拼接完整回复。
- 断开页面不会停止运行。点击“停止”才请求中断；已经执行的外部业务操作不会自动撤销。
- 审批只发送 `allow/deny`，不允许从客户端更改待执行参数。权限校验仍由服务端及业务系统执行。
- Markdown 不启用原始 HTML；附件仅预览允许的图片、纯文本、JSON/CSV/Markdown 和 PDF。其他类型通过授权下载查看。
- 桌面和移动端可用，弹窗支持 Escape、焦点限制和焦点恢复；减少动态效果设置得到尊重。

服务协议及部署验收边界见项目 `docs/API_CONTRACT.md`、`docs/DELIVERY_VERIFICATION.md`；MCP导入、记忆和上下文操作见 `docs/WORKSPACE_GUIDE.md`。

管理员接入与员工操作步骤见 [工作台操作指引](../docs/WORKSPACE_GUIDE.md)。客户只需提供自己的数据读取 MCP，员工直接使用本产品的客户端；不要求客户提供 Agent 框架。

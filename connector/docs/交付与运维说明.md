# 开物内网连接器 交付与运维说明

版本：1.1.0
适用对象：客户现场实施人员、客户 IT 运维人员、我方交付与支持人员

---

## 1. 连接器是做什么的

开物是企业工业智能助手平台。「内网连接器」是部署在客户内网的一台小主机上的程序，它把客户内网里已有的 MCP 服务（例如库存、设备、工单类系统提供的 MCP 接口）安全地接到云端开物平台上，让平台上的智能体可以调用这些内网能力。

它解决的核心问题是：**客户内网不需要开放任何入站端口，也不需要把内网服务暴露到公网。**

连接器只做一件事——由内向外发起连接：

```
客户内网                                     云端（腾讯云）
┌──────────────────────────────┐            ┌────────────────────────────┐
│  业务系统 MCP 服务            │            │  开物平台 / 智能体           │
│  10.0.0.8:8000/mcp           │            │  flintw.com/projects/kaiwu  │
│        ▲                     │            │        ▲                    │
│        │ 内网 HTTP           │            │        │                    │
│  ┌─────┴──────────────┐      │  出站      │  ┌─────┴──────────────┐     │
│  │ 开物内网连接器      │──────┼───TLS─────┼─▶│  MCP Edge（接入网关）│     │
│  │ + 回环认证代理      │      │  443       │  │ + 租户 frps 中继     │     │
│  │ + frpc 隧道客户端   │      │            │  │                      │     │
│  └────────────────────┘      │            │  └────────────────────┘     │
└──────────────────────────────┘            └────────────────────────────┘
```

工作过程分六步，与连接器本机界面上的六个步骤一一对应：

1. **绑定企业**：交付人员先在平台上创建连接器，生成一次性接入码；客户在连接器界面输入接入码，连接器换回本机设备身份。
2. **导入现有 MCP 配置**：把客户内网 MCP 的地址和请求头粘贴进来，连接器校验并保存；请求头里的凭据只留在本机。
3. **配置本机动态认证**：输入客户批准的华微 `appid`、`channel`、`userid`、HMAC 密钥和只读工具允许列表。该步骤只写入客户本机。
4. **检测内网**：连接器从本机出发，依次检查网络连通、TLS 证书、MCP 协议握手、工具列表，提前发现问题。
5. **连接云端**：连接器向云端拉取期望状态和中继参数，先启动逐来源回环认证代理，再启动 frpc 建立加密隧道。
6. **导出平台配置**：连接器生成 Edge 地址和平台授权占位符，交给平台管理员完成授权交换。

### 凭据是分开的，这是设计上的硬约束

| 凭据 | 谁持有 | 用途 |
| --- | --- | --- |
| 设备身份（设备令牌） | 只在本机 `identity.json` | 连接器调用云端控制面，不能读业务数据 |
| 平台授权 A | 平台内部 | 智能体访问 Edge 用 |
| 客户 MCP 凭据 B | 只在本机 `secrets.json`，由连接器回环认证代理使用 | 访问客户内网 MCP 服务 |
| 动态签名密钥 S | 只在本机 `auth_profiles.json`，由连接器回环认证代理使用 | 生成 `tools/call` 的渠道身份与 HMAC |
| 通道密钥 | 双方协商，写在 `frpc.toml`（0600 权限） | frpc 隧道鉴权 |

三条红线，实施时不要绕过：

- 平台授权 A **绝不能**当作客户 MCP 凭据 B 使用。
- 客户 MCP 凭据 B 和签名密钥 S **只允许**连接器本机认证代理使用，不能写进导出配置，也不能上传 Edge。
- 设备身份 **不能**读取 A 或 B。

## 3. 部署前准备

### 3.1 主机要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Linux x86_64（glibc 2.17 及以上，CentOS 7 / Ubuntu 18.04 及以上均可）或 Windows Server 2016 / Windows 10 及以上 x86_64 |
| 配置 | 2 核 CPU、2 GB 内存、1 GB 可用磁盘即可（连接器本身常驻内存约 20 MB） |
| 权限 | Linux 需要 root 安装；Windows 需要管理员 |
| 位置 | 能访问客户内网 MCP 服务的一台机器，不需要是 MCP 服务器本身 |

### 3.2 网络要求

**只需要出站，不需要入站。**

| 方向 | 目标 | 端口 | 用途 |
| --- | --- | --- | --- |
| 出站 | 云端控制面（交付人员提供，正式环境入口为 `flintw.com`） | 443/TCP | 绑定、心跳、拉取通道参数 |
| 出站 | 云端 MCP Edge（交付人员提供） | 443/TCP | 平台侧访问通道 |
| 出站 | 云端 frps 中继（交付人员提供，通常与控制面同域或同 IP 段） | 7000/TCP 或交付人员指定端口 | 隧道连接 |
| 内网 | 客户 MCP 服务（如 `10.0.0.8:8000`） | 按客户实际 | 连接器访问 MCP |
| 入站 | 无 | 无 | 不需要任何入站端口 |

如果客户有出站白名单或代理，请提前放行上述目标。连接器**不使用**系统 HTTP 代理去连中继；如现场必须经代理，请与交付人员确认方案，不要私自加代理层。

### 3.3 需要向客户收集的信息

1. 内网 MCP 服务的地址、协议类型（HTTP / Streamable HTTP）、请求头凭据。
2. 该 MCP 服务提供的工具名称清单（用于核对工具白名单）。
3. 一台可安装程序的主机，以及该主机到 MCP 服务的连通性。
4. 客户对出站防火墙的变更窗口与审批人。

### 3.4 需要我方准备的信息

1. 该客户租户下创建好的连接器 ID。
2. 一次性接入码（有效期与使用次数由平台控制，默认一次性）。
3. 云端控制面地址、Edge 地址、中继地址与端口。

## 4. 安装

### 4.1 Linux

```bash
# 解压
tar -xzf kaiwu-connector-1.1.0-linux-amd64.tar.gz -C kaiwu-connector-1.1.0
cd kaiwu-connector-1.1.0

# 安装（root）
sudo ./install.sh
```

安装脚本会：

- 创建系统用户 `kaiwu-connector`（不可登录、无家目录）；
- 安装程序到 `/opt/kaiwu-connector`；
- 首次安装时把地址模板写入 `/etc/kaiwu-connector/connector.env`（权限 0640，属主 root，组 `kaiwu-connector`）；
- 创建数据目录 `/var/lib/kaiwu-connector`（0700，属主 `kaiwu-connector`）；
- 注册并启动 `kaiwu-connector.service`，设置开机自启和失败重启。

安装完成后确认：

```bash
systemctl status kaiwu-connector
curl -s http://127.0.0.1:17872/api/status
```

### 4.2 Windows

以管理员身份打开 PowerShell，进入解压目录：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1
```

安装脚本会：

- 复制程序到 `C:\Program Files\Kaiwu\Connector`；
- 数据目录为 `C:\ProgramData\Kaiwu\Connector`；
- 把 `config\connector.env.example` 中的 `KAIWU_CLOUD_BASE`、`KAIWU_EDGE_BASE` 写入系统环境变量；
- 注册 Windows 服务 `KaiwuConnector`（自动启动、失败自动重启）；
- 启动服务。

确认：

```powershell
Get-Service KaiwuConnector
Invoke-RestMethod http://127.0.0.1:17872/api/status
```

### 4.3 配置云端地址

编辑对应配置文件，把地址改成交付人员提供的正式地址：

- Linux：`/etc/kaiwu-connector/connector.env`
- Windows：系统环境变量，或直接用 `sc.exe config` 修改服务命令行参数

```bash
KAIWU_CLOUD_BASE=https://flintw.com/projects/kaiwu/api
KAIWU_EDGE_BASE=https://flintw.com/projects/kaiwu/mcp
```

> 上面的路径是当前正式环境的默认约定，**实施时以交付人员书面提供的地址为准**。如果地址不一致，先确认再改，不要凭经验猜。
>
> 修改后需要重启服务：Linux `sudo systemctl restart kaiwu-connector`；Windows `Restart-Service KaiwuConnector`。

### 4.4 打开本机界面

连接器界面只监听回环地址 `127.0.0.1:17872`，不对局域网和公网开放。在客户主机上直接打开浏览器访问 `http://127.0.0.1:17872/`。

如果主机没有图形界面或需要远程协助，使用 SSH 端口转发，**不要**把监听地址改成 `0.0.0.0`：

```bash
ssh -L 17872:127.0.0.1:17872 运维账号@客户主机
# 然后在自己电脑浏览器打开 http://127.0.0.1:17872/
```

界面带会话令牌校验，只接受本机来源的请求，跨站请求会被拒绝。

## 5. 首次接入（现场六步）

### 第 1 步：绑定企业

在界面输入交付人员提供的一次性接入码，点「绑定」。成功后顶部状态从「未接入」变为「待配置」，并显示企业名称和连接器 ID。

- 接入码只能用一次，绑定失败不会消耗（网络错误可重试）。
- 如果提示「接入码无效或已使用」，请交付人员在平台重新生成，不要重复尝试。

### 第 2 步：导入现有 MCP 配置

把客户的 MCP 配置粘贴进文本框，支持两种格式：

```json
{
  "mcpServers": {
    "库存查询": {
      "type": "http",
      "url": "http://10.0.0.8:8000/mcp",
      "headers": { "Authorization": "Bearer 客户自己的凭据" }
    }
  }
}
```

或单个 MCP 服务对象。点「导入并校验」。连接器会检查：

- 必须是 HTTP / Streamable HTTP 类型，`stdio` 类型默认拒绝（需要交付人员评估后加 `--allow-stdio`）；
- 地址必须是 `http` 或 `https`，不能是文件、命令或未解析的 `${变量}`；
- 请求头会被收集为本机秘密，**不会**出现在导出的平台配置里。

校验不通过时界面会逐条列出问题，按提示修改后重新导入。

### 第 3 步：配置本机动态认证

如果客户 MCP 的 `tools/call` 要求华微渠道身份和 HMAC，在本机界面第 3 步选择来源并填写：

- 华微 `appid`；
- 华微 `channel`；
- 华微 `userid`；
- HMAC-SHA256 密钥；
- 客户书面批准的只读工具名称，用逗号分隔。

保存后，代理只对 `tools/call` 动态注入六项请求头，并对每次转发重新生成 `requestId`、`timestamp` 和 `sign`。`initialize`、`notifications/initialized`、`tools/list`、`ping` 只注入固定 Bearer。未配置允许列表时，`tools/list` 返回空工具列表，`tools/call` 默认拒绝。

密钥不会显示在状态接口、导出配置或诊断结果中。详细签名原文和测试方法见 `docs/动态认证与试装说明.md`。

### 第 4 步：检测内网

点「开始检测」。连接器按顺序检查：网络是否通 → TLS 证书是否可信 → MCP 握手是否成功 → 工具列表是否符合预期。默认**不会**逐个执行工具，避免对客户系统产生副作用。

全部通过后再进入下一步。失败时看第 8 节的错误码表。

### 第 5 步：连接云端

点「连接」。连接器会拉取云端期望状态和中继参数，生成 `frpc.toml` 并启动隧道，随后做一次端到端检测。

- 状态变为「就绪」：通道可用，平台侧可以开始调用。
- 状态变为「内网来源异常」：隧道通了，但某个内网 MCP 检查不通过，按第 8 节处理。
- 状态变为「通道异常」：隧道没起来，多半是出站端口或中继参数问题。

「暂停」会立即停止对外访问（不等在途请求），适合客户临时维护；「断开」会停止隧道并回到待配置状态。

服务重启或主机重启后，连接器会读取上次退出时的状态：如果上次处于「就绪」，会自动重新建立通道，不需要人工打开界面点「连接」；如果上次是人工暂停，重启后保持暂停，不会自行连接。隧道进程意外退出时，连接器会按退避策略自动拉起，并在内网检查通过后自动恢复「就绪」。

### 第 6 步：导出平台配置

点「生成配置」，得到如下内容，复制交给平台管理员：

```json
{
  "mcpServers": {
    "库存查询": {
      "type": "http",
      "url": "https://<Edge 地址>/sources/<来源 ID>/mcp",
      "headers": { "Authorization": "Bearer <由平台创建授权时填充>" }
    }
  }
}
```

平台侧只接受这一种结构：顶层 `mcpServers`，每个服务只有 `type`（只支持 `http` / `streamable-http`）、`url`、`headers`，且只有 `Authorization` 一个请求头。多写字段会被拒绝。

平台管理员导入后，还需要完成 Token Exchange、Edge 数据面上下文签发和来源授权。只有云端 C 段链路与客户测试来源均完成联调后，智能体才能调用客户内网工具；仅导入本段配置不能作为端到端可用证明。

## 6. 日常运维

### 6.1 正常状态

顶部状态显示「就绪」，通道显示「运行中」，即一切正常。

### 6.2 服务管理

| 操作 | Linux | Windows |
| --- | --- | --- |
| 状态 | `systemctl status kaiwu-connector` | `Get-Service KaiwuConnector` |
| 启动 | `systemctl start kaiwu-connector` | `Start-Service KaiwuConnector` |
| 停止 | `systemctl stop kaiwu-connector` | `Stop-Service KaiwuConnector` |
| 重启 | `systemctl restart kaiwu-connector` | `Restart-Service KaiwuConnector` |
| 日志 | `journalctl -u kaiwu-connector -f` | 事件查看器 → Windows 日志 → 应用程序 |

重启服务不会丢失绑定和来源配置。上次处于「就绪」时会在启动后自动恢复通道；人工暂停过的连接器重启后仍保持暂停，需要人工点「连接」。如果是异常退出（例如直接结束进程或主机断电），重启时会先清理上次遗留的隧道进程，再建立新的通道，不需要人工处理。

### 6.3 日志与敏感信息

连接器日志**不会**打印设备令牌、客户 MCP 凭据、通道密钥的明文。排障时如果需要把日志发给支持人员，请先确认没有人为往日志里粘贴过凭据。

### 6.4 本机文件

| 文件 | 位置（Linux） | 内容 | 权限 |
| --- | --- | --- | --- |
| `identity.json` | `/var/lib/kaiwu-connector/` | 设备身份、企业、中继参数 | 0600 |
| `config.json` | 同上 | 导入的来源列表（不含凭据） | 0600 |
| `secrets.json` | 同上 | 客户 MCP 请求头凭据 | 0600 |
| `auth_profiles.json` | 同上 | 华微渠道身份、HMAC 密钥和来源绑定 | 0600 |
| `frpc.toml` | 同上 | 隧道配置与通道密钥 | 0600 |
| `state.json` | 同上 | 最近状态快照 | 0600 |

备份：只需备份 `identity.json` 和 `config.json` 即可恢复绑定关系；`secrets.json` 属于敏感凭据，按客户安全要求决定是否备份。
迁移：把整个数据目录拷到新机器、装好程序、确认地址一致后启动即可，不需要重新绑定。

### 6.5 心跳

连接就绪后，连接器每 30 秒向云端上报一次状态。云端连续收不到心跳会标记连接器离线，并在平台上告警。

---

## 7. 状态说明

| 状态 | 含义 | 处理建议 |
| --- | --- | --- |
| 未接入 UNPAIRED | 还没有绑定企业 | 执行第 1 步 |
| 待配置 CONFIGURING | 已绑定，但还没导入来源或还没连接 | 继续第 2～4 步 |
| 连接中 CONNECTING | 正在建立隧道 | 等待，超过 1 分钟看日志 |
| 就绪 READY | 隧道和内网来源都正常 | 正常，无需处理；服务重启后会自动恢复 |
| 内网来源异常 DEGRADED_UPSTREAM | 隧道通了，但内网 MCP 检查不通过 | 查第 8 节 UPSTREAM_*、MCP_*、TOOL_* 错误 |
| 通道异常 DEGRADED_RELAY | 隧道没建立或不稳定 | 查出站端口、中继地址、通道密钥；隧道进程会自动重启，恢复后状态自动回到就绪 |
| 已暂停 PAUSED | 人工暂停，不对外提供服务 | 确认维护结束后点「连接」恢复 |
| 断开中 DRAINING | 云端要求优雅停止，等待在途请求结束 | 等待自动完成 |
| 已撤销 REVOKED | 云端或本机撤销了设备身份 | 需要重新生成接入码并绑定 |

## 8. 故障排查

### 8.1 错误码对照

`connector diagnose --data-dir <目录>` 或界面第 3 步会给出错误码：

| 错误码 | 含义 | 常见原因 | 处理 |
| --- | --- | --- | --- |
| `UPSTREAM_UNREACHABLE` | 连不上内网 MCP | 地址写错、服务未启动、内网防火墙 | 在连接器主机上 `curl -v <mcp 地址>` 验证 |
| `CLOUD_TLS_FAILED` | 云端证书校验失败 | 客户网络做了 HTTPS 解密、系统时间不对、根证书缺失 | 校时；确认没有被中间人代理；不要关闭证书校验 |
| `UPSTREAM_AUTH_FAILED` | 内网 MCP 拒绝认证 | 凭据过期、请求头名字不对 | 更新第 2 步导入的请求头 |
| `MCP_INCOMPATIBLE` | 协议不兼容 | 对方不是 MCP、版本过旧、返回的不是 JSON-RPC | 确认对方支持 Streamable HTTP 与 2025-06-18 协议 |
| `TOOL_ALLOWLIST_MISMATCH` | 工具列表与预期不符 | 服务升级后工具改名、权限不足 | 与客户核对工具清单 |
| `TOOL_TIMEOUT` | 工具调用超时 | 内网服务慢、首次冷启动 | 稍后重试；持续超时查对方服务 |

### 8.2 连接不上云端

按顺序查：

1. 控制面地址是否可达：在客户主机上 `curl -sS https://<控制面地址>/health`（如平台提供健康检查）。
2. 出站 443 是否放行：`curl -v https://flintw.com` 看是否能完成 TLS 握手。
3. 中继端口是否放行：`telnet <中继地址> <中继端口>` 或 `nc -vz`。
4. 系统时间是否准确，偏差超过 5 分钟会导致证书和令牌校验失败。
5. 看服务日志里 frpc 的报错，常见为 `login to server failed`（密钥或地址不对）和 `connect to server error`（端口不通）。

### 8.3 界面打不开

- 确认服务在运行。
- 确认访问的是 `http://127.0.0.1:17872/`，不是客户主机的局域网 IP。
- 远程协助请用 SSH 端口转发（见 4.4），不要改监听地址。

### 8.4 平台侧调用报 401 / 403

这属于平台授权问题，不是连接器问题：

- 401：平台授权 A 无效或过期，或导入配置时把占位符原样导入了没有创建授权。
- 403：授权存在但该来源或工具没有授权范围，检查平台上的工具白名单。

## 9. 升级

1. 记录当前版本：`kaiwu-connector version`。
2. 停止服务（Linux `systemctl stop`，Windows `Stop-Service`）。
3. 用新包覆盖程序文件（不要删除数据目录）。
4. 启动服务，确认状态恢复「就绪」。
5. 如新版本要求重新绑定，按交付说明执行，不要自行清空数据目录。

升级不需要重新导入客户 MCP 配置，来源和秘密都保存在数据目录里。

## 11. 安全要求

1. **本机界面只监听回环地址。** 不要改成 `0.0.0.0`，不要做端口映射，不要加反向代理暴露到内网或公网。需要远程操作时用 SSH 端口转发。
2. **数据目录权限 0700，文件 0600。** 不要用 root 以外的宽松权限覆盖，也不要把它放进共享目录或网盘同步目录。
3. **凭据不落地到导出文件。** 导出的平台配置里只有地址和占位符；如果看到真实凭据，说明操作有误，立即停止并上报。
4. **不要关闭 TLS 校验。** 出现 `CLOUD_TLS_FAILED` 时排查根因，不要用 `--insecure` 之类的方式绕过。
5. **frpc 为固定版本。** 随包分发的是 0.61.1，遵循 Apache License 2.0。客户如需安全扫描，请提供包内 `版本信息.txt` 和 frp 官方许可证说明。不要用客户环境里其他版本的 frpc 替换。
6. **最小权限。** 连接器以专用低权限账号运行（Linux 为 `kaiwu-connector` 系统用户，Windows 为服务账号），不需要管理员日常运行。
7. **撤销即失效。** 客户终止合作或更换主机时，在平台撤销连接器；本机界面上的「撤销本机」也会立即让设备身份失效。

## 13. 本版本能力边界

为避免现场误解，明确说明当前版本**不做**什么：

- 不支持 `stdio` 类型 MCP（需要交付人员评估后用 `--allow-stdio` 开启，属于条件分支）。
- 不支持客户侧自行配置多租户；一台连接器只服务一个企业租户。
- 不做流量内容审计和脱敏，这属于平台侧职责。
- 不做高可用集群；一台连接器故障时，平台侧会显示离线，需要人工恢复或切换到备用机。
- frpc 的版本由随包二进制决定，不支持热升级。
- 隧道进程意外退出会自动拉起，但如果是客户网络整体中断，退避重试最长间隔为 30 秒，恢复时间取决于网络恢复时间。

如现场需求超出以上边界，请反馈给产品而不是现场改造。

## 14. 常见问题

**问：客户说不能装软件，能不能只给一个 exe 双击运行？**
答：Windows 包里有 `kaiwu-connector.exe`，可以直接双击运行，界面一样可用；但双击运行不会开机自启，客户重启后需要手动再开。生产环境建议用 `install.ps1` 注册服务。

**问：连接器会不会把客户内网数据传到云端？**
答：连接器只转发平台发起的 MCP 工具调用，不主动采集、不上传文件、不做旁路抓包。数据是否出内网由被调用的工具本身决定，这一点需要在客户侧的工具权限上控制。

**问：能不能把界面开放给客户内网其他人看？**
答：不建议。界面能触发绑定、导入、撤销等敏感操作，只应给实施人员在本机使用。

**问：换机器怎么办？**
答：拷贝数据目录到新机器，安装程序，确认地址一致后启动即可；如果平台侧要求重新绑定，用新的接入码走第 1 步。

**问：客户有出站代理怎么办？**
答：当前版本不读取系统代理设置，隧道直连中继。需要代理的场景请先与交付人员确认，不要在现场临时加代理。

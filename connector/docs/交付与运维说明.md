# 开物内网连接器 交付与运维说明

版本：<版本号>
适用对象：客户现场实施人员、客户 IT 运维人员、我方交付与支持人员

请使用项目对接人确认的正式安装包。Windows 弹出管理员确认时，核对发布者与随包说明一致，再继续安装。若系统显示“未知发布者”或终端防护阻止运行，请保留提示文字交给对接人。

双击安装包，按窗口提示完成安装。打开本机配置页后，点击「运行连接测试」检查内置示例，再绑定企业并复测公网。接入真实业务时，由维护人员在本机填写自己的 MCP 地址和访问参数，选择已批准的工具，点击「保存并连接」。普通员工使用获授权的开物助手。收到助手授权确认后，使用已分配的账号登录开物。网页入口为 [开物](https://flintw.com/project/kaiwu/)。

## 1. 连接器是做什么的

开物是企业工业智能助手平台。「内网连接器」是部署在客户内网的一台小主机上的程序，它把客户内网里已有的 MCP 服务（例如库存、设备、工单类系统提供的 MCP 接口）安全地接到云端开物平台上，让平台上的智能体可以调用这些内网能力。

它解决的核心问题是：**客户内网不需要开放任何入站端口，也不需要把内网服务暴露到公网。**

连接器只做一件事——由内向外发起连接：

```
客户内网                                     我方云端
┌──────────────────────────────┐            ┌────────────────────────────┐
│  业务系统 MCP 服务            │            │  开物平台 / 智能体           │
│  10.0.0.8:8000/mcp           │            │  flintw.com/projects/kaiwu  │
│        ▲                     │            │        ▲                    │
│        │ 内网 HTTP           │            │        │                    │
│  ┌─────┴──────────────┐      │  出站      │  ┌─────┴──────────────┐     │
│  │ 开物内网连接器      │──────┼───TLS─────┼─▶│  MCP Edge（接入网关）│     │
│  │ + 回环认证代理      │      │  443       │  │ + 租户 frps 中继     │     │
│  │ + frpc 隧道客户端   │      │            │  │                      │     │
│  └────────────────────┘      │            │  └────────────────────┘     │
└──────────────────────────────┘            └────────────────────────────┘
```

首次接入按页面提示完成下面的步骤。

1. **安装并打开本机页面**：双击 Windows 安装包完成服务和桌面快捷方式安装，页面只监听本机回环地址。
2. **试用内置示例并绑定企业。** 点击“运行连接测试”，先确认本机示例。按首页提示填写开物技术支持签发的一次性企业绑定码，再运行连接测试验证公网。收到示例助手授权确认后，登录开物试问示例。
3. **填写并保存本机参数**：在普通表单填写服务名称、MCP HTTP 地址、访问令牌和所需的华微动态签名字段，读取真实工具目录后勾选允许工具，再点击“保存并连接”。
4. **查看接入结果**：页面分别显示“业务服务本机检查”“连接器公网隧道”“开物业务接入”。企业集成凭据 K、来源路由和平台授权由开物管理员完成，本机成功不会被写成全链路成功。

原始 `mcpServers` JSON 导入仅作为维护人员的高级兼容选项，不是客户首次接入的前置条件。

### 凭据是分开的，这是设计上的硬约束

| 凭据 | 谁持有 | 用途 |
| --- | --- | --- |
| 设备身份（设备令牌） | 只在本机 DPAPI 保护文件 | 连接器调用云端控制面，不能读业务数据 |
| 企业集成凭据 K | 开物导入配置与云端验证哈希 | 开物调用我方 Edge；绑定企业和允许来源 |
| 客户 MCP 凭据 B | 只在本机 DPAPI 保护文件，由回环认证代理使用 | 访问客户内网 MCP 服务 |
| 动态签名密钥 S | 只在本机 DPAPI 保护文件，由回环认证代理使用 | 生成 `tools/call` 的渠道身份与 HMAC |
| 中继令牌 R／来源密钥 T | frps、visitor 的受控配置；Windows frpc 仅通过子进程环境接收 | 专属隧道鉴权 |

三条红线，实施时不要绕过：

- 企业集成凭据 K **绝不能**当作客户 MCP 凭据 B 使用，也不能转发到客户业务 MCP。
- 客户 MCP 凭据 B 和签名密钥 S **只允许**连接器本机认证代理使用，不能写进导出配置，也不能上传 Edge。
- 设备身份 **不能**读取 A 或 B。

## 2. 交付物清单

客户交付目录中的 Windows 可直接双击 `kaiwu-connector-<版本号>-windows-amd64-setup.exe` 安装。`.zip` 保留为附加便携包和内部工程诊断包，Linux 交付物为 `.tar.gz`。

```
bin/kaiwu-connector        连接器主程序（Windows 为 kaiwu-connector.exe）
bin/frpc                   隧道客户端（Windows 为 frpc.exe），0.61.1 版，Apache License 2.0
config/connector.env.example  云端地址配置模板
docs/交付与运维说明.md      本文档
docs/README.md             Linux 工程包的开发与构建说明
install / uninstall 脚本    Linux: install.sh、uninstall.sh
                           Windows: setup.exe；ZIP 内另有 install.ps1、uninstall.ps1
systemd/kaiwu-connector.service  Linux 服务单元
版本信息.txt                版本号、提交号、构建时间
```

本版本 frpc 为固定版本随包分发，客户现场不需要单独下载，也不建议自行升级——版本由云端中继统一配套验证。

## 3. 部署前准备

### 3.1 主机要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Linux x86_64（glibc 2.17 及以上，CentOS 7 / Ubuntu 18.04 及以上均可）或 Windows Server 2016 / Windows 10 及以上 x86_64 |
| 配置 | 2 核 CPU、2 GB 内存、1 GB 可用磁盘即可（连接器本身常驻内存约 20 MB） |
| 权限 | Linux 需要 root 安装；Windows 需要管理员 |
| 位置 | 能访问客户内网 MCP 服务的一台机器，不需要是 MCP 服务器本身 |

### 3.2 网络要求

**只需要出站，不需要入站。**

| 方向 | 目标 | 端口 | 用途 |
| --- | --- | --- | --- |
| 出站 | 云端控制面（候选包已预配置为 `https://flintw.com/api/kaiwu`） | 443/TCP | 绑定、心跳、拉取通道参数 |
| 出站 | 云端 MCP Edge（候选包已预配置为 `https://flintw.com/projects/kaiwu/mcp`） | 443/TCP | 平台侧访问通道 |
| 出站 | 云端 frps 中继（交付人员提供，通常与控制面同域或同 IP 段） | 7000/TCP 或交付人员指定端口 | 隧道连接 |
| 内网 | 客户 MCP 服务（如 `10.0.0.8:8000`） | 按客户实际 | 连接器访问 MCP |
| 入站 | 无 | 无 | 不需要任何入站端口 |

如果客户有出站白名单或代理，请提前放行上述目标。连接器**不使用**系统 HTTP 代理去连中继；如现场必须经代理，请与交付人员确认方案，不要私自加代理层。

### 3.3 在本机准备业务接入

1. 安装和内置示例测试需要目标服务器的管理员权限。公网测试还需要企业首次绑定和相应的出站连接。
2. 接入真实业务时，在本机填写内网 MCP 地址和该服务要求的访问参数。凭据只在本机录入。
3. 在表单中读取工具列表并勾选获准使用的只读工具。员工通过已获授权的开物助手试问。

### 3.4 需要我方准备的信息

1. 该客户租户下创建好的连接器 ID。
2. 一次性接入码（有效期与使用次数由平台控制，默认一次性）。
3. 云端控制面地址、Edge 地址、中继地址与端口。

## 4. 安装

### 4.1 Linux

```bash
# 解压
mkdir -p kaiwu-connector-<版本号>
tar -xzf kaiwu-connector-<版本号>-linux-amd64.tar.gz -C kaiwu-connector-<版本号>
cd kaiwu-connector-<版本号>

# 安装（root）
sudo ./install.sh
```

安装脚本会：

- 创建系统用户 `kaiwu-connector`（不可登录、无家目录）；
- 安装程序到 `/opt/kaiwu-connector`；
- 首次安装时把地址模板写入 `/etc/kaiwu-connector/connector.env`（权限 0640，属主 root，组 `kaiwu-connector`）；
- 创建数据目录 `/var/lib/kaiwu-connector`（0700，属主 `kaiwu-connector`）；
- 注册并启动 `kaiwu-connector.service`，设置开机自启和失败重启。

安装完成后确认：

```bash
systemctl status kaiwu-connector
curl -s http://127.0.0.1:17872/api/status
```

### 4.2 Windows

把 `kaiwu-connector-<版本号>-windows-amd64-setup.exe` 放到客户 Windows 机器后双击运行，在正常的 Windows 用户账户控制提示中确认提升权限。安装器使用中文欢迎页、安装进度页和完成页，自动完成文件落盘、服务注册和启动。完成页默认勾选“打开本机配置页面”；也可以从桌面的“开物内网连接器配置”或开始菜单的普通中文快捷方式打开。

若旧浏览器提示“增强安全配置”阻止页面内容，请保持安全防护开启。在安装连接器的同一台服务器上，用单位已有且允许使用的现代浏览器打开下方地址。若单位没有这样的浏览器，请把提示告知项目对接人。

`http://127.0.0.1:17872/`

安装脚本会：

- 复制程序到 `C:\Program Files\Kaiwu\Connector`；
- 数据目录为 `C:\ProgramData\Kaiwu\Connector`；
- 把 `config\connector.env.example` 中已预置的 `KAIWU_CLOUD_BASE=https://flintw.com/api/kaiwu` 和 `KAIWU_EDGE_BASE=https://flintw.com/projects/kaiwu/mcp` 写入系统环境变量；
- 模板值为空时保留已经配置的非空机器级 `KAIWU_CLOUD_BASE`、`KAIWU_EDGE_BASE`，避免默认卸载后重新安装把客户地址清掉；
- 注册 Windows 服务 `KaiwuConnector`（自动启动、失败自动重启）；
- 启动服务。

**下载时出现安全提示**　请保留提示文字或截图并联系项目对接人核对安装包。此时安装程序可能尚未运行，也就没有安装编号。保持终端防护开启。

**安装窗口提示失败**　请把窗口中的安装编号交给项目对接人。若这是首次安装且服务器还未绑定企业，请在窗口按 Ctrl+C，将本次中文摘要交给对接人。关闭窗口后，如提示已保存，可在 `%ProgramData%\Kaiwu\Connector\logs\install-failure-summary.txt` 重新查看。这个文件显示最近一次成功保存的失败摘要，请核对编号。摘要会分别说明安装停在哪一步、已知原因和恢复结果。

请按同一安装编号核对原因码和记录时间（UTC）。`file_missing` 表示本次检查时找不到文件。`file_missing_after_check` 表示同一文件首次通过校验，替换前再次检查时已经找不到。经确认的隔离或删除动作以对应时段的防护处置记录为准。点击安装后若提示已有安装任务，先处理已打开的安装窗口。

### 4.3 核对云端地址

本候选包已经预配置本轮验证使用的公网地址。安装后应核对，而不是要求现场重新填写：

```text
KAIWU_CLOUD_BASE=https://flintw.com/api/kaiwu
KAIWU_EDGE_BASE=https://flintw.com/projects/kaiwu/mcp
```

Linux 对应 `/etc/kaiwu-connector/connector.env`；Windows 对应机器级环境变量。只有我方明确切换测试或生产环境时，才按新的书面地址覆盖，不能由现场凭经验猜测。

> 修改后需要重启服务：Linux `sudo systemctl restart kaiwu-connector`；Windows `Restart-Service KaiwuConnector`。

### 4.4 打开本机界面

连接器界面只监听回环地址 `127.0.0.1:17872`，不对局域网和公网开放。在客户主机上直接打开浏览器访问 `http://127.0.0.1:17872/`。

如果主机没有图形界面或需要远程协助，使用 SSH 端口转发，**不要**把监听地址改成 `0.0.0.0`：

```bash
ssh -L 17872:127.0.0.1:17872 运维账号@客户主机
# 然后在自己电脑浏览器打开 http://127.0.0.1:17872/
```

界面带会话令牌校验，只接受本机来源的请求，跨站请求会被拒绝。

## 5. 首次接入（普通表单流程）

客户正常只需要使用安装器，不需要运行命令行脚本、解压工程诊断包或手工编写 MCP JSON。安装完成后，双击桌面的“开物内网连接器配置”快捷方式，浏览器会打开只监听本机的 `http://127.0.0.1:17872/` 配置页。

### 5.1 填写内部 MCP 参数

在主页面“配置内部 MCP 服务”区域填写：

1. **服务名称**：例如“库存查询”，用于本机维护和后续平台授权核对。
2. **MCP HTTP 地址**：客户内网 MCP 的 Streamable HTTP 地址，例如 `http://10.0.0.8:8000/mcp`。
3. **访问令牌**：客户 MCP 要求的固定 Bearer。已有令牌留空表示保留本机已保存值；页面不会再次显示已保存令牌。
4. **华微动态签名**：只有客户 MCP 在 `tools/call` 时要求华微渠道身份和 HMAC 时才勾选，并填写 `appid`、`channel`、`userid` 和 HMAC 密钥。`appid` 默认是 `MCP`；其他值必须按客户确认的信息填写，不能猜测。已有 HMAC 密钥留空表示保留原值，页面不会再次显示。

“当前配置对象”用于选择新增或维护已有来源。更新一个来源时，连接器只替换这个来源，不会删除其他来源、其他来源的访问令牌或动态签名配置。

#### 5.1.1 停用不再使用的旧来源

升级现场如果保留了以前的测试来源、旧地址或已经停止的服务，不需要删除配置，也不能让这些来源阻断当前来源接入。操作顺序如下：

1. 在“当前配置对象”下拉框中选择不再使用的旧来源；已停用的来源名称后会显示“（已停用，不参与连接）”。
2. 点击“停用此来源”。连接器只把该来源标记为停用，来源配置、访问令牌、动态签名密钥和其他来源都会保留。
3. 停用来源不会参与本机诊断、云端来源登记或公网隧道启动。确认下拉框名称后出现上述“已停用”标记。
4. 在“当前配置对象”中选择“＋ 新增 MCP 服务”，填写当前可用服务的名称、MCP HTTP 地址、访问令牌和动态签名参数，读取并勾选真实工具，再点击“保存并连接”。

如果所有来源都被停用，点击“保存并连接”会明确返回失败，页面不会显示为已连接。若要重新使用某个已停用来源，选中它并点击“启用此来源”，确认配置和工具允许列表后再保存并连接。

### 5.2 读取工具并选择允许范围

点击“读取工具列表”。连接器会执行真实 MCP `initialize` 和 `tools/list`，不会调用任何业务工具，也不会把草稿写入磁盘。读取成功后，页面显示上游真实工具名称和说明，维护人员勾选客户书面批准的只读工具。

不能提交空的工具允许列表，也不支持用 `*` 通配符绕过允许列表。客户不知道工具名称时，应通过这里的真实目录读取结果确认，不需要让客户猜固定业务字段。

### 5.3 保存并连接

勾选工具后点击“保存并连接”。连接器按以下顺序执行，并在业务配置区域分别显示三个阶段的结果：

1. **内网 MCP 可访问**：检查地址、TLS、MCP 初始化、认证和工具目录。失败时页面会指出实际失败阶段，并在“高级选项与诊断详情”中保留原始诊断。用户应先修正地址、访问令牌或动态签名，不能把保存成功当作内网检查成功。
2. **公网隧道已连接**：企业已经绑定且云端已经发布专属 frps/visitor 路由时，连接器启动固定版本 frpc 并等待隧道就绪。未绑定企业时停留在本阶段，不启动隧道。
3. **开物平台接入**：企业集成凭据 K、来源路由和平台授权由开物管理员配置。页面会明确显示“等待管理员配置”或“待管理员确认”，即使本机 MCP 和隧道已通过，也不会把本地成功写成平台已经可使用。

失败时的处理：

- 内网阶段失败：按页面提示检查 MCP 地址、访问令牌或动态签名，再点击主按钮重试。
- 公网隧道失败：检查客户出站 443/TCP 和中继端口是否放行，并联系开物管理员确认企业绑定、专属 frps/visitor 和来源路由。
- 内网与隧道通过但平台仍显示等待：这是正常的交付阶段边界，请由开物管理员签发企业集成凭据 K、完成来源路由和平台导入后再做真实工具调用。

### 5.4 高级选项

“高级选项与诊断详情”只用于维护和排障：

- 已有的标准 `mcpServers` JSON 仍可导入作为高级兼容入口，但导入会整体替换来源列表，不应与普通表单同时使用。
- “暂停”和“断开并回到待配置”用于维护；不会删除来源配置和秘密。
- “运行详细诊断”显示原始检查结果，失败时应把脱敏后的诊断详情交给技术支持。
- Edge 地址预览只显示本机生成的来源地址，不包含 `Authorization`，也不是可以导入开物平台的完整 MCP JSON。正式 MCP JSON 必须由开物管理员在企业集成凭据 K 签发时生成。
- 撤销连接器会清除本机企业身份、访问令牌和动态签名配置，必须重新签发后才能再次接入。

### 5.5 结果判定

普通客户流程的完成标准是：

- 页面显示“内网 MCP 可访问”；
- 企业已绑定时页面显示“公网隧道已连接”；
- 开物管理员已经配置企业集成凭据 K 和来源路由，并在开物平台完成真实工具调用。

这三项分别取证，不能互相替代。仅安装成功、仅本机诊断成功或仅看到 frpc 进程运行，都不等于开物平台端到端业务已经通过。

## 6. 日常运维

### 6.1 正常状态

顶部状态显示「就绪」，通道显示「运行中」，即一切正常。

### 6.2 服务管理

| 操作 | Linux | Windows |
| --- | --- | --- |
| 状态 | `systemctl status kaiwu-connector` | `Get-Service KaiwuConnector` |
| 启动 | `systemctl start kaiwu-connector` | `Start-Service KaiwuConnector` |
| 停止 | `systemctl stop kaiwu-connector` | `Stop-Service KaiwuConnector` |
| 重启 | `systemctl restart kaiwu-connector` | `Restart-Service KaiwuConnector` |
| 日志 | `journalctl -u kaiwu-connector -f` | 事件查看器 → Windows 日志 → 应用程序 |

重启服务不会丢失绑定和来源配置。上次处于「就绪」时会在启动后自动恢复通道；人工暂停过的连接器重启后仍保持暂停，需要人工点「连接」。如果是异常退出（例如直接结束进程或主机断电），重启时会先清理上次遗留的隧道进程，再建立新的通道，不需要人工处理。

### 6.3 日志与敏感信息

连接器日志**不会**打印设备令牌、客户 MCP 凭据、通道密钥的明文。排障时如果需要把日志发给支持人员，请先确认没有人为往日志里粘贴过凭据。

### 6.4 本机文件

| 文件 | 位置（Linux） | 内容 | 权限 |
| --- | --- | --- | --- |
| `identity.json` | `/var/lib/kaiwu-connector/` | 设备身份、企业、中继参数 | 0600 |
| `config.json` | 同上 | 普通表单或高级导入生成的来源列表（不含凭据） | 0600 |
| `secrets.json` | 同上 | 客户 MCP 请求头凭据 | 0600 |
| `auth_profiles.json` | 同上 | 华微渠道身份、HMAC 密钥和来源绑定 | 0600 |
| `frpc.toml` | 同上 | 不含 R／T 的隧道模板；秘密只在子进程环境中 | 0600 |
| `state.json` | 同上 | 最近状态快照 | 0600 |

**同机恢复。** 使用本次升级前已校验的完整受限备份，按对应恢复说明还原程序、服务、设备身份和本机凭据。检查服务启动后，再从开物发起一次原业务只读查询。

**更换 Windows 主机。** 设备身份密钥和业务凭据受原 Windows 系统保护。在新主机安装并按设备更换流程完成企业绑定，由维护人员在新机重新录入业务参数。确认授权的业务查询成功后，再按迁移安排撤销旧设备。

### 6.5 心跳

连接就绪后，连接器每 30 秒向云端上报一次状态。云端连续收不到心跳会标记连接器离线，并在平台上告警。

## 7. 状态说明

| 状态 | 含义 | 处理建议 |
| --- | --- | --- |
| 未接入 UNPAIRED | 还没有绑定企业 | 等待开物管理员签发并完成企业绑定 |
| 待配置 CONFIGURING | 企业状态已建立，但来源或连接尚未完成 | 在普通表单填写 MCP 参数并点击“保存并连接” |
| 连接中 CONNECTING | 正在建立隧道 | 等待，超过 1 分钟看日志 |
| 就绪 READY | 隧道和内网来源都正常 | 正常，无需处理；服务重启后会自动恢复 |
| 内网来源异常 DEGRADED_UPSTREAM | 隧道通了，但内网 MCP 检查不通过 | 查第 8 节 UPSTREAM_*、MCP_*、TOOL_* 错误 |
| 通道异常 DEGRADED_RELAY | 隧道没建立或不稳定 | 查出站端口、中继地址、通道密钥；隧道进程会自动重启，恢复后状态自动回到就绪 |
| 已暂停 PAUSED | 人工暂停，不对外提供服务 | 确认维护结束后点「连接」恢复 |
| 断开中 DRAINING | 云端要求优雅停止，等待在途请求结束 | 等待自动完成 |
| 已撤销 REVOKED | 云端或本机撤销了设备身份 | 需要重新生成接入码并绑定 |

## 8. 故障排查

### 8.1 错误码对照

界面“高级选项与诊断详情”中的“运行详细诊断”会给出错误码；命令行诊断仅由我方技术支持使用：

| 错误码 | 含义 | 常见原因 | 处理 |
| --- | --- | --- | --- |
| `UPSTREAM_UNREACHABLE` | 连不上内网 MCP | 地址写错、服务未启动、内网防火墙 | 在连接器主机上 `curl -v <mcp 地址>` 验证 |
| `CLOUD_TLS_FAILED` | 云端证书校验失败 | 客户网络做了 HTTPS 解密、系统时间不对、根证书缺失 | 校时；确认没有被中间人代理；不要关闭证书校验 |
| `UPSTREAM_AUTH_FAILED` | 内网 MCP 拒绝认证 | 访问令牌过期或配置错误 | 在普通表单重新填写访问令牌并保存 |
| `MCP_INCOMPATIBLE` | 协议不兼容 | 对方不是 MCP、版本过旧、返回的不是 JSON-RPC | 确认对方支持 Streamable HTTP 与 2025-06-18 协议 |
| `TOOL_ALLOWLIST_MISMATCH` | 工具列表与预期不符 | 服务升级后工具改名、权限不足 | 与客户核对工具清单 |
| `TOOL_TIMEOUT` | 工具调用超时 | 内网服务慢、首次冷启动 | 稍后重试；持续超时查对方服务 |

### 8.2 连接不上云端

先查看页面“公网隧道已连接”阶段的真实错误和详细诊断。客户网络需要允许到 `flintw.com:443` 及我方中继端口的出站连接；系统时间偏差超过 5 分钟也会导致证书和令牌校验失败。需要进一步检查网络或服务日志时，由我方技术支持执行，客户不需要运行命令行测试。

### 8.3 界面打不开

- 确认服务在运行。
- 确认访问的是 `http://127.0.0.1:17872/`，不是客户主机的局域网 IP。
- 远程协助请用 SSH 端口转发（见 4.4），不要改监听地址。

### 8.4 平台侧调用报 401 / 403

这属于平台授权问题，不是连接器问题：

- 401：企业集成凭据 K 无效、过期或已撤销；向云端管理员重新签发并更新开物 MCP 配置。
- 403：授权存在但该来源或工具没有授权范围，检查平台上的工具白名单。

## 9. 升级

1. Windows 双击新版 `setup.exe` 覆盖安装；安装器会先备份旧程序、配置和服务快照，再注册并启动新服务。Linux 升级由我方运维人员按随包说明执行。
2. 打开本机配置页面，确认原有来源和秘密仍保留。若存在不再使用且服务已停止的旧来源，先按 5.1.1 停用；停用不会删除配置或秘密。
3. 选中当前可用来源，确认 MCP 地址、认证参数和工具允许列表后点击“保存并连接”，验证内网阶段和公网隧道阶段。
4. 如升级失败，由我方技术支持按安装日志和数据目录 `backups\<时间>-pre-upgrade\restore.ps1` 回滚。
5. 如新版本要求重新绑定，按交付说明执行，不要自行清空数据目录。

升级不需要重新导入客户 MCP 配置，来源和秘密都保存在数据目录里。

## 10. 卸载

### Linux

```bash
sudo ./uninstall.sh           # 删除程序和服务，保留配置与本机身份
sudo ./uninstall.sh --purge   # 连同 /etc/kaiwu-connector、/var/lib/kaiwu-connector 和系统用户一起删除
```

### Windows

优先从 Windows“设置 → 应用 → 已安装的应用”或开始菜单卸载。默认卸载删除程序和服务，保留 `C:\ProgramData\Kaiwu\Connector` 中的配置、本机身份和云端机器级环境变量，方便重新安装后恢复。只有明确要求彻底清除时，才由我方人员使用 `uninstall.ps1 -Purge`；该操作会删除本机身份、配置和备份，不能作为普通卸载步骤。

卸载前请交付人员在平台上撤销该连接器，否则云端会保留一条离线记录。

## 11. 安全要求

1. **本机界面只监听回环地址。** 不要改成 `0.0.0.0`，不要做端口映射，不要加反向代理暴露到内网或公网。需要远程操作时用 SSH 端口转发。
2. **数据目录权限 0700，文件 0600。** 不要用 root 以外的宽松权限覆盖，也不要把它放进共享目录或网盘同步目录。
3. **凭据不落地到导出文件。** 导出的平台配置里只有地址和占位符；如果看到真实凭据，说明操作有误，立即停止并上报。
4. **不要关闭 TLS 校验。** 出现 `CLOUD_TLS_FAILED` 时排查根因，不要用 `--insecure` 之类的方式绕过。
5. **frpc 为固定版本。** 随包分发的是 0.61.1，遵循 Apache License 2.0。客户如需安全扫描，请提供包内 `版本信息.txt` 和 frp 官方许可证说明。不要用客户环境里其他版本的 frpc 替换。
6. **服务账号边界。** Linux 使用不可登录的 `kaiwu-connector` 系统用户。当前 Windows 诊断候选包仍以 `LocalSystem` 安装，数据目录仅授予 SYSTEM 和管理员访问；它尚未达到正式生产要求的专用低权限服务身份，客户验收时必须如实记录，不能把候选包描述为已完成最小权限加固。
7. **撤销即失效。** 客户终止合作或更换主机时，在平台撤销连接器；本机界面上的「撤销本机」也会立即让设备身份失效。

## 13. 本版本能力边界

为避免现场误解，明确说明当前版本**不做**什么：

- 不支持 `stdio` 类型 MCP（需要交付人员评估后用 `--allow-stdio` 开启，属于条件分支）。
- 不支持客户侧自行配置多租户；一台连接器只服务一个企业租户。
- 不做流量内容审计和脱敏，这属于平台侧职责。
- 不做高可用集群；一台连接器故障时，平台侧会显示离线，需要人工恢复或切换到备用机。
- frpc 的版本由随包二进制决定，不支持热升级。
- 隧道进程意外退出会自动拉起，但如果是客户网络整体中断，退避重试最长间隔为 30 秒，恢复时间取决于网络恢复时间。

如现场需求超出以上边界，请反馈给产品而不是现场改造。

## 14. 常见问题

**问：客户说不能装软件，能不能只给一个 exe 双击运行？**
答：客户应双击 `kaiwu-connector-<版本号>-windows-amd64-setup.exe` 安装。安装器会在正常的用户账户控制提示中申请管理员权限，然后注册并启动 Windows 服务、创建开始菜单和桌面配置入口。不要再让客户直接双击 `kaiwu-connector.exe` 代替安装，因为那样不会注册开机自启服务，也没有标准卸载入口。

**问：连接器会不会把客户内网数据传到云端？**
答：连接器转发已授权的工具请求和工具响应。设备完成绑定后，也可以上报脱敏的安装和运行事件，供技术支持按编号查询。安装事件记录阶段、结果和错误码。客户的访问密钥保留在本机，诊断记录排除查询参数和业务结果正文。

**问：能不能把界面开放给客户内网其他人看？**
答：不建议。界面能触发绑定、导入、撤销等敏感操作，只应给实施人员在本机使用。

**问：换机器怎么办？**
答：Windows 的访问凭据由原机器加密保护。请在新机上安装连接器，使用开物管理员为新机签发的接入码完成绑定，并在新机本地重新填写业务访问参数。验证新机业务调用后，再由维护人员安排旧机退出。

**问：客户有出站代理怎么办？**
答：当前版本不读取系统代理设置，隧道直连中继。需要代理的场景请先与交付人员确认，不要在现场临时加代理。

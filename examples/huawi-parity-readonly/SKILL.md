# 只读业务 Skill（受限通用规则候选）

> 来源边界：本文件只是本轮允许的**有界通用只读规则输入**，不是客户原始 SKILL.md、插件清单、提示词、运行配置、业务数据或答案的完整副本，也不声称与任何客户实现逐字等价或生产等价。缺失的证据必须如实报告，不得补造。

## 1. 适用范围与权限边界

- 本 Skill 只提供说明性规则，不注册、不授予、不扩大任何可执行工具或数据权限。
- 只使用平台已授权、且在部署时由管理员绑定的只读能力：describe 负责检索数据集和查看真实字段，query 负责读取已验证字段；动作目录由 describe 发现；不调用 call。
- 不新增、不覆盖、不绕过现有审批策略。写入、导出、发消息、外部调用、创建工单、修改数据等动作一律不执行。
- 租户隔离、用户隔离、凭据隔离、幂等执行和审计沿用平台现状，本 Skill 不改变这些约束。

## 2. 先做语义拆解：对象、范围、指标、单位

回答前先把问题拆成四项，并写清楚采用的解释：

1. **对象**：问的是哪一类业务记录或数据集，例如批次、工单、设备、质检记录。不得把不同对象混为一谈。
2. **范围**：时间区间与时区、组织、产线、状态等限制条件。范围必须能落到已发布字段；不得因为问题语气模糊就自行扩大或缩小范围。
3. **指标**：记录数、去重计数、合格率、均值、比例等。比率必须说明分子和分母。
4. **单位与精度**：件、批、百分比、小数位、时区。不同单位不得直接相加或比较。

问题存在歧义时，先写出采用的对象、范围、指标、单位解释，再继续查询。不得悄悄选择一种解释后把它当成用户原意。

## 3. 先 describe 再 query

- `describe` 顶层只接受 `code`、`keyword`、`kind`、`page`、`rows`，没有必填项。列表或检索使用 `keyword` 或 `kind`；精确详情只按 `code`（请求对象仅包含 code，不同时传 kind、keyword、page、rows），不得使用名称或其他未观察到的选择器。
- 先按需检索出候选 `code`，再用该 `code` 取详情：真实字段名、字段类型、关联关系、数据粒度。只有 describe 详情实际返回的字段，才可以出现在 query 的 select、filters、order_by 或 group_by 中。
- 详情中的嵌套字段与支持的操作符尚未复核；不得补造嵌套结构、操作符、排序方向或分页参数行为。
- **不得猜测字段名、字段 ID、数据集名、关联键或状态码**；不得把界面显示标签当作字段名。
- describe 没有返回所需字段时，说明缺什么、已经检索了什么、需要谁补充。不得改用名称相近的字段顶替。
- 当前上下文已经核实过所需对象和字段时，不重复发现；只有缺少回答所必需的证据时才发起 describe。

## 4. 有限发现与停止条件

- 发现必须按需且有界：先关键词检索，最多 3 轮收敛；每轮说明目的，例如“确认批次表的日期字段”。
- 无需查询、或所需字段已在当前上下文核实时，跳过发现，不为了流程完整而重复 describe。
- 获得足够的字段、关联和粒度证据后立即停止，不遍历全部数据集，不逐条扫描记录，不无限重试。
- 没有找到结果时，报告检索词、检索范围、时间和“未找到”，不得把一次未命中扩大成“全库都没有”的推断。

## 5. Query 构造规则

- 顶层只使用已观察到的 `dataset`、`select`、`filters`、`group_by`、`include_total`、`order_by`、`page`、`rows`；`dataset` 和 `select` 必填。不要发明其他顶层属性。
- select 使用结构化对象数组，不传 SQL 字符串。明细例如 `{"field":"batch_id"}`（字段须已核实且可选择）；聚合一律使用显式 `alias`，例如 `{"field":"*","aggregate":"count","alias":"record_count"}`。示例字段与别名仅为合成示意，实际字段及聚合必须由 describe 与工具契约核实；不要发明选择器结构。
- `*` 只能用于 COUNT(*) 计数，不能用于取行。
- group_by 中的字段必须与 select 里的分组字段完全一致；filters 只使用已核实字段与已确认支持的操作符；order_by 使用实际输出字段名或聚合别名。嵌套操作符和排序方向格式尚未复核，未确认时不要假定，说明“该用法尚未验证”。
- 不要把客户名称、租户名称、个人数据或原始记录值放进 select 或别名；别名只用中性口径名。
- include_total 只表示记录数或分组数，不是某个聚合单元格的值；不得把 total 当作业务指标值。
- 返回结构按 dataset、columns、data、rows、page、has_more、total 理解。data 是位置矩阵，列名以 columns 为准，不按位置猜含义。`rows` 是本次请求的页大小，不是 `len(data)`；最后一页的 `len(data)` 可以小于 `rows`。`page` 是当前页。`total` 可缺省，表示输出记录数或分组数，不是聚合单元格的值。

## 6. COUNT、显式别名与零的含义

- 未分组计数使用 `{"field":"*","aggregate":"count","alias":"record_count"}` 或 `{"field":"batch_id","aggregate":"count_distinct","alias":"batch_count"}`；必须明确别名，且字段及操作受工具定义支持。COUNT 和 DISTINCT 是指标口径的说明，不是传给 MCP 的 SQL。
- 别名要说明统计口径；不得依赖平台默认列名，也不得用无名聚合列直接回答。
- 分组聚合和分页行为在取得单独契约证明前不视为已验证；需要使用时先说明“该口径尚未验证”。
- `COUNT(*) = 0` 仅在实际成功的匹配聚合回执确有数值单元格 0 时成立：表示工具报告当前查询口径的记录数为 0，保留别名、范围、时间，不推断全库或其他权限范围无记录。
- `COUNT(DISTINCT field) = 0` 只表示工具报告该字段去重计数为零，不等于没有记录；字段空值的具体统计语义仍依赖已核实契约。不得把 DISTINCT 零写成“没有记录”或“没有数据”；需要判断有无记录时，另做 `COUNT(*)`。

## 7. 主关系缺失时的辅助统计

- 如果 describe 证实主对象与目标对象之间没有已发布的关联或字段，直接说明“无法据此推断该关系”，不得臆造关联、分母、范围或业务含义。
- 可选做法：使用已验证字段做不超过 3 个各自独立、安全且有意义的只读辅助聚合。每个辅助统计都要标注对象、范围、字段、别名、单位和用途。
- “有意义”指能直接补充用户可理解的对象范围事实，例如同一已核实对象的记录数，或有明确业务含义的去重数；不要做与问题无关的凑数统计。
- “安全”指只用已核实字段做聚合，不为辅助聚合读取或输出无关明细、个人数据、凭据或原始 ID 列表，不跨租户、组织或连接，不用辅助统计反推缺失的关联。
- 辅助统计不是主问题答案，不得拼接成主关系结论，也不得用辅助值反推缺失的关联。
- 辅助统计之间不得互相替代；每个结果单独标注证据边界。

## 8. 不替换对象、范围或口径

- 不得用相近对象、相近数据集、相近字段或相近口径替代用户所问。
- 主数据不可用、无权限或字段缺失时，直接说明不可用，不得静默换源后把结果当成原问题答案。
- 用户明确同意替代时，必须标注替代对象、与原问题的差异、可比性限制，并在回答中显著说明。
- 不跨租户、不跨组织、不跨连接借用数据来补足结果。

## 9. 零、空、未查询、失败与无权限

必须区分以下状态，不得合并成同一个“0”：

- **已核实为 0（COUNT(*)）**：实际成功回执中的计数单元格为 0。说明工具报告该查询口径为 0，并附已知数据集、字段、范围和时间；未核实的范围或时间不得补造。
- **DISTINCT 为 0**：查询成功，但只是工具报告该字段去重计数为零，不等于没有记录；不得写成“已核实无记录”。如需确认记录有无，另查 COUNT(*)。
- **空页或无行**：当前页没有返回行，可能只是分页未取全或过滤到空页。不能等同于 0。
- **未查询**：没有发起查询，就写“未查询”，不得写成 0。
- **失败**：工具错误、超时、解析失败等，单独报告失败原因。
- **无权限或被拒绝**：单独报告，不得推断为 0、空或“不存在”。

每个结论都附上数据集、字段、范围、时间、单位和分页状态。证据不足时只给部分结论，并列出还缺什么。

## 10. 分页、部分结果与覆盖边界

- `has_more=false` 只表示当前页没有后续页；若从第一页连续取全且同一查询口径成立，才可声明本次查询分页取全。二者都不证明全量业务覆盖。范围、时间、数据源、权限或字段完整性仍可能缺失，必须单独说明。
- 否则必须写“部分结果：第 page 页，本页实际返回 len(data) 行，has_more=true”，不得省略。`rows` 是页大小，`len(data)` 是本页实际返回行数；二者不等不表示缺页或数据缺失。
- 不得用部分页外推总数、比例、趋势或排名。
- 比例和比率只在分子、分母来自同一对象、同一范围、同一粒度且分母大于 0 时计算；分母为 0 时说明不可计算。

## 11. 不执行不安全动作

- 不写、不改、不删、不导出、不发消息、不触发外部流程、不创建工单、不执行 call 动作。
- 不索取或输出凭据、token、密码、连接串、密钥；不输出与问题无关或未经授权的客户名称、租户名称、个人数据或完整的内部 ID 列表。回答尽量使用聚合结果和中性别名。
- 不绕过人工审批，不把建议写成已经完成，不声称已经部署或已经生效。
- 如果请求包含上述动作，说明只读边界，并给出只读替代，例如查询状态或读取已有记录；不要自行执行。

## 12. 回答结构

1. 先给一句结论，再列证据：数据集、字段、范围、时间、单位、分页。
2. 明确区分：已核实、未核实、无法推断、未查询、失败、无权限；COUNT 零与 DISTINCT 零分别表述。
3. 列出无法推断的关系和缺失输入，不编造补全。
4. 说明覆盖边界：本 Skill 不保证全量、实时或客户生产等价。
5. 对不确定项给出下一步所需的最小补充信息，而不是猜测答案。

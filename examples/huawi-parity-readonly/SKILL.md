# 华微只读业务 Skill（受限通用规则候选）

> 来源边界：本文件只是本轮允许的**有界通用只读规则输入**，不是客户原始 SKILL.md、插件清单、提示词、运行配置、业务数据或答案的完整副本，也不声称与任何客户实现逐字等价或生产等价。缺失的证据必须如实报告，不得补造。

## 1. 适用范围与权限边界

- 本 Skill 只提供说明性规则，不注册、不授予、不扩大任何可执行工具或数据权限。
- 只使用平台已授权、且在部署时由管理员绑定的只读能力：describe 负责检索数据集和查看真实字段，query 负责读取已验证字段；call 只允许用于发现，不执行动作。
- 不新增、不覆盖、不绕过现有审批策略。写入、导出、发消息、外部调用、创建工单、修改数据等动作一律不执行。
- 租户隔离、用户隔离、凭据隔离、幂等执行和审计沿用平台现状，本 Skill 不改变这些约束。

## 2. 先做语义拆解：对象、范围、指标、单位

回答前先把问题拆成四项，并写清楚采用的解释：

1. **对象**：问的是哪一类业务记录或数据集，例如批次、工单、设备、质检记录。不得把不同对象混为一谈。
2. **范围**：时间区间与时区、组织、产线、状态等限制条件。范围必须能落到已发布字段；不得因为问题语气模糊就自行扩大或缩小范围。
3. **指标**：记录数、去重计数、合格率、均值、比例等。比率必须说明分子和分母。
4. **单位与精度**：件、批、百分比、小数位、时区。不同单位不得直接相加或比较。

问题存在歧义时，先写出采用的对象、范围、指标、单位解释，再继续查询。不得悄悄选择一种解释后把它当成用户原意。

## 3. 先 describe 再 query

- 先通过受权的 describe 按关键词或类型检索数据集，再获取相关数据集的详情：真实字段名、字段类型、关联关系、数据粒度。
- 只有 describe 详情中实际返回的字段，才可以出现在 query 的 select、filters、sort 或 group_by 中。
- **不得猜测字段名、字段 ID、数据集名、关联键或状态码**；不得把界面显示标签当作字段名。
- describe 没有返回所需字段时，说明缺什么、已经检索了什么、需要谁补充。不得改用名称相近的字段顶替。
- 如果平台只提供按代码取详情，只能使用 describe 返回的代码，不自造代码或编号。

## 4. 有限发现与停止条件

- 发现必须有界：先关键词检索，最多 3 轮收敛；每轮说明目的，例如“确认批次表的日期字段”。
- 获得足够的字段、关联和粒度证据后立即停止，不遍历全部数据集，不逐条扫描记录，不无限重试。
- 没有找到结果时，报告检索词、检索范围、时间和“未找到”，不得把一次未命中扩大成“全库都没有”的推断。

## 5. Query 构造规则

- select 只列 describe 已验证的字段。
- `*` 只能用于 COUNT(*) 计数，不能用于取行。
- group_by 中的字段必须与 select 里的分组字段完全一致；filters 和 sort 只使用已发布字段与已支持的操作符。
- include_total 只表示记录数或分组数，不是某个聚合单元格的值；不得把 total 当作业务指标值。
- 返回结构按 dataset、columns、data、rows、page、has_more、total 理解。data 是位置矩阵，列名以 columns 为准，不按位置猜含义。

## 6. COUNT 与显式别名

- 未分组的 COUNT / COUNT DISTINCT 必须显式别名，例如 `COUNT(*) AS record_count`、`COUNT(DISTINCT batch_id) AS batch_count`。
- 别名要说明统计口径；不得依赖平台默认列名，也不得用无名聚合列直接回答。
- 分组聚合和分页行为在取得单独契约证明前不视为已验证；需要使用时先说明“该口径尚未验证”。
- 计数为 0 是有效结果，保留别名、范围和查询时间，不要改写成“没有数据”或“失败”。

## 7. 主关系缺失时的辅助统计

- 如果 describe 证实主对象与目标对象之间没有已发布的关联或字段，直接说明“无法据此推断该关系”，不得臆造关联、分母、范围或业务含义。
- 可选做法：使用已验证字段做不超过 3 个各自独立有意义的只读辅助聚合。每个辅助统计都要标注对象、范围、字段、别名和单位。
- 辅助统计不是主问题答案，不得拼接成主关系结论，也不得用辅助值反推缺失的关联。
- 辅助统计之间不得互相替代；每个结果单独标注证据边界。

## 8. 不替换对象、范围或口径

- 不得用相近对象、相近数据集、相近字段或相近口径替代用户所问。
- 主数据不可用、无权限或字段缺失时，直接说明不可用，不得静默换源后把结果当成原问题答案。
- 用户明确同意替代时，必须标注替代对象、与原问题的差异、可比性限制，并在回答中显著说明。
- 不跨租户、不跨组织、不跨连接借用数据来补足结果。

## 9. 零、空、未查询、失败与无权限

必须区分以下状态，不得合并成同一个“0”：

- **已核实为 0**：查询成功，且当前范围内确实没有记录。写“已核实为 0”，并附数据集、字段、范围和时间。
- **空页或无行**：当前页没有返回行，可能只是分页未取全。不能等同于 0。
- **未查询**：没有发起查询，就写“未查询”，不得写成 0。
- **失败**：工具错误、超时、解析失败等，单独报告失败原因。
- **无权限或被拒绝**：单独报告，不得推断为 0、空或“不存在”。

每个结论都附上数据集、字段、范围、时间、单位和分页状态。证据不足时只给部分结论，并列出还缺什么。

## 10. 分页与部分结果

- 只有 has_more=false，或已经取全所有页，才能声明结果完整。
- 否则必须写“部分结果：第 page 页，本页 rows 行，has_more=true”，不得省略。
- 不得用部分页外推总数、比例、趋势或排名。
- 比例和比率只在分子、分母来自同一对象、同一范围、同一粒度且分母大于 0 时计算；分母为 0 时说明不可计算。

## 11. 不执行不安全动作

- 不写、不改、不删、不导出、不发消息、不触发外部流程、不创建工单、不执行 call 动作。
- 不索取或输出凭据、token、密码、连接串、密钥，也不输出完整的内部 ID 列表。
- 不绕过人工审批，不把建议写成已经完成，不声称已经部署或已经生效。
- 如果请求包含上述动作，说明只读边界，并给出只读替代，例如查询状态或读取已有记录；不要自行执行。

## 12. 回答结构

1. 先给一句结论，再列证据：数据集、字段、范围、时间、单位、分页。
2. 明确区分：已核实、未核实、无法推断、未查询、失败、无权限。
3. 列出无法推断的关系和缺失输入，不编造补全。
4. 说明覆盖边界：本 Skill 不保证全量、实时或客户生产等价。
5. 对不确定项给出下一步所需的最小补充信息，而不是猜测答案。
